# 文案审核：候选审核

[专题索引](../../文案审核.md) · [先读使用边界](00-使用边界.md)。命令与代码路径仍以技能根目录为基准。

## 3. 审核流程（Agent 可直接执行）

### 3.1 输入

1. 待审文案：按元素分块，每块带类型标签。类型取值：`hero_title` `hero_subtitle` `section_title` `card_title` `card_body` `button` `link` `form_label` `form_hint` `error` `meta_title` `meta_description` `body`。
2. 事实清单（可选但强烈建议）：品牌名、城市、产品、工艺、价格、周期、证书、数据。审核时只能用这里和原文里出现的事实。
3. 品牌语气（可选）：称呼用“你”还是“您”、是否允许幽默。没给时：称呼只要求全文统一（见 4.4 第 3 条对 B23 的修订）；不加幽默（Mailchimp Voice and Tone：“If you're unsure, keep a straight face”）。

### 3.2 步骤

**第 0 步：问三个问题**（Orwell 作者自问；Google tone “What am I trying to say?”；Zinsser 第 2 章 “What am I trying to say? … Have I said it?”）
先看本屏实际构图、图像和操作，再读候选和简报的 `purpose`。试着遮去这一句：访客会少知道什么、哪个操作会变得难以辨认？说明能从哪里看出这项损失。若同屏已有相同信息或入口，选一处最易识别的保留；两处各有用途时分别说明。其余标 `drop`，无需从候选中强挑一句。

**第 1 步：整句删除**
- R-D1 删开场白、过渡句、“我们深知/理解你……”“在当今……的时代”。【出处】NN/g Cringeworthy #4；Zinsser 第 4 章（编辑常常直接扔掉前三四段）；GOV.UK 不要 Introduction 小节。
- R-D2 删重复前一句或重复标题/摘要的句子。【出处】Zinsser 第 3 章方括号法（“the one that essentially repeats what the previous sentence said”）；GOV.UK“Do not repeat the summary in the first paragraph”；Ant Design“不重复用户已知事实”。
- R-D3 删读者不需要、或能自己推出的句子。【出处】Zinsser 第 3 章；GOV.UK“Publish only what someone needs to know … Nothing more”。
- R-D4 删“我们致力于/始终坚持/用心”类表态句，换成可验证事实；没有事实就删。【出处】NN/g 客观版 +27%；Mailchimp“Speak truth … Avoid grandiose claims”；GOV.UK“emotionless”。

**第 2 步：词句替换**（按 3.3 黑名单逐条扫）

**第 3 步：结构**
- R-S1 结论/卖点放句首，关键词前置。【出处】NN/g 倒金字塔；GOV.UK front-loading；Microsoft“Get to the point fast”；Ant Design“重要的信息放在显著位置”。
- R-S2 一段一个意思，段首是主题句。【出处】Strunk Rule 9；NN/g（用户只读每段第一句）。
- R-S3 并列卖点用同一句式。【出处】Strunk Rule 15。
- R-S4 段落 ≤5 句，句子超 25 个英文词就检查能否拆。【出处】GOV.UK。中文换算：单句超 35 字检查能否拆【归纳，未验证】。
- R-S5 三条以上并列信息改列表。【出处】NN/g scannable；Strunk Rule 15 末段（多则用表）。

**第 4 步：事实核对**
- R-F1 不新增原文和事实清单里没有的事实。缺事实的位置写 `【待补：……】`，交给人填。【归纳】依据：Strunk Rule 12 要具体，但具体必须有事实；Google excessive claims 要可验证。
- R-F2 绝对化、保证类说法（最、第一、绝对、确保、100%、永不）没有来源就降级或删除。【出处】Google excessive claims；Ant Design“表述不应过于极端”。
- R-F3 数字用阿拉伯数字。【出处】Ant Design。

**第 5 步：按元素检查长度**（见 3.4）

**第 6 步：总量检查**
- 可以记录删改前后的字数。以信息和操作是否完整决定取舍，不设删减比例。
- 朗读一遍，像不像人说的话；不像就改。【出处】叶圣陶《写文章跟说话》（嘴里不那么说，笔下就不该那么写）；张中行转述叶圣陶“念给那间房里的人听”；Google tone “Try reading parts of your document out loud”；GOV.UK error message“Read the message out loud”。
- 最后自检：再删一两个字意思变不变，不变就删。【出处】张中行转述叶圣陶；Orwell 规则 iii。

### 3.3 中文 AI 腔 / 欧化句式黑名单

| # | 命中模式 | 改法 | 依据 |
|---|---|---|---|
| B1 | 进行 / 作出 / 加以 / 予以 + 动作名词（进行制作、作出贡献） | 直接用动词：制作、贡献很大 | 【出处】余光中第二节“万能动词”；Orwell“verbal false limbs”；digital.gov hidden verbs；Strunk Rule 10（名词承担全部动作） |
| B2 | 基于……原因 / 有……存在 / 造成……死亡 | 因此 / 问题很多 / 死了 | 【出处】余光中第一、七节原例 |
| B3 | 作为一个/一家……的…… | 拆成判断句：“我们是……，……” | 【出处】余光中第二节（“作为竹林七贤之一的刘伶”，“作为”纯然多余）；“作为一家/一个”是同类套用【归纳】 |
| B4 | 最……之一 / ……之一（无明确范围） | 删“之一”或给出具体范围、事实 | 【出处】余光中第二节；Strunk V 章 One of the most |
| B5 | ……性 / ……度 / ……型的（可读性、知名度、难度很高的） | 还原为形容词：好看、有名、很难 | 【出处】余光中第二、六节 |
| B6 | 的的不休（参差的斑驳的黑影） | 删“的”、改“而”、改短句 | 【出处】余光中第六节 |
| B7 | ……地 修饰（成功地推翻、精心地打磨） | 删副词或删“地”；“成功地”一律删 | 【出处】余光中第五节；Zinsser 第 3 章（与动词意思重复的副词） |
| B8 | 被 字句（被誉为、被广泛应用） | 改主动；或用“受、获、遭、为……所” | 【出处】余光中第七节；Strunk Rule 10；Orwell 规则 iv；GOV.UK active voice |
| B9 | 关于 / 有关 / 由于……使得 | 删介词；删因果连接词，让上下文表达 | 【出处】余光中第四节 |
| B10 | 和 / 与 / 及 / 以及 连接本可并列的词 | 删连接词或用顿号、“而” | 【出处】余光中第三节 |
| B11 | 人们 / 用户们 / 匠人们 / 顾客们 | 大家、人人，或直接删“们” | 【出处】余光中第二节 |
| B12 | 让我们（一起）…… | 删，或改成用户动作 | 【出处】Google tone“Phrasing in terms of let's”；Ant Design 不混用你我 |
| B13 | 我们深知 / 我们理解 / 在当今快节奏的时代 | 删，换成事实 | 【出处】NN/g Cringeworthy #4 |
| B14 | 让你 / 使你能够 / 帮助你 / 为你提供 | 写用户能做什么：“查看……”“买到……” | 【出处】NN/g Cringeworthy #2（enables）；Ant Design“明确表述立足点” |
| B15 | 非常 / 十分 / 极其 / 真正 / 确实 | 删，或换成事实 | 【出处】NN/g Cringeworthy #3；Strunk V 章 Very、Certainly；Zinsser 第 3 章 qualifiers |
| B16 | 值得一提的是 / 需要注意的是 / 有趣的是 / 不难发现 | 删，直接说 | 【出处】Zinsser 第 3 章（“It should be pointed out”“It is interesting to note”）；Strunk V 章 Interesting；Google tone“please note” |
| B17 | 只需 / 轻松 / 简单几步 / 一键 | 删，或写具体步骤数（有事实时） | 【出处】Google tone（simply、It's easy、quickly） |
| B18 | 赋能 / 打造 / 引领 / 生态 / 全方位 / 一站式 / 无缝 / 闭环 | 拆成实际在做的事；做不出就删 | 原则【出处】GOV.UK buzzwords（“breaking the term into what you're actually doing”）；Zinsser fad words；Google buzzwords。具体中文词表【归纳】 |
| B19 | 极致 / 最优质 / 顶级 / 完美 / 独一无二 / 绝对 | 删，或换成可验证事实 | 【出处】Google excessive claims；Ant Design 不极端；NN/g marketese。具体词【归纳】 |
| B20 | 匠心 / 温度 / 旅程 / 保驾护航 / 生命力 / 开启……之旅 | 删套用比喻，写具体做法 | 【出处】Orwell 规则 i（常见于印刷品的比喻不用）、Dying metaphors；Mailchimp“fluffy metaphors”。具体词【归纳】 |
| B21 | 不仅……而且…… / 不只是……更是…… 堆在卖点句 | 拆成两个短句，或只留一个事实 | 【归纳】。旁证：Orwell 引用的套话例句正是“not only of achieving … but at the same time of …”结构 |
| B22 | 了 / 太 的冗余（见到了老师、不太认识） | 删 | 【出处】张中行转述叶圣陶 |
| B23 | 您 | 你（品牌另有要求除外） | 【出处】Ant Design“拉近彼此的距离” |
| B24 | ！ | 删；只在祝贺、问候时保留 | 【出处】Google tone；Ant Design |
| B25 | 报错里的 抱歉 / 请 / 无效 / 非法 / 哎呀 | 删，改为“发生了什么 + 怎么改” | 【出处】GOV.UK error message（no please、sorry、invalid、illegal、oops）。冲突：Ant Design 允许系统原因造成的错误用“抱歉”。规则：用户输入错误不用“抱歉”，系统故障可用 |
| B26 | 不能 / 不要 / 请勿（引导用户输入时） | 改成正面指引 | 【出处】Ant Design“友好、尊重用户”；Strunk Rule 11 |
| B27 | 首先……其次……最后……总之（短文案里） | 删序列词，改列表 | 【归纳】依据 NN/g scannable、GOV.UK 列表示例 |
| B29 | 标题、副标题短句、按钮、标签、导航、卡片标题结尾带标点（「早八。」「开始今天。」） | 去掉结尾的 。．.！!？?；;，,：: | 【出处】Ant Design 文案规范：标签、标题、输入框提示、按钮不加句号。由 `check-copy.mjs` 运行时检查 |
| B28 | 立即探索 / 了解更多精彩内容（按钮） | 动词 + 对象：看作品、预约 | 【出处】Mailchimp 按钮必须含动词；Mailchimp 不用“Click here”；GOV.UK 标题去掉同义重复 |

英文文案另加：utilize→use、enables you to→直接写动作、very/really→删、the fact that→删、there is/there are→改动词句、in order to→to。【出处】NN/g Cringeworthy；Strunk Rule 13；Microsoft top 10；Orwell operators。

### 3.4 按网页元素的长度上限

| 元素 | 上限 | 依据 |
|---|---|---|
| `meta_title` 页面标题 | ≤65 字符（英文含空格）；中文 ≤30 字【归纳，未验证】 | 【出处】GOV.UK titles |
| `meta_description` 摘要 | ≤160 字符（英文）；中文 ≤80 字【归纳，未验证】 | 【出处】GOV.UK summaries |
| `hero_title` 首屏主标题 | 中文 ≤14 字，英文 ≤8 词；只讲一件事 | 【归纳，未验证】依据 NN/g 扫读、GOV.UK front-loading |
| `hero_subtitle` 副标题 | 中文 ≤40 字，1–2 句；补主标题没说的事实 | 【归纳，未验证】 |
| `section_title` / `card_title` | 中文 ≤8 字；名词短语或动词短语；不用问句 | 不用问句【出处】GOV.UK headings；字数【归纳】 |
| `card_body` 卡片说明 | 中文 ≤40 字，1–2 句，一个卖点 | 一卡一意【出处】NN/g one idea per paragraph；字数【归纳】 |
| `body` 正文段落 | ≤5 句；单句英文 ≤25 词，中文 ≤35 字【归纳】 | 【出处】GOV.UK |
| `button` | 必须含动词；中文 2–6 字、英文 1–3 词；不加句号 | 动词、简洁【出处】Mailchimp；不加句号【出处】Ant Design；字数【归纳】 |
| `form_label` / `form_hint` | 不加句号；提示里有示例，报错就不再给示例 | 【出处】Ant Design；GOV.UK error message |
| `error` 表单错误提示 | 说清问题 + 怎么改；沿用字段标签用词；中文 ≤20 字（不含示例）【归纳】 | 【出处】GOV.UK error message；Microsoft“You need an ID that looks like this” |

### 3.5 输出格式

每块一行：

| 元素 | 原文 | 改后 | 删了什么 | 规则编号 | 待补事实 |
|---|---|---|---|---|---|

表后附：
- 字数：原文 N 字 → 改后 M 字（M/N）。字数统计去掉空白。
- 待补事实清单。
- 不确定项：规则互相冲突或需品牌决定的地方，列出来，不擅自决定。

## 5. 接入方式

本机用户偏好：各独立标题行、导航、按钮和标签末尾不加句号等标点；检查包含嵌套 span、伪元素及交互后文本。正文正常标点，不能把整页无标点当作设计风格。


- 子 Agent 定义：`agents/copy-reviewer.toml`（名字 `copy_reviewer`）。复制到 `~/.codex/agents/` 或项目 `.codex/agents/`。规则通过宿主独立子代理运行；此 TOML 的独立角色自动加载仍需按宿主配置验证，不能仅靠文件存在宣称角色已安装。
- **A 模式的时机**：锁定并实测代表样段之前，只整理事实与用户固定原文。需要验证分行时，可在样段临时放等长字。样段自查通过后，依据样段及原站实见的对应屏幕列文字需求；未打开的章节留待补看。类型表只供命名，不按“每章标题＋副标题＋按钮”预发全站候选，也不为消化剩余候选增加面板。其他模式按其实际页面目标选块。
- **提交候选**：主 Agent 按 [关联技能](../../关联技能.md) 的 `copywriting` 路由，默认在 Google AI Studio 提交 `blocks`、`facts`、`voice` 和相关状态材料。每块写 `id`、`type`、`purpose`；A 在用途说明中引用所见章节或状态 ID，写明此处缺字会损失什么。只向 Gemini 索取需创作部分的 1～3 条候选；贞贞 API 限用户明确指定时使用。缺事实记在交付记录，失败保留真实错误，由主 Agent 沿原入口回收或退稿，不自行代写。
- **独立审核与回填**：`candidate` 按第 0 步逐处复核，必要块才检查候选质量。保存 `copy/review.json` 的实际代理回执与 `slots`，每项含 `id`、`decision: keep|drop`、`reason`，与本轮 `brief.blocks` 一一对应。合并项记 `drop`，理由写保留项 ID；`approved.json` 只收 `keep` 及确切候选引用或固定原文出处。可附第 3.5 节删改表。记录格式见 [自动化与门槛](../../自动化与门槛.md)。
- 门槛：第 1 条“不新增事实”违反一次即本轮不通过；字数超上限只提示。

无需创作时可列空 `blocks` 并说明 `empty_reason`，或为用户固定原文填写 `source=fixed`、`text`、`origin`。成品完成后按 [page 模式](04-成品页面.md) 独立核对实际页面。用户只要审核已有页面时可直接进入 page；只更新技能时不发起审核。
