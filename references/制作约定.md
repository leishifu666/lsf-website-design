## 当前用户偏好（评审于2026-10-31更正）

A 有指定参考时，先把主站当前范围内的页面、行为和资产取证做完。后面的五站研究与五项组件偏好仅用于补足需要的内容与已有部件。其它案例或组件出现、原站没有的效果，不上页面。

- **所有模式先定表现技术，参考还原沿用原机制（2026-10-31）**：制作前按[特殊渲染第0.1节](特殊渲染.md#01-所有模式先选表现技术再制作)确定核心场景、实际渲染技术、资源形态和动效驱动，写入现有DESIGN.md与组件规格并实际落实，不能默认交付平面排版、图片位移和通用淡入。模式B迁移适用机制；A先读公开代码与资源，再沿用参考核心场景的渲染接口、场景库、模型/材质及驱动方式，不擅自降成看起来相似的替代；C每个方向都说明表现技术，D说明候选技术证据及采用方式；E在优化范围内复用或调整现有机制；F把技术证据与实施约束写进提示词，不越界建站。GSAP负责适合的编排与属性驱动，不能替代WebGL渲染、真实模型或shader，也不强制把参考核心时间线改写成另一套引擎。本条优先于旧“统一迁移到GSAP”和“仅记录简化即可”的表述，不强制所有网站使用三维；用户明确的纯排版方向与局部修改范围继续优先。
- **模式A内置取证与多构建Agent（2026-10-31）**：页面地图、交互驱动识别、全状态与素材分层、组件实施规格、同条件验收均已内置于[参考取证与组件规格](参考取证与组件规格.md)，不依赖另装克隆类技能。这是已有的多构建能力；用户选择只做一套时由当前对话主Agent直接制作，不因历史授权默认分派构建。用户本次另行明确要求并行时，才按独立组件分工；主Agent先稳定共享基础、明确文件所有权并负责整合，不创建worktree或自动提交，不按规格行数机械增派Agent。实现并行不增加现有设计评审次数。
- **先五站调研，再设计独特性（2026-10-31）**：新建、整页改版和重新生成网站，先实际调研至少5个不同的真实网站，说明各站的记忆点、产品关系、形成机制及本项目取舍，再做方向预览或制作。每个原创方向须有可复述且与产品有关的核心记忆点，选定后写入项目DESIGN.md并落实到页面。本条替代旧C“默认不找参考”，细则见[五站调研与记忆点](五站调研与记忆点.md)。用户之后明确限制联网或要求只按指定参考执行时，以该次要求为准；只分析指定站、局部修复、仅提示词和技能更新不追加五站。既有评审预算不变。
- **视觉素材与建模同等重要（2026-10-31）**：展示型网站默认主动规划并实际使用与主题有关的摄影、透明底物件、插画或三维建模/渲染素材，形成主体、前景和环境层次；不局限于HTML、Canvas、Three.js等代码绘制，不用平面几何拼图代替应有的真实材质和氛围。Codex中优先使用可用的GPT生图能力，透明物件须请求并验证真实alpha；生图能力不可用时记录待生成项，不自动切图库，替代须有用户明确接受，建模可用已有模型或可用的建模工具，详见[氛围图片](氛围图片.md)和[特殊渲染](特殊渲染.md)。用户指定Codex内置生图（GPT Image 2.5）；工具未暴露型号时记录实际工具与回执，不冒称已锁定后台版本；不强制每页三维，不堆无关图片，用户明确的纯排版方向优先。
- **评审提速（2026-10-31）**：默认最多2次真实独立调用、1批集中修改。首审达标即止；按需由全新Agent定向复核，不再每次全量盲评追分。失败/超时及exec兜底共用预算，到限如实报告未达标/未验证。评审同次加载[unslop审查法](unslop-审查法.md)，用户方向与GSAP要求优先。此条替代旧“循环到达标、最多10轮、连续两轮”的默认约定，命令和细则见[自动化与门槛](自动化与门槛.md)。
- 当前前端阶段只评设计感、美感和动效表现，采用[五维美学评分表](../templates/评审评分表.md)。不按性能、加载或工程指标评分，不运行每轮Lighthouse门禁，不为提高指标减少动画；工程优化留待用户要求。
- **禁用按钮hover上浮、hover带动图标运动**。不能以“所有内容有动画”为由重新加入，也不能原样保留组件库里的同类效果。其他动效仍要有设计并实际审查。
- **所有网页制作模式共用：每个实际制作的网页至少复用5个不同的适用组件或交互动效**。制作前必须查用户Chrome“设计类工具网站 → 有趣高级的组件”书签，从对应网站取得真实源码，按页面主题适配并实际使用；流程、计数与来源记录见[组件书签与源码复用](组件书签与源码复用.md)。只看演示后自行重写、仅引入库、堆零散图标或重复实例都不能凑数。此要求不限于模式C，随机种子与否不改变它；只分析、只反推提示词或仅更新技能时，保留制作约束但不越界实现网页。31条入口的具体源码地址、迁移入口、付费/许可和未验证项见[组件网站源码核查](组件网站源码核查.md)。
- **生图与透明底单体**：根据参考和主题规划素材；A 的主角先查原站采用的模型、分层绘画或视频及其遮挡与光照，再决定制作方式。适合独立叠放的绘层可做真正透明底单体；环境图按需要保留，不默认全部画完整背景，不硬凑数量。内置image_gen透明请求显式设`transparent_background: true`并检查实际alpha。模式F同时交付逐项素材方案和完整生图提示词，详见[氛围图片](氛围图片.md)。
- **当前内置生图每条提示词固定结尾（2026-11-02）**：每条网站生成、编辑和变体提示词均以固定句结束：“画面干净通透，材质完整自然，纹理平滑统一，主体清晰，避免过度锐化、色斑、噪点、碎纹、崩坏和畸变。”，不得改写、遗漏或在其后追加其他提示词文字。默认不切换Midjourney；历史免附句例外已由当前要求覆盖。
- 本段和五维评分表优先于旧工程参考中的性能建议、hover范例和七维评分；当本次请求仅为更新技能时，不修改网站、不发起网站评审。

## 4. 硬规则

- 不照抄参考站的具体视觉（配色值、字体、版式、插画、文案）。只迁移原则。模式A 例外：数值和动效参数照参考站，文案、图片、logo、字体文件、插画仍不能照搬。
- 没有实测的数据（字体、颜色、间距、性能分数）不写成事实，标“推断”。
- 完整六版探索中的 1～3 版不交付、不被选中、不参与组合；此条不适用于模式A/C的甲/乙/丙三方向可选预览。
- 完整探索只合并一次方案卡对比；选定成品使用两次预算。未达标可展示当前版本，但不能冒充验收完成。
- 交付前按当前制作模式核对适用规则；B/C/E可借[反套路清单](反套路清单.md)诊断，A不因参考本身使用某手法扣分，也不借此偏离已选风格。
- 交付前用 375 / 768 / 1440 截图自查实际页面（若已进入开发）。
- 外部组件库只借鉴交互机制，不照搬视觉。

### 后续技巧的收录

- 新技巧优先合并进已有专题 reference，按“解决的问题 / 适用场景 / 判断或最小做法 / 限制与替代 / 验证方式 / 来源与验证状态”记录；主文件只保留入口与何时查阅。同类内容合并，冲突时写清适用条件，专题难以检索时再拆分，不为每本书或每条收藏新建文件，也不要求每次任务通读全部技巧。
- 区分来源概念、技能应用建议和用户偏好。来源写作者/版本/章节或链接；推导出的网页做法明确标为应用建议，不把示例数值、方案编号或评分线说成心理学定律。用户已选的工具、模式与授权继续按当前约定执行。
- 经反复验证且适用范围广的判断再提炼为设计原则；经常复用的代码可沉淀为模板或组件，能稳定、客观检测的问题再考虑脚本。未实测的内容标明待验证。
- 技巧默认作为按场景选择的方法，不因收录就升级为所有页面的硬规则、Hook 门禁或额外任务阶段；用户参考与项目已有设计系统优先。
