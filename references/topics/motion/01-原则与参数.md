## A. 原则：为什么丝滑 / 高级，什么时候不该动

1. **自然 = 有物理感**。网页状态常常是瞬间切换，所以显得假；现实里没有东西会凭空出现或消失。建议多用弹簧动画。—— Emil Kowalski《Great Animations》https://emilkowal.ski/ui/great-animations
2. **快**。快的动画提升“感知性能”；用 ease-out；UI 动画通常应 <300ms。（同上）同一个 300ms，ease-in 的下拉菜单就是比 ease-out 的显得慢。——《7 Practical Animation Tips》https://emilkowal.ski/ui/7-practical-animation-tips
3. **有目的**：空间一致性、表示状态变化、解释功能、给出反馈、避免突兀跳变。“只是好看”且用户会频繁看到的动效，就别做。—— Emil 官方 skill 文件 https://github.com/emilkowalski/skills/blob/main/skills/emil-design-eng/SKILL.md
4. **频率帮助决定节奏，不是固定次数门槛**：Emil和Rauno提醒，高频命令及重复操作的装饰动画容易显得拖沓；低频引导可以承载更鲜明的体验（https://emilkowal.ski/ui/you-dont-need-animations 、https://rauno.me/craft/interaction-design）。补核[Emil的Raycast原帖](https://x.com/emilkowalski/status/2054264701790421135)：他主张键盘触发不加动画，实例是每天反复打开命令工具。这是从业者建议，不扩成所有键盘交互的普遍禁令。本技能仍按用户要求设计和审查全部内容，保持焦点与真实结果即时可见，不等待装饰动画；需要直接切换的具体高频状态在清单说明依据，其他适用状态继续由GSAP实现，见J3。
5. **可打断**：用户中途改主意时，动画要能从当前位置平滑接上。CSS transition 能中途转向，keyframes 只会从头重播（Emil，Great Animations）。真实世界本身就可打断，比如翻书（Rauno）。
6. **动势与空间连续**：手势要保留甩出的速度和角度；元素从哪里来就回哪里去，比如 App 从图标展开、Toast 从同一方向进出（Rauno；Emil 的 You Don't Need Animations）。
7. **要和品牌气质一致**：Sonner 故意用了稍慢的时长和 `ease`，显得优雅。俏皮的组件可以多一点弹，专业仪表盘就要干脆、快（Emil 的 SKILL.md）。
8. **属性优先级**：视觉移动、缩放优先用`transform`，淡入淡出优先用`opacity`，避免用`left/top/width/height`逐帧改变几何而反复触发布局；需要真实重排时按K节处理。可合成的transform动画通常能避开逐帧布局/绘制，但不保证所有transform或JS驱动动画在主线程繁忙时都流畅。`will-change`仅在有依据时局部使用，结束后移除；不据此替换用户指定的GSAP或削减动画。来源：[web.dev动画指南](https://web.dev/articles/animations-guide)，2026-10-23复核；详细限制与验证见K节。
9. **无障碍**：`prefers-reduced-motion` 表示用户希望减少“非必要运动”；缩放、平移大物体会诱发前庭不适。https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion 。减少动效不等于完全不动（Chrome View Transitions 文档；Emil 的 SKILL.md：保留辅助理解的 opacity / 颜色过渡，去掉位移类动画）。NN/g：视差、轮播自动前进、滚动劫持都可能让前庭障碍用户头晕；闪烁可能诱发癫痫。https://www.nngroup.com/articles/animation-duration/
10. **Disney 12 原则落到 UI**（IxDF）：挤压拉伸用来表现可按的触感；预备动作（anticipation），例如 hover 时轻微移动，暗示“这里能点”；跟随与重叠，例如图先动、标题和描述随后跟上，用来建立层级；慢入慢出；弧线路径；夸张要克制，过度会烦人。https://www.interaction-design.org/literature/article/ui-animation-how-to-apply-disney-s-12-principles-of-animation-to-ui-design
11. **微交互结构**（Saffer）：触发器 → 规则 → 反馈 → 循环与模式（triggers, rules, feedback, loops & modes）。这里只读到书的目录和简介：https://www.oreilly.com/library/view/microinteractions/9781449342760 ；https://dl.acm.org/doi/10.5555/2531374 。NN/g 的定义：微交互就是一对“触发–反馈”，反馈应紧贴触发点、小而贴合上下文；它的作用是显示系统状态、防错（例如提供撤销）、传达品牌。https://www.nngroup.com/articles/microinteractions/

## B. 参数表（每个值都注明来源）

| 项目 | 值 | 来源 |
|---|---|---|
| UI 动画上限 | 通常 <300ms；180ms 的下拉比 400ms 显得灵敏 | Emil, 7 tips / You don't need animations |
| 按钮按下反馈 | 100–160ms | Emil SKILL.md |
| Tooltip / 小 popover | 125–200ms | Emil SKILL.md |
| 下拉 / 选择框 | 150–250ms | Emil SKILL.md |
| 弹窗 / 抽屉 | 200–500ms | Emil SKILL.md |
| 时长随元素尺寸和移动距离调整 | 相近条件下，大体量或长距离可试更长时长；旧示例的小下拉/全屏菜单150 vs 300ms只是对照，不是公式；操作结果仍即时响应，见J2 | [原尺寸示例](https://x.com/emilkowalski/status/2043666802404696483)；[2026-10-20新核原帖](https://x.com/emilkowalski/status/2108531407786242389)【从业者观点】 |
| NN/g 时长 | 大多 100–500ms；简单反馈（勾选、开关）约 100ms；大的屏幕变化 200–300ms；500ms 起明显拖沓；400ms 算很慢，只用于大屏上的大位移；进场比退场略长（如 300 进 / 200–250 出） | https://www.nngroup.com/articles/animation-duration/ |
| 按压缩放 | `:active { transform: scale(0.97) }`，范围 0.95–0.98，`transition: transform 160ms ease-out` | Emil 7 tips + SKILL.md |
| 入场初始缩放 | 不要从 scale(0) 开始；从 0.9 以上，例子是 0.93 / 0.95，配合 opacity | Emil 7 tips |
| 自定义缓动 | ease-out `cubic-bezier(0.23,1,0.32,1)`；ease-in-out `cubic-bezier(0.77,0,0.175,1)`；抽屉 `cubic-bezier(0.32,0.72,0,1)`；UI 永远不用 ease-in | Emil SKILL.md |
| 缓动怎么选 | 进出场用 ease-out；在屏幕内移动或变形用 ease-in-out；hover / 颜色变化用 ease；匀速运动（marquee、进度条）用 linear | Emil SKILL.md |
| M3 缓动 | standard `cubic-bezier(0.2,0,0,1)`；standard-decelerate `(0,0,0,1)`；standard-accelerate `(0.3,0,1,1)`；emphasized-decelerate `(0.05,0.7,0.1,1)`；emphasized-accelerate `(0.3,0,0.8,0.15)`；emphasized 在 CSS 中没有对应值，用 standard 兜底 | https://m3.material.io/styles/motion/easing-and-duration/tokens-specs |
| M3 时长 | short1–4 = 50/100/150/200ms；medium1–4 = 250/300/350/400；long1–4 = 450/500/550/600；extra-long1–4 = 700/800/900/1000。示例：选择控件 200ms standard；FAB 展开成 sheet 400ms emphasized；卡片展开到全屏 500ms emphasized。注：M3 Expressive 已改用弹簧系统，这套时长与缓动“不再维护” | 同上 |
| 弹簧（Apple 式） | `{type:"spring", duration:0.5, bounce:0.2}`；bounce 保持 0.1–0.3，大多数 UI 不要弹；拖拽关闭、俏皮交互可以弹 | Emil SKILL.md |
| 弹簧（物理参数） | `{mass:1, stiffness:100, damping:10}`；跟随鼠标时用 useSpring，参数 stiffness 100、damping 10 | Emil SKILL.md |
| Motion 弹簧默认值 | bounce 默认 0.25（取值 -1 到 1，0 表示无回弹）；damping 默认 10；mass 默认 1；restSpeed 0.1；restDelta 0.01；tween 默认 0.3s；支持 `visualDuration`。页面写 stiffness 默认值为 1，看起来不太对，使用前需核对 | https://motion.dev/docs/react-transitions |
| 交错（stagger） | 每项间隔 30–80ms；stagger 期间不能阻塞交互 | Emil SKILL.md |
| Tooltip 延迟 | 第一个 tooltip 有延迟；之后在同组里移动时立即出现、不加动画（`data-instant` 时 duration 设为 0ms，过渡 125ms ease-out） | Emil 7 tips |
| 遮盖瑕疵用的模糊 | 切换状态时加 `filter: blur(2px)`；模糊始终 <20px（Safari 上开销大） | Emil 7 tips / SKILL.md |
| 不对称时长 | 用户在做决定的环节慢（长按删除：2s linear），系统响应快（松手：200ms ease-out）；退出比进入快 | Emil SKILL.md |
| 甩动关闭 | 速度 >0.11 px/ms 即关闭，不管拖了多远 | Emil SKILL.md |
| Lenis 平滑滚动 | 默认 lerp 0.1；duration 1.2s（设了 lerp 时 duration 无效）；默认 easing `t=>Math.min(1,1.001-Math.pow(2,-10*t))`；smoothWheel true；syncTouch false | https://github.com/darkroomengineering/lenis（README） |
