# 图标与插画（2026-10-19）

## 1. 规则（用户规定）
1. **不准手写 SVG 图标。** 界面图标（箭头、搜索、菜单、文件、勾选等）只能使用一套开源图标库中的实际组件/原始图标；不能手写SVG路径、CSS几何或字符，也不用生图替代功能图标。插画与场景物件按生图规则或授权资产处理。
2. **不准用字母或符号冒充图标**：「篇章 v」里的小写 v、`>`、`^` 当箭头，一律换成图标库的 chevron。
3. **整站只用一套图标库**，统一线宽、尺寸、端点样式；不同库混用会显得乱。
4. 例外：品牌 logo 可以是 SVG（来自品牌方的文件，不是现画的）；从图标库原样复制的 SVG 要在每个 SVG 紧前写 `icon-source: 库名/图标名` 注释。

## 2. 用哪个库（许可证 2026-10-19 用 `npm view` 核对）
| 库 | npm 包 | 许可证 | 风格 |
|---|---|---|---|
| Lucide | `lucide-react` / `lucide-static` | ISC | 线性，24 网格，2px 线宽，最常用 |
| Phosphor | `@phosphor-icons/react`（核心包 `@phosphor-icons/core`） | MIT | 6 种字重（thin～fill、duotone），适合要变化的品牌 |
| Tabler | `@tabler/icons-react`（`@tabler/icons`） | MIT | 线性，数量多 |
| Heroicons | `@heroicons/react`（`heroicons`） | MIT | Tailwind 官方，outline / solid |
| Remix Icon | `remixicon` | Apache-2.0 | 线性 + 面性成对 |
| Iconify | `@iconify/json`、`unplugin-icons` | 包本身 MIT；**每个图标集各有许可证**，用前查该集 | 聚合 200+ 图标集 |

选法【归纳】：先看参考站用的是哪一类（线性 / 面性 / 双色、线宽多少），选风格最接近的一个库；模式A 还原时用 `extract-components.mjs` 量参考站图标的尺寸和线宽。

## 3. 立体示意、插画与SVG边界

用户2026-11-02允许SVG绘制立体物件、等轴测/剖面示意和有意义的空间图解，优先复用开源场景或图形组件；它们与UI图标分开。SVG呈现的是立体示意，不能冒称真实模型、WebGL或原参考机制。图中箭头、按钮、关闭等功能图标仍必须来自开源图标库；不能把图标包进插画组件绕过规则。下面旧的“静态装饰优先生图”不禁止这类明确允许的立体示意。
- 根据参考主动规划透明底人物/道具/前景单体，作为独立排版和GSAP动效层；环境图按用途保留。具体方案、真实alpha检查与每条提示词的固定结尾见[氛围图片](氛围图片.md)。模式F逐项交付素材生图提示词；实际制作再调用，不能把计划称作已生成。
- 实现前写 assets-plan.json：元素用途、库/许可证或生成素材路径、统一的材质/透视/配色、静态还是动态、触发方式。UI 图标库源码是 SVG 并不违规；来源注释只是声明，仍应核对真实库资产，不能拿它为手写路径洗白。
- 静态拟物装饰优先生图，透明底、边缘干净、无残留字样，整组保持同一风格；不要用 div/SVG 拼一幅平面装饰，只加 hover 就称为动态场景。用户说的真实物件可采用实物抠图/生成物件 + 浮动 UI 拼贴。
- 功能性的闹钟、仪表、地图或窗口组件若有真实状态、操控和反馈，可以按组件实现；有意义的持续运动、物理变化或空间交互可使用 CSS/Canvas/Three.js/WebGL，按性能与降级要求选择，不强制每页 3D。

- 这不是界面图标，是插画。用生图工具出透明底 PNG（提示词结尾加固定句，见 `氛围图片.md` 2.5），再用 `process-image.mjs` 处理；或用开源插画库并核对许可证。
- 同一页的插画用同一套画风：同样的线宽、配色、透视角度。【归纳】
- 写错的插画（图四的勾和边框画歪了）比没有更糟：生成后 100% 放大检查，不合格重出。

## 4. 图标和文字对齐
**目标【归纳】**：图标的大小与对齐应适应旁边的文字，并遵循项目已有设计系统。居中和基线对齐按场景选择，不把某个 CSS 单位当成全站硬规则。

**常见问题**：图标尺寸与字号脱节；用 `vertical-align: -6px` 这类魔法数硬调，换字号就错（图二）。头像方块和右边的名字既不顶齐、也不居中（图一）。下拉菜单里选中项多了左内边距，文字和其他项不齐（图三）。

### 4.1 常规写法
- 图标 + 文字放进 `display: inline-flex; align-items: center; gap: …` 的容器。【归纳】
- 图标尺寸需要跟文字缩放时，可用 `width: 1em; height: 1em`（或 `1.25em`）；固定工具栏、独立图标按钮等沿用组件尺寸令牌，不强制把已有 px / rem 全改成 cap。【归纳】
- 要更精确地按字形对齐，可以给文字加 `text-box: trim-both cap alphabetic`，裁掉字体上下多余空间，再居中。Baseline 2026 新近可用。来源：MDN text-box-trim https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-box-trim
- 头像 + 文字块：`align-items: flex-start`，头像顶部和名字首行顶部对齐；或者整块居中。两种选一种，全站统一。【归纳】
- 列表选中 / hover 态：只改背景和颜色，不改内边距；背景要往外扩，用负外边距或给所有项同样的内边距。【归纳】

### 4.2 可选技巧：按大写字高缩放图标（cap）

- **解决的问题**：同一标签换字体或字号后，固定高度的图标与字形比例不协调。
- **适用场景【归纳】**：图标需要接近拉丁大写字高、并与文字基线配合的单行标签或链接。中文、混合字体、多行文字先看实际字形和布局，必要时继续用 `em + center`。
- **依据**：`1cap` 取元素所用首个可用字体的 cap-height，约对应拉丁大写字高；不是汉字高度或行高。缺少可靠字体度量时浏览器可估算，无法确定时使用字体 ascent。`baseline` 负责盒子的基线对齐，不识别 SVG 内部可见图形的边缘。
- **最小写法**：以下针对正方形 `viewBox` 的库图标；给图标组件设置 `class="label__icon"`，需要 cap 方案的容器另加 `label--cap`。基础方案同时作为不支持 cap 时的降级。

```css
.label {
  display: inline-flex;
  align-items: center;
  gap: 0.4em;
}

.label > .label__icon {
  display: block;
  font: inherit;
  flex: none;
  inline-size: 1em;
  block-size: 1em;
}

@supports (block-size: 1cap) {
  .label--cap {
    align-items: baseline;
  }

  .label--cap > .label__icon {
    inline-size: 1cap;
    block-size: 1cap;
  }
}
```

- **限制与替代**：图标库自带的 `width` / `height` 或内联样式可能影响尺寸，需核对最终计算样式。非正方形图标按 `viewBox` 比例另行处理宽度，不能套用上面的正方形尺寸；只有高度变化，并不保证宽度自动符合预期。图形内留白、描边和视觉重心仍需检查；不承诺“所有字体都完美对齐”。图标大小不等于按钮可点击区域，不随之缩小操作目标。【归纳】
- **来源与验证状态（2026-10-19）**：已核对 [W3C 字体相对单位](https://www.w3.org/TR/css-values-4/#cap)、[W3C 基线生成规则](https://www.w3.org/TR/css-align-3/#baseline-export) 与 [MDN length](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)。代码示例待本机验证；不作为新的脚本门禁或强制检查项。

## 5. 检查

允许的立体SVG可在单个根元素标记`data-lsf-illustration="isometric"`（或`cutaway`、`spatial`），脚本会提示人工复核，不把它当手写图标。标记不能证明用途或来源，也不能为箭头等UI图标豁免；评审仍实际检查。
```bash
node scripts/check-icons.mjs --src src                                   # 手写 SVG
node scripts/check-icons.mjs --url http://localhost:3000 --viewports 375,1440   # 字符冒充图标、图标没对齐、头像没对齐、列表项不齐
```
实测（2026-10-19，测试页）：报出 `Card.jsx` 里手写的两段 path（lucide 引入的和 logo 放行）；报出「篇章 v」的字符箭头、`vertical-align:-9px` 的搜索图标偏 5.6px、头像比名字高 17px、选中项多缩进 10px；`inline-flex` 对齐的图标没有误报。linear.app 上 0 误报。

## 6. 页面里的小设计：要么用代码做成会动的，要么用生图（用户规定 2026-10-19）
像图二那几张“开会卡片 / 待办卡片 / 聊天卡片”的小装置：
- **动态**：用代码做，并且真的要动起来。比如用真实组件拼成的 UI 卡片，让待办被逐条勾选、消息逐条弹出；或者用 Three.js / WebGL 做一个能转、能跟鼠标的小模型；或者用 Rive / Lottie 动画。动起来才值得用代码写。
- **静态**：顶多有个 hover，就不要用 CSS / SVG 手画，改用生图模型出透明底插画。同一页的插画一次定好画风（线宽、配色、透视、光源），提示词结尾加固定句（`氛围图片.md` 2.5）。
- 不允许的中间态：用 div、边框、圆角手搭出来的静态“插画”，又不动、又画得粗糙。
- 参考做法：先用 `extract-media.mjs` / `extract-motion.mjs` 看参考站这类小装置是图片、视频、Rive、canvas，还是真实组件，再照同样的技术路线做。
