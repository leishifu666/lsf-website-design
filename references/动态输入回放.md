# 两侧动态输入回放

先在浏览器走过目标路径，选好能代表每个机制的控件和观察层。复制 [输入计划示例](../templates/behavior-replay.example.json)，按实际 DOM 替换示例地址、选择器、输入和等待区间。每一类可以有多个实验。组件菜单和卡片使用不同机制时分开测。触屏、Canvas 内对象或跨窗口行为可另存专门实验。

## 两侧运行

在技能的 scripts 目录安装现有 Playwright 依赖后，从技能根目录执行。沿用 CHROME_PATH、LSF_PROXY 和 HEADED 环境设置。默认运行隔离的无头 Chromium，无用户登录态。依赖在测试项目中时也可复制脚本及其 lib 同目录运行。

```sh
node scripts/replay-behavior.mjs ref/inputs.json reference ref/replay-01
node scripts/replay-behavior.mjs ref/inputs.json implementation test/paired-01
```

两个命令读取同一文件，单次回放共用一个浏览器上下文。相同文件字节、视口、实验 ID 和步骤顺序才能对账。要验证波动，把整套计划再跑一轮写入新目录。参数 `observeMs` 指输入调用完成后继续采样的毫秒数，默认 400。原生事件有独立时间戳，操作前的可操作性等待会记入时间轴。对长加载页，等可操作的目标层出现，再开始下一个实验。

## 选目标和动作

- `targets` 用稳定角色命名。CSS 选择器可为共用字符串，也可用 `{reference,implementation}` 对应两侧。输入目标须唯一。观察目标不唯一或缺失，会留下实际匹配数；核对人不能据此判定相同。
- 每项实验的 `watch` 可包括触发者、主角、背景、遮罩、导航、受控面板或实际滚动容器。对目标指定 `pseudos` 和有名称的 `children`，分别记录伪元素和子层。通过 `properties` 选择 CSS 字段或应用公开的 CSS 自定义属性，可在计划级或单个目标覆写。伪元素的 rect 为 null，能直接读取的宽、高、inset 可从计算样式取得。
- 六类使用 `load / scroll / hover / pointer / component / navigation`。冷进入用 `visit`，同上下文刷新用 `reload`。若需加载完成态，可用 `waitFor` 等唯一的可见就绪标记，或用 `wait` 观察指定时间。稳定等待不会补回加载中的帧。
- 滚轮用 `wheel` 设置 dy、可选 dx、count 和 intervalMs；在滚轮之前用 move 指定坐标。小增量、间隔、快速大增量、停止等待和未静止时反向各留一段。嵌套滚动容器可从对应层的 scrollTop 读实际位移。
- `hover` 进入实际控件，`move` 到空白位置提前离开，再 hover 回到相同目标。坐标相对于计划视口。指针跟随用多段 move，观察目标应是被驱动层。多层开放或跨段响应要一并列入 watch。
- `down / up` 分开测按住与释放，`focus / key` 测键盘路径。焦点可用 Tab、Shift+Tab 移动，箭头、Home、End、Escape 可单独输入。激活键 Enter 和 Space 必须声明当前焦点控件。其他组件可用 click，先人工确认这是只影响页面显示的操作。点击菜单、标签、展开项时同时采集受控面板。
- `link` 点击真实站内链接。到达地址默认须等于解析后的 href；已确认的同源重写用 expectedUrl 指定。用 back / forward 走浏览器历史；direct 会从空白文档直接加载给定地址。要测转场中断，单独开一个实验，让 link 设置 `"interrupt": true, "observeMs": 40`，紧接 back、另一个 link 或 direct，并对后续步骤设置实际预期地址。记录两个输入的实际间隔；如果自动等待越过了转场时段，调整探针再测。本工具没有点击表单提交、下载或打开外链的动作。
- `screenshotsMs` 在动作派发结束后按请求时刻截屏，`screenshot: true` 在本步末尾截屏。每张截图保存实际起止时间。截图可能比请求时刻更晚，对快速中断使用连续数值帧，另开一轮截图。无障碍、折叠态、触屏操作按站点单独补测。

## 回放产物

每轮必须使用空目录。input-plan.json 逐字节保存本轮使用的计划。replay.json 保存计划 SHA-256、浏览器版本、运行模式、视口、选择器映射和各步状态。frames/ 保存显式关键截图及失败时当前画面。单项失败会保留之前取得的帧，跳过该实验剩余步骤；后面的实验从当时实际状态继续，运行脚本返回非零。恢复必须回到明确起点。

1. `experiments[].steps[].events/frames` 分开保存真实事件和浏览器渲染帧。wallMs 为 epoch 毫秒，tMs 相对于该步骤开始，documentStartMs 区分文档生命周期。帧含真实 URL、根滚动位置、目标及子层几何、computed style 和控件状态。每次输入后优先保留最先几帧，后段降低采样率。跨文档或浏览器忙碌时检查实际帧间隔。
2. `direct` 是页面公开的运行值，如 GSAP 版本、ScrollTrigger 起止值、Lenis options 和画布尺寸。需要核对动画参数时，在相应目标上设 `animations: true`。`direct[].effects` 会保留目标及指定子层正在运行的 Web Animations API timing、keyframes 和首次读到的时间，帧内 animations 保留进度与播放状态。CSS 时长、缓动与延迟也在各帧的计算样式内。私有运行态、没有导出的实例保持空缺。
3. `measured` 按实验和 **从零开始** 的 step 索引，给出每层属性第一次变化所在的采样区间及最后一次观察到变化的时间。以实际输入事件为零点，无对应事件时从步骤开始计时。滚轮另列起止 y 与首次观测到位移的时间上界。内容或实例重建时应结合逐帧图像和文档起点解释数据。
4. `fitted` 仅对可用的单次单调滚动、稳定尾段、足够中间样本拟合指数曲线，附样本数、误差和所用端点。指标体现本次输入、设备与当前观测；不据此填写源码 easing。Canvas/WebGL 内部的对象轨迹需公开实现、运行实例或独立逐帧图像证据。DOM 外框保持不动不能证明内部场景静止。

`ok` 表示计划动作完成且取得了主文档帧。另核对两侧机制、层级、相对顺序、视口和数值误差后，才可更新成品对照结果。
