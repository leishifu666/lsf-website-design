# 风格还原：让 AI 按参考站的真实数值做，不瞎编（模式A）

## 为什么 AI 会“瞎搞”
1. 只给链接或截图，AI 看不到真实数值，只能凭印象猜颜色、间距、圆角；动效完全看不到。
2. AI 有自己的默认审美（圆角 12px、紫色渐变、fade-up、Tailwind 默认色板），猜不出来就回到默认。
3. 模式B 的“只迁移原则”、第4版法则、反套路清单会主动把它推离参考站。模式A 关掉这三条。
4. 只写“请遵守规格”没用。要让规格外的值**写不出来**（Tailwind 主题清空默认值）或**写了就失败**（check-tokens 静态 + 运行时双查）。

先按 [A 模式原站取证与成品对账](A模式证据格式.md) 建立完整状态清单和资产映射。以下抽样脚本服务于这份清单；扫描成功或识别出技术库都不能当成全部状态已经走通。
## 工具分工
| 步骤 | 工具 | 产出 |
|---|---|---|
| 量静态数值 | `scripts/extract-tokens.mjs`（读计算样式 + 网络里所有 CSS 源码，含 CDN） | `tokens.json` |
| 量动效 | `scripts/extract-motion.mjs`（库识别、ScrollTrigger/Lenis 运行时参数、canvas/WebGL 探针、按钮优先的 hover/按压、真实滚轮逐帧） | `motion.json`、`frames/`、`.webm` |
| 拆组件 | `scripts/extract-components.mjs`（按钮、卡片、导航、输入框、标签、区块，按样式去重成变体并截图） | `components.json`、`components.md`、`crops/` |
| 页面结构、交互与组件合同 | 本技能内置[参考取证与组件规格](参考取证与组件规格.md)和[规格模板](../templates/组件还原规格模板.md) | 页面地图、驱动模型、状态/内容/素材层、响应式、目标文件及验收条件；不依赖其他克隆技能 |
| 写规格 | `scripts/spec-draft.mjs` 出草稿 → 人工确认 | `ref/reference-spec.json` |
| 生成令牌 | `scripts/gen-tokens.mjs` | `tokens.css`、`tokens.tailwind.css`、`tokens.allow.json` |
| 对账 | `scripts/check-tokens.mjs`（静态 + `--url` 运行时）、并排截图、同一个 extract-motion 跑实现页 | 违规清单、还原度评审 |

## 流程

参考站存在滚动推进的章节或持续变化的主场景时，先读 [滚动叙事](滚动叙事.md)。取证和规格补上分镜、触发式/进度式、固定区间、阅读停顿、倒滚/锚点直达与移动端差异；沿用现有报告和 ref/motion 证据，不用平滑滚动或通用 fade-up 替代核心叙事，也不另外启动多版探索。
制作使用[统一提示词](../templates/风格参考统一提示词.md)。指定网址先启动原站侦察；缺少参考时先做适用的五站调研并选定主参考，默认直接制作一套；用户明确要比较时，按[预览分流](三方向预览与确认.md)把同一份完整提示词、主题与网址交给三位构建者，各自完成一个预览，不额外指定不同构图、素材或交互。以下取证与高精度要求对直接制作和预览都适用，其他案例不改变主参考风格。用户仅要求分析时执行适用取证，不进入实现或评审。沿用原项目并核对明确技术约束，核心场景按[取证第4.1节](参考取证与组件规格.md#41-核心场景的渲染技术与公开源码取证)查公开代码、资源与真实驱动，锁定后按原机制实现。GSAP用于适合的编排层，不能强制替换参考的核心渲染与时间线；约束确有冲突时说明，不默默降级。素材授权和禁用hover要求继续遵守。
1. **量**（375 / 768 / 1440 各跑一次 tokens 和 components；motion 跑 1440，必要时再跑 375）
   ```bash
   node scripts/extract-tokens.mjs <url> ref/1440 1440
   node scripts/extract-tokens.mjs <url> ref/375 375
   node scripts/extract-components.mjs <url> ref/comp-1440 1440
   node scripts/extract-motion.mjs <url> ref/motion 1440
   node scripts/extract-media.mjs <url> ref/media 1440          # 图片怎么处理：透明抠图、遮罩、穿插、混合模式
   node scripts/check-transitions.mjs <url> ref/transitions 1440 # 弹窗、菜单、tab 的进出场时长和缓动
   ```
   motion.json 里重点看：`libs`（用了什么库）、`runtime.scrollTriggers`（start/end/scrub/pin，GSAP 暴露在 window 上时才读得到）、`runtime.lenisOptions`、`smoothScroll`（滚轮后 60ms 和 960ms 的位移差，能看出有没有平滑滚动）、`rendering`（canvas 类型、着色器数、rAF 次数）、`interactions`（每个按钮/卡片/链接的 hover、子元素、伪元素和按压变化）、`frames[].changedElements`（每一屏有多少元素随滚动在变）。
   读不到的内部参数用当前可用浏览器能力补查；仍不可读取时记录推断或未验证。录屏估算须保留采样条件和范围，不能当精确库配置。自动脚本是抽样/草稿，不代表所有组件和状态已覆盖。
2. **内置结构、全状态与组件取证**：按[参考取证与组件规格](参考取证与组件规格.md)记录页面地图，先判断滚动、点击、悬停、时间或混合驱动，再操作全部有区别的状态，记录内容/样式前后差异、退出与反向行为。核对透明主体、背景、遮罩、视频/Canvas、前景和模型等真实素材层；375/768/1440记录布局和输入变化。重要组件在开工前按[模板](../templates/组件还原规格模板.md)形成目标文件、接口、令牌引用、状态内容、素材及验收合同；重复变体共享，不机械地每个按钮建文件。已有ref证据直接沿用，缺关键状态先补测；不能只凭默认态截图实现。
3. **锁定样式与归并规格**：`node scripts/spec-draft.mjs <url> ref/1440/tokens.json ref/375/tokens.json --motion ref/motion/motion.json > ref/reference-spec.draft.json`。草稿按出现次数取值，会混入无关控件。主Agent核对后给颜色、字号等起角色名，补充滚动/转场，保存`ref/reference-spec.json`。锁定样式值由该文件统一生成令牌；DESIGN.md说明设计语言，组件合同说明结构和状态并引用令牌，不另造相冲突的值。确需适配时记录依据和exceptions，不能为检查变绿偷偷改规格。
4. **生成令牌**：`node scripts/gen-tokens.mjs ref/reference-spec.json src/styles`。
   - 普通 CSS：组件只引用 `tokens.css` 里的变量。
   - Tailwind v4：`@import "tailwindcss"; @import "./tokens.tailwind.css";`。文件里 `--color-*: initial` 等写法会删掉默认色板、圆角、阴影、缓动，只留规格值（Tailwind 官方 Theme variables 文档，2026-10-19 读取，并在 4.3.3 上实测：`bg-zinc-800`、`rounded-lg`、`shadow-md`、`ease-out` 不再生成）。
   - `p-4` 这类数字间距默认仍可用（= 4 × 4px）。要连它一起关掉加 `--strict-spacing`（实测 `--spacing: initial` 后 `p-4` 不再生成，但 `w-4`、`h-4` 也会失效）。不加时由 check-tokens 换算检查。
   - 任意值（`p-[13px]`）和 `duration-300` 主题挡不住，由 check-tokens 查。
5. **实现与多Agent分工**：主Agent先稳定全局令牌、字体、类型/接口、共享组件和资源路径；组件合同就绪后，可按[并行构建分工](参考取证与组件规格.md#6-多构建agent共享基础先行按所有权并行)让多个构建Agent在原项目各自负责独立文件，主Agent继续取证和最终装配。不创建worktree，不自动提交，不按150行或卡片数量机械拆Agent。下列约束连同组件合同正文、截图/状态证据、素材和文件所有权交给实现者；不只发“去读另一个技能”。用户未要求时不自行写入AGENTS.md。用户另行授权Gemini实现时沿用[关联技能](关联技能.md)的外部模型交接，不能把文案授权扩大为整站外发：
   ```
   本任务是风格还原（模式A）。
   - 样式值只能来自 ref/reference-spec.json 生成的 tokens.css / tokens.tailwind.css。不能写字面量颜色、px、ms、cubic-bezier，不能用 Tailwind 任意值和默认色板。
   - 需要规格里没有的值：先核对是否遗漏了参考取证。主题替换、中文适配或可访问性带来的常规可逆调整，写清“需要什么、为什么、参考站对应位置”，记录到 reference-spec.json 的 exceptions 后重新生成令牌；只有会改变用户目标或已锁定核心风格时才澄清，不能为让检查变绿而修改规格。
   - 核心场景沿用取证锁定的渲染接口、场景库、资源形态、时间线/状态机和转场机制；原站用模型、深度位移、shader就做对应机制，不能擅自换成图片移动或普通淡入。GSAP承担适合的编排与属性驱动，不强制改写原站核心驱动；读不到的值不编造成实测。
   - 不得套用自己的默认圆角、阴影、渐变、fade-up。
   - 按已完成的区块运行对应样式检查：node scripts/check-tokens.mjs ref/reference-spec.json src --allow src/styles/tokens.allow.json。多人并行时记录未完成模块的已知缺项，不回退他人工作；相关检查失败先定位，不能改规格或删检查掩盖问题。主Agent装配后按项目实际命令核对类型/构建及真实联动。
   ```
6. **对账**
   - 静态：`node scripts/check-tokens.mjs ref/reference-spec.json src --allow src/styles/tokens.allow.json`。查颜色（hex/rgb/hsl/oklch/oklab/lab/lch/命名色）、字体、字号、行高、字距、间距、圆角、阴影、时长、缓动；未定义的 `var(--x)`；本地自定义变量的值；Tailwind 任意值、数字间距类、`duration-*`、默认色板；React 内联样式和 Motion/GSAP 的 `duration`、`ease`。
   - 运行时：`node scripts/check-tokens.mjs ref/reference-spec.json --url http://localhost:3000 --paths /,/about`。在规格的每个视口下读所有可见元素的计算样式，兜住静态扫不到的写法（第三方组件、浏览器默认样式、JS 写进去的样式）。
   - 截图与状态：同视口、同滚动位置、同tab/展开状态、可比动画阶段，参考与实现各留证据。逐区块检查素材层、交互驱动、返回/退出和移动变化；偏差先判断是取证还是实现错误，再定向修正。
   - 动效与机制：用 `extract-motion.mjs` 跑实现页，结合代码及运行证据和组件机制合同，逐项核对渲染接口/场景库、模型与材质资源、真实进度/状态更新、合成转场、hover/按压及滚动关系。探针结果不能独立证明机制一致；截图相似但核心机制未实现，仍属未完成。
7. **既有独立评审内核对还原度**：在评审目标卡`--target`加入当前规格版本、重要组件合同和状态摘要、实际可消费的参考截图及观察限制，按内置方法交接。仍用既有五维与三项视觉约束；配色、排版、间距、组件、素材层、驱动与转场判“一致 / 接近 / 偏离”，偏离给证据或参考值/实现值。check-tokens用于定位，不把脚本错误自动换成美学扣分。首审达标即止，最多两次真实调用，修改后只复核原问题及实际影响；构建Agent数量不增加评审轮次。

## 这个模式里关掉的规则
- 第4版选择法则不启用；默认直接制作一套。可选三预览仍按同一参考与同一提示词独立执行，不为凑差异偏离参考，用户确认后不再发散。
- 反套路清单：参考站本身用了的做法不算套路。
- `templates/motion-tokens.css` 和 `交互动效.md` 的默认参数：动效时长、缓动、按压缩放一律用规格里的实测值。
- 获奖级打磨：只在用户要求“在原风格上再提升”时做，且不能改动锁定的规格值。

## 边界
还原设计语言、结构关系与行为。主题使用用户自己的文案和资产；用户自有或明确获授权的素材按授权复用，其他参考素材仅作本地对照并保留来源，上线前替换。字体使用有授权版本或记录适配，图标沿用项目的合法素材体系。样例文件沿用`public/_samples/`等已有约定，按项目实际脚本或构建产物核查，不编造`npm run samples`等不存在的命令。取证、规格和并行构建所需的方法与模板已在本技能内。
