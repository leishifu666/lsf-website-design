# 更有趣的页面：先找参考和开源实现，再接入交互

用户说“页面没意思”“有趣一点”“高级一点”“加点厉害的交互”，就读取本文件，并纳入当前模式和既有调研。先查项目已有能力、实际网站与开源组件，不凭印象手搓场景。A沿用主参考机制；E在获授权范围增强；C将方法变成本项目专属体验，不因此另开原创模式。

## 实施顺序

1. 在指定组件书签、实际优秀网站和开源仓库寻找符合本页主题的效果；实际操作滚动、hover、拖拽、倒滚和移动端，不只看封面图。参考Shopify式滚动产品叙事时先选具体页面取证，不能假称所有Shopify站使用同一套动画。
2. 找到对应的开源组件、示例或场景源码，核对许可、必要依赖和项目框架。记录实际源文件、版本/提交、落地文件和适配；未取得可用源码继续找候选，不看完演示就从零仿造，不能用“用了Three.js”冒充复用了场景组件。
3. 先复用项目已有的同源实现，再复用组件库/官方开源示例。主Agent可编写必要的主题数据、连接和布局适配；不得从零手写现成可复用的图标、通用组件或复杂动效引擎。开源不等于演示素材/字体全部可用，资源单独核对。
4. 将实际技术、输入、输出状态、资源与验收写入现有DESIGN.md和组件合同。做出真实可操控场景，再交同一轮视觉评审检查，不能只让画面自己播放。

## 按表现目标选技术

| 想要的体验 | 可选工具与实际职责 | 优先查找的开源实现 |
|---|---|---|
| 产品模型、复杂材质、部件翻转/拆解 | Blender制作模型，glTF/GLB等资源进入Three.js；React项目可用React Three Fiber/Drei | [Three.js示例](https://github.com/mrdoob/three.js/tree/dev/examples)、[Drei](https://github.com/pmndrs/drei)，沿用可用模型和交互组件 |
| 翻滚、翻面、拖拽、卡片空间转场 | GSAP Flip/Draggable或项目已有Motion，负责布局状态、姿态与交互反馈 | 官方示例及已有组件书签；翻滚用于内容切换，不恢复禁用的按钮/图标hover运动 |
| 视差、固定画面、滚动推进故事 | GSAP ScrollTrigger编排pin/scrub/章节；需要平滑滚动时适配Lenis | [GSAP](https://github.com/greensock/GSAP)、[Lenis](https://github.com/darkroomengineering/lenis)，先看参考的实际触发、反向与手机行为 |
| ASCII/字符化空间画面 | Three.js的ASCII示例/效果、Canvas字符绘制层；字符效果对应主题内容 | Three.js官方`webgl_effects_ascii`示例或已核对开源组件，不把整页正文变成难读字符画 |
| Canvas二维互动、粒子、遮罩与位移 | PixiJS或已有Canvas组件承担渲染，指针输入驱动真实状态 | [PixiJS](https://github.com/pixijs/pixijs)与指定组件库的实际源组件 |
| WebGL着色器、折射、流体、深度位移 | Three.js/OGL及已有shader组件承担实时渲染；明确资源与输入 | [OGL](https://github.com/oframe/ogl)、Three.js示例及已核对的React Bits组件 |
| 物理碰撞、弹性拖动、可抓取物件 | Rapier及项目适配组件承担物理，渲染层单独选择 | [React Three Rapier](https://github.com/pmndrs/react-three-rapier)，核对触屏、释放与复位 |
| 角色、图形状态机与交互动画 | Rive/Lottie的已有可用资产及播放器，状态与业务控件联动 | 官方开源运行时与有授权素材；播放器开源不代表所有动画资产免费 |
| 可解释的立体示意、等轴测图 | 允许SVG画空间层次、剖面和状态关系；优先复用适用图形组件 | SVG是立体错觉示意，不冒称真实三维/WebGL；图中箭头等控件仍用开源图标库 |

以上为选型候选，不要求全装、不固定引擎。WebGPU等更强接口只在参考/目标需要且已有可用组件、环境支持时采用，说明回退；使用API前核对项目实际版本与官方文档。

## 输入与反馈必须成立

- 模型、WebGL/Canvas场景优先提供与内容有关的鼠标响应：指针改变观察角度、拖拽旋转/抓取、射线拾取高亮部件、点击展开、配置改变材质等。不能只有自动旋转或跟随光标的装饰，却没有可理解结果。
- 指针离开可回到稳定状态，拖拽不误触页面滚动；必要时有复位入口。触屏使用拖动/点击，关键操作支持键盘和可读名称，不把hover当唯一入口。
- 滚动叙事明确章节、进度映射、pin区间、停顿和倒滚恢复；视差层有前后景依据，不能以无限长空白制造“高级感”。详见[滚动叙事](滚动叙事.md)。
- `prefers-reduced-motion`和图形上下文不可用时保留内容与可完成任务；不为性能评分删掉用户要求的正常场景。

每页至少五项适用源码复用、界面图标必须来自开源库、禁用按钮hover上浮与hover图标运动继续执行。开源检索失败如实说明缺口，不假称已复用，也不擅自把目标降成静态占位。
