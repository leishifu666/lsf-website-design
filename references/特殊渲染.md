# 表现技术选择与特殊渲染

读取日期：2026-10-19。只写读过原文的内容；【归纳】= 本技能的总结。

## 0. 建模与素材制作不限于网页代码（用户2026-10-31补充）

先确定主体的造型、材质、镜头和叙事，再选择制作与呈现工具。可使用品牌已有模型、[Poly Haven等授权资产](氛围图片.md)、本机实际可用的Blender等建模工具，或下方img2threejs路线；不能因为擅长代码就只堆基础几何体。使用外部工具前检查它是否可用，不虚构已建模或已渲染的结果。

原创设计中，同一个三维主体可按目标选择透明静帧、分层图片、序列/视频或实时模型；选择须支持已确定的镜头、材质和交互。模式A沿用参考的实际呈现机制：参考是实时模型、深度位移或shader场景时，不能自行改为预渲染图加HTML/GSAP位移。Three.js是呈现工具之一，不是唯一的模型制作方式。不为本路线自动安装软件、开通付费服务或另起项目。

素材与网页须统一光源、透视、色彩、遮挡和动作；非代码产物同样进入现有assets-plan.json和375/768/1440实际检查，不追加整站评审阶段。位图生图不可用时记录待生成项，不自动换工具或图库；已有授权模型与材质仍可按真实场景需要复用。

### 0.1 所有模式：先选表现技术，再制作

用户2026-10-31明确要求：技术选择是各建站模式的实施判断，不能总是做成平面页面。新建、整页改版、重新生成在方向确定与实施前，先查已有组件、场景、依赖和素材，再为核心体验确定实际技术。把以下内容写进现有DESIGN.md的Overview/Components及相关组件规格，不另加报告或审批：

- **要表现什么**：主体、材质、空间关系或可操作行为；用户滚动、拖动、点击或等待时，具体发生什么变化，为什么属于当前主题。
- **用什么实现**：分开记录页面框架、渲染接口、场景/交互库、素材生产与资源格式、动效/进度驱动和转场合成。它们可组合，不把“用了React/GSAP”当作已经选定渲染方案，也不把canvas当成一种渲染机制。
- **为什么这样选**：依据参考代码或原创表现目标，说明所选技术承担的作用、现有能力和必要依赖。涉及版本/API时核对项目依赖与官方资料。普通可逆选型自行完成，不把技术选择抛给用户；与明确硬约束冲突时指出具体冲突，不能默默削弱目标。
- **怎样证明做成**：列出对应文件、资源、输入、关键中间状态和验收方式。技术名称、静态截图、导入一个库不算实现。展示型网站至少落实一处与主题有关、可实际播放或操作的核心场景；通用fade-up、按钮hover、整张背景图轻移不能单独满足此要求。功能型网站围绕真实操作与状态转换设计，不额外塞入无关三维展台。

| 模式 | 技术选择与实施要求 |
|---|---|
| 1 参考型 | 查清拟迁移的核心机制及证据，再用适合本产品的技术实现；只迁移原则不等于只迁移配色与排版。允许适配机制，须说明本项目如何真实实现。 |
| A 风格还原 | 按[公开代码取证与机制锁定](参考取证与组件规格.md#41-核心场景的渲染技术与公开源码取证)，沿用参考的核心渲染接口、场景库、资源形态、驱动与合成方式。原站用Three.js/WebGL模型、深度位移、shader或Rive，就实现相应机制，不能换成平面图近似。 |
| C 从零原创 | 甲/乙/丙各自说明核心场景及技术路线，技术不必为了凑差异而不同。预览展示代表性动态/交互；静态预览只能说明设计意图，选定后须把该技术路线实际做成。 |
| D 找参考 | 候选分析补充核心效果的技术证据与本项目采用方式；未知标未知，不给五站都强加全量源码审计。选中后的核心机制须在实施前补齐证据，并按模式B或A执行。 |
| 3 优化型 | 先检查现有渲染与动效，保留有效机制；整页改版对薄弱核心体验重新选型并落实。局部优化只处理受影响部分，不借选型重建无关模块。 |
| 4 反推提示词 | 在提示词中分清原站技术证据、必须沿用的机制、建议与未知，给出可执行的资源/驱动/合成规格；只有截图时不猜框架。此模式不自动写网站或声称动效已验收。 |

DOM/CSS可用于真实的布局重排、遮罩、空间层叠和操作反馈；Canvas 2D用于相应二维绘制；WebGL/WebGL2/WebGPU及场景库用于对应的材质、模型和着色器表现；媒体或交互图形按其实际驱动选择。按目标选一个主方案，必要时组合，不要求每页都上WebGL，也不能因熟悉HTML而一律省略核心动态体验。纯排版、静态交付等用户明确方向优先。

GSAP是编排与属性驱动工具，不代替渲染器、模型或材质系统；可驱动场景参数，但模式A不得用“统一GSAP”覆盖参考核心时间线/状态机。正常呈现与减少动态效果、能力不足时的备用呈现分别记录；备用静帧不能代替正常模式完成验收。公开代码无法取得或工具不足时，保留已知机制、说明具体缺口并继续独立部分，不能擅自改成平面替代再宣称还原完成。

沿用现有自查和独立主审核对“选型→真实实现→可见效果”，不新增评分维度、Agent轮次或脚本门禁；静态看起来接近但机制未实现时，相关实施要求仍未完成。

## 1. 什么时候值得用（先回答“会不会更有趣”）

用于在已定目标内选择具体方案，不能用本节推翻用户已选的动态、空间或参考还原方向。【归纳】判断三问：
1. 它如何形成与主题有关的视觉记忆、空间感、材质或操作手感？品牌氛围和趣味体验也可构成理由，不能只因不增加正文信息就取消。
2. 选哪种呈现最符合目标：真实图片、建模预渲染、视频或实时场景均可；不以“CSS能近似”为由牺牲已选造型与质感。静态背景可用普通图像而非每帧绘入canvas。https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas
3. 在当前设备与布局中是否实际成立？记录加载和绘制表现、保留可用的静帧与状态；工程优化按用户要求处理，不以LCP或实现成本另设美学门槛。

用户已明确选择三维叙事主体时，直接在该方向内实施；上述问题用于选择复杂度和性能方案，不以“CSS 也能画个近似物”为由擅自替换。一个共享渲染舞台可以跨多个章节复用，沿用整站一处重型渲染区域的约束，不是每章新建一个 renderer。

适合的位置【归纳】：首屏一处主视觉（产品 3D、材质、粒子组成的品牌图形）、作品集的图片 hover 变形（Codrops WebGL distortion，见 `交互动效.md` C 节）、数据可视化、可把玩的小装置（签名交互，整站最多 1 处）。不适合：正文背景、导航、任何高频操作。

## 2. 选哪种技术【归纳】

| 需求 | 用 | 备注 |
|---|---|---|
| 2D 粒子、线条、噪声纹理、简单图表 | Canvas 2D | 最轻；文字和 UI 仍用 DOM（MDN：canvas 里尽量不画文字） |
| 图片变形、全屏着色器、流体 | WebGL（OGL / 原生）或 Three.js 的 ShaderMaterial | 只要一个平面加着色器时，Three.js 偏重 |
| 3D 模型、灯光、相机、交互 | Three.js（React 项目用 @react-three/fiber） | 模型用 glTF，纹理考虑压缩格式 |
| 工具制作的场景或交互图形 | 按原资源选择Spline场景或Rive动画/状态机等 | 分清场景类型和运行时，不把交互图形都称为3D模型 |
| A 还原：参考站用了什么 | 沿用参考的核心库、渲染接口、资源及驱动机制 | 探针只提供线索；结合公开代码、资源和运行证据锁定，详见取证第4.1节 |

## 2.5 先生成参考图，再按图建立三维叙事主体

这是一条按需选用的设计与素材路线：**Codex 内置生图 → 参考图核对 → img2threejs 程序化重建 → Three.js 场景 → 滚动叙事**。需要原创小模型但只有文字设想时优先考虑；已有足够清楚的参考图就直接复用。只更新或讨论技能不执行这条流程。

### A. 先确定主体要讲什么

在现有分镜和 assets-plan.json 里记录：主体用途、轮廓/材质风格、会动的部件、各章节目标姿态、相机视角、移动端展示及性能目标。先查项目已有模型、组件和 three 依赖；不要另起重复的渲染系统。

### B. Codex 生图，准备建模参考

- 读取已安装的 `imagegen`，默认调用内置 `image_gen`。生成与网站调性一致的单一、完整、未被遮挡的主体；轮廓、结构与材质分区清楚，背景干净，避免强透视、复杂环境、运动模糊和无关文字。网页素材不套用封面主标题确认流程。
- 风格可写实或风格化，依据项目选择；不因要建模就擅自变成低多边形、卡通或只有几个粗糙几何体的拼接。
- 实际检查图片后复制到当前项目，保留原图和生成提示，不能仅引用工具缓存位置。若同时需要透明底静态素材，向工具明确请求透明背景并验证实际 alpha，不用棋盘格图片充当透明。
- 主视角不足以支持关键结构或动作时，基于同一个主体参考补充必要视角，保持比例与身份。生成的背面是概念设计补充，不是对原图不可见结构的实测；不要求每个简单物件都生成全套视图。

### C. 按图建模，交回真实可控的对象

- 读取 [`img2threejs`](../../img2threejs/SKILL.md)，把用途设为网页实时叙事主体，并交付实际参考图、识别特征、动作需求和性能目标。按其 intake、qualityContract、状态与逐阶段质量门槛推进，不凭记忆拼命令，不替换已通过的部分。
- 当前技能以代码构造几何与材质，交回可集成的 Three.js 模型工厂/组件、命名分组、部件枢轴及必要资源。网站可直接使用该源码；不默认要求神经网格服务、下载模型或先导出 GLB。
- 简单旋转、开合、抬起等动作可由部件层级与枢轴实现。真正需要肢体变形、蒙皮和动作片段时，再按基技能选择角色路径；静态模型不能只凭“有骨骼/片段文件”就称为已可播放。
- 按建模技能要求做参考对照和多角度渲染检查：主体轮廓、关键部件、前后侧结构、材质与枢轴都要成立。未达标继续修模型，不能只凭一张正面截图、扁平贴图或“代码能运行”验收。

### D. 接入滚动叙事

- 主 Agent 将模型接回原网站，由分镜进度驱动主体位置、朝向、部件姿态、相机或光照；统一坐标、缩放、接地和阴影，与网页图像、配色及文字层次一致。
- 分清确定性的滚动姿态与独立播放的动作。绑定连续滚动的部分可以由当前位置直接求值，支持倒滚、快速跨章和锚点直达；不要在每个滚动事件里反复启动动画或重新创建模型。
- 如使用 Three.js 动画片段，按项目版本核对 `AnimationMixer`：它支持指定时间采样；滚动定位与按 deltaTime 播放不能在同一段动作上互相抢控制，timeScale、动作激活与片段时长也须实测。[官方 AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)。
- 牛马主题的概念例：同一个小角色在早起、通勤、工作、午饭和下班章节改变姿态与道具；角色轮廓保持一致，动作服务情节。具体造型和镜头依项目确定，不把此例固定成所有网站的六章模板。

### E. 网页级验收与交接

沿用已有网站验收：375/768/1440 检查构图与遮挡；检查实际滚动、倒滚、跳转和动作中间状态；记录加载、绘制和资源开销。模型未就绪、WebGL 不可用或减少动态效果时，显示能表达故事的静态图/分镜，正文与核心操作仍可用。

assets-plan.json 记录参考图与提示、模型源码/资源路径、关键分组与分镜对应关系、建模状态/渲染证据及降级素材；技术参数以当前依赖和实测为准。建模技能的状态文件和质量证据保留在当前任务目录，不把它的展厅、调试面板或导出界面自动加入正式网站，也不新增整站审批阶段。

本节的流程分工来自已读取的 `imagegen` 与 `img2threejs` 入口，设计与联动方法为【归纳】。2026-10-19 核对了上述 AnimationMixer，以及 Three.js [响应式](https://threejs.org/manual/pages/responsive.html)、[按需渲染](https://threejs.org/manual/pages/rendering-on-demand.html)、[资源清理](https://threejs.org/manual/pages/cleanup.html)文档；这次仅更新技能，没有实际执行新的图片到模型转换或网站渲染验收。

## 3. 必须做到的实现规则（每条有出处）

**渲染循环**
- 不动的场景不要一直渲染：先渲染一次，只在模型或纹理加载完、相机或设置被用户改动、窗口尺寸变化时再渲染；开了阻尼要用 rAF 合并请求，避免重复申请帧。来源：three.js manual《Rendering on Demand》https://threejs.org/manual/pages/rendering-on-demand.html
- 动画用 `requestAnimationFrame`，不用 `setInterval`。来源：MDN Optimizing canvas。
- 离开视口时暂停循环（IntersectionObserver）。【归纳】

**尺寸与清晰度**
- 用 CSS 决定 canvas 显示尺寸，代码只在显示尺寸变化时调用 `renderer.setSize(width, height, false)`（第三个参数 false，不让 three.js 改 CSS 尺寸），同时更新相机宽高比。来源：three.js manual《Responsive Design》https://threejs.org/manual/pages/responsive.html
- 高 DPI：按 `devicePixelRatio` 放大绘图缓冲区；性能不够时画到更小的缓冲区再放大。来源：MDN WebGL best practices《Consider rendering to a smaller back buffer》《devicePixelRatio and high-dpi rendering》https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices ；MDN Optimizing canvas《Scaling for high resolution displays》。【归纳】上限建议 `Math.min(devicePixelRatio, 2)`，未实测。

**内存**
- three.js 不会自动释放 GPU 资源：几何体、材质、纹理、渲染目标都要显式 `dispose()`；材质释放不会连带释放纹理。来源：three.js manual《How to dispose of Objects》https://threejs.org/manual/pages/how-to-dispose-of-objects.html 、《Cleanup》https://threejs.org/manual/pages/cleanup.html
- 组件卸载（React/Vue 路由切换）时释放上面这些资源并停止循环。【归纳】
- 用完的 WebGL 上下文可用 `WEBGL_lose_context` 主动释放；离开页面时不需要专门做。来源：MDN WebGL best practices《Lose contexts eagerly》。

**性能**
- 减少 draw call（合批、纹理图集）；能在顶点着色器算的不放到片元着色器；3D 里会缩小显示的纹理用 mipmap。来源：MDN WebGL best practices 对应小节。
- 生产代码避免 `getError`、`getParameter`、`readPixels` 等同步阻塞调用。来源：同上《Avoid blocking API calls in production》。
- 不要假设本机的上限（纹理尺寸、采样器数量）在用户设备上也有；MDN 给出几乎所有设备都支持的下限，如 `MAX_TEXTURE_SIZE: 4096`。来源：同上《Understand system limits》。
- 2D：重复绘制的内容预渲染到离屏 canvas；坐标取整；变化频率不同的内容分层到多个 canvas；少用 `shadowBlur`。来源：MDN Optimizing canvas。

**可访问性与降级**【归纳，依据 `交互动效.md` A9】
- `prefers-reduced-motion: reduce` 时停掉自动动画，只保留静态首帧或用户触发的变化。
- canvas 只做装饰时加 `aria-hidden="true"`；承载信息时，页面上要有等价的文字或数据表。
- WebGL 不可用（创建上下文失败、`webglcontextlost`）时显示静态图，页面其他部分照常工作。
- 首屏 canvas 先放海报图占位并写死宽高比，脚本加载完再淡入，避免 CLS。

## 4. 验收

- 用现有运动取证和目标场景的 render/update 统计核验：仅滚动驱动的模型在状态停稳后应停止无效重复绘制；确有持续角色动作时，只在可见且需要播放期间运行，暂停/离场后停止。全站 rAF 可能由其他组件申请，不能单凭全站计数断言三维场景一直渲染；上下文与设计说明一致。
- Chrome DevTools MCP Performance 录 10 秒滚动：无长任务连续出现；内存曲线在来回切换路由后回落。【未验证：本次沙箱只验证了探针能记录上下文和 rAF，没有跑长时间性能录制】
- `npm run lhci`：LCP、CLS 仍达标。
- reduced-motion 截图（`npm run gate` 已包含）里主视觉是静态首帧，不是空白。
