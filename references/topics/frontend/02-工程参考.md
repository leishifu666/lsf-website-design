## D. Core Web Vitals（web.dev）
- LCP ≤ 2.5s；INP ≤ 200ms；CLS ≤ 0.1。按 75 分位统计，移动端和桌面端分开看，三项都达标才算通过。— https://web.dev/articles/vitals

## E. 前卫但稳妥的使用规则（硬规则）
1. 核心布局和配色只用广泛可用或新近可用的特性（容器查询、:has、subgrid、oklch、color-mix、clamp、嵌套）。
2. 有限支持的特性（滚动驱动动画、跨文档 VT、text-wrap:pretty、interpolate-size）只做渐进增强：用 `@supports (animation-timeline: view())` 包裹，不支持时内容默认可见、静态完整。
3. 所有非用户触发的动效写在 `@media (prefers-reduced-motion: no-preference)` 里；VT 在减少动态效果时跳过，或改成交叉淡入。
4. 同一页只安排一个编排好的动效时刻；用户操作触发的反馈动效不受此限。
5. 颜色先在 oklch 中定义 4–6 个令牌，变体用相对颜色或 color-mix 派生，再用 light-dark() 输出两套主题，最后核对对比度。
6. 流体字号与 OpenAI 规则冲突时，按场景取舍：营销和编辑类页面用 Utopia 的 clamp（保证 rem 下限，允许用户缩放）；工具类界面用固定档位字号。
7. 引入任何趋势前，先过 Smashing 五问；3D、WebGL 要守住 LCP ≤ 2.5s、CLS ≤ 0.1，并预留 aspect-ratio。
8. 交付前，对照 `反套路清单.md` 逐项排查。
