# 交互动效：状态与转场

[专题索引](../../交互动效.md) · [先读使用边界](00-使用边界.md)。命令与代码路径仍以技能根目录为基准。

## 状态切换必须有过渡（2026-10-19 补充）

AI 最常漏掉的是“中间那一段”：弹窗、面板、抽屉、下拉菜单直接 `display:none ↔ block`，tab 内容直接替换，滚动到某区块时背景色直接跳。用户看到的是闪一下，很生硬。

**规则**
1. 所有出现 / 消失的浮层（弹窗、抽屉、下拉、popover、toast、折叠内容）都要有进入和退出过渡；退出比进入快（见上文 A 节时长表）。
2. 背景色、主题色、区块底色的切换要有过渡（`transition: background-color`，或 View Transitions），不能一帧跳过去。
3. 内容替换（tab、轮播、筛选结果）至少做交叉淡入淡出；位置变化用布局动画（Motion `layout`，或 View Transitions）。
4. 例外：键盘触发的操作（Esc 关闭、快捷键）可以没有动画（A 节第 4 条）。`prefers-reduced-motion: reduce` 时改成短淡入淡出或直接切换。

**写法**
- `display: none` 的元素默认不触发过渡。要做进入动画，用 `@starting-style` 写初始值；要做退出动画，给 `display` 和 `overlay` 加 `transition-behavior: allow-discrete`（简写里写 `display .2s allow-discrete`）。适用于 `<dialog>`、`popover`、`display:none` 切换和刚插入 DOM 的元素。Baseline 2024。来源：MDN @starting-style https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@starting-style
```css
.panel { opacity: 0; translate: 0 8px; transition: opacity .2s ease-out, translate .2s ease-out, display .2s allow-discrete, overlay .2s allow-discrete; }
.panel[open], .panel:popover-open { opacity: 1; translate: 0 0; }
@starting-style { .panel[open], .panel:popover-open { opacity: 0; translate: 0 8px; } }
```
- React 条件渲染（`{open && <Panel/>}`）卸载时没有退出动画：用 Motion 的 `AnimatePresence`，或保持挂载、用上面的 CSS 切换。
- 背景 / 主题切换：`html { transition: background-color .4s ease; }`，或 `document.startViewTransition(() => 切换主题)`。

**检查**：`node scripts/check-transitions.mjs <地址>`。逐个点击带 `aria-expanded / aria-controls / popovertarget / role=tab / summary` 等的触发器，点击后 40ms 看有没有正在运行的过渡或动画，600ms 后看哪些元素出现、消失、换了底色；有变化但没有动画就报“瞬间切换”。再用指针（点空白处）关闭，查退出。另外按真实滚轮滚动整页，查 html/body 底色硬切。
- 先空等 640ms 记下页面自己会变的区域（自动播放的演示、轮播），排除掉，避免误报。
- 实测（2026-10-19）：测试页上 `display` 直接切换的弹窗被报出，`@starting-style` 的 `<dialog>` 和 opacity 过渡的面板通过，滚动时 JS 直接改 body 底色被报出、加 `transition` 后通过。linear.app 上测到导航菜单打开有过渡、点外部关闭时浮层直接移除（参考站本身就是这样，A 还原时照参考站做，并在规格里写明）。
- 用在参考站上：`transitions.json` 记下每个状态切换实际的时长、缓动和动画属性，抄进 `reference-spec.json` 的 `motion`。
- 这是启发式检查：报错后看 `shots/` 截图复核，确认是页面本身的问题再改。


## 导航栏、开场、页面切换、趣味交互（2026-10-19 补充）

先看参考站和获奖站怎么做，再做自己的：`extract-motion.mjs` 的 `navOnScroll` 字段会报出导航随滚动的变化（向下隐藏 / 向上出现、变矮、换底色、出现模糊或阴影），`animations` 里能看到开场动画的名字和时长。

### 导航栏随滚动
| 模式 | 什么时候用【归纳】 | 写法 |
|---|---|---|
| 向下滚隐藏、向上滚出现（hide on scroll / “hidey bar”） | 长页面、内容为主 | 新写法：`html { container-type: scroll-state }`，`@container scroll-state(scrolled: bottom) { header { translate: 0 -100% } }`，再加 `transition: translate .25s`。Chrome 144 起支持，不支持的浏览器只是不隐藏，属于渐进增强。来源：Chrome 144 beta 博客 https://developer.chrome.com/blog/chrome-144-beta ；Bram.us https://www.bram.us/2025/10/22/solved-by-css-scroll-state-queries-hide-a-header-when-scrolling-down-show-it-again-when-scrolling-up/ 。导航里有焦点时不要隐藏：`header:not(:focus-within)`（同一篇）。要全浏览器一致就用 JS 比较 scrollY 方向切 class。 |
| 透明 → 实底 / 毛玻璃 | 首屏是满版大图 | 粘性导航 + `@container scroll-state(stuck: top)` 改底色，Chrome 133 起。来源：https://developer.chrome.com/blog/css-scroll-state-queries |
| 变矮、logo 缩小 | 品牌感强的首页 | 滚动驱动动画 `animation-timeline: scroll()` 绑定高度/缩放，或同上 stuck 查询 |
| 阅读进度条 | 文章页 | `animation-timeline: scroll()` 驱动 `scale-x` |

### 开场加载动画（intro / preloader）【归纳】
- 只在资源确实重（WebGL、大视频）或品牌需要一个开场时做；纯静态页不做。
- 总时长 ≤ 1.5～2 秒，可点击跳过；同一会话第二次访问不再播放（`sessionStorage` 记一下）。
- 不能挡住 LCP：首屏真实内容照常渲染，开场层盖在上面淡出；不要把内容藏到动画结束才插入 DOM。
- 实例：Shopify Editions 冬季 ’26 页（2026-10-19 用本技能脚本实测）开场有 `load-lines`（6s，SVG 线条描绘）和导航项依次进入的 `nav-item-in`（1s，cubic-bezier(0.13,0.46,0.15,0.92)）、列表 `stagger-fade-in`（0.6s）。

### 页面切换
- 多页站：`@view-transition { navigation: auto; }` 开启跨文档视图过渡，给要“延续”的元素（标题、主图）设同一个 `view-transition-name`。单页应用：`document.startViewTransition()`。都要在 `prefers-reduced-motion` 下关掉或改成淡入淡出。前后两页必须同源；`navigation: auto` 只在同源、没有跨源重定向、由用户点击页面内容触发（不是浏览器按钮）的前进、替换和前进后退导航时生效。来源：MDN @view-transition https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@view-transition
- 动画方向要有意义：进入详情从卡片位置放大，返回时缩回去。【归纳】

### 趣味交互：Shopify Editions 那种叫什么
那种做法没有唯一的名字，常见叫法【归纳】：
- **产品界面拼贴 / 浮动卡片（floating UI cards）**：把真实的产品界面切成小卡片（订单状态 “Paid”、销售额、图表），和实物抠图（滑板、轮子）叠在一起，前后错开，远处的卡片加模糊做**景深**，看起来像一张立体的桌面。
- **滚动叙事（scrollytelling）**：随着滚动，卡片和物件按顺序进场、移动、换内容。
- **彩蛋（easter eggs）**：藏在页面里、可以点或拖的小东西。Shopify 这一期的播客提到页面里藏了可交互的彩蛋（如 Slack 表情、标价离谱的帽子）。来源：Liquid Weekly 第 56 期节目介绍 https://liquidweekly.com/blogs/podcast/episode-56-the-renaissance-edition
- 这个页面拿了 2026 One Show 互动类网站奖项。来源：One Club 页面 https://www.oneclub.org/awards/theoneshow/-award/64482/the-renaissance-edition

用本技能脚本实测 Shopify Editions 冬季 ’26（https://www.shopify.com/editions/winter2026 ，2026-10-19，1440px）：
- 160 个图片 / 视频 / 背景，其中 105 个是带透明通道的 AVIF / WebP（抠图物件和界面卡片），9 个平铺纹理背景。说明那种“摆满真实物件”的效果，是大量透明素材叠出来的，不是一整张图。
- three.js r181（WebGL2）、Lenis 平滑滚动（60ms 位移 200、960ms 位移 400）、Rive 动画；滚动时每屏有 30～60 个元素在变。
- 做法拆成三层【归纳】：底层纹理或渐变背景 → 中层透明物件和 UI 卡片（`position: absolute`，按滚动进度位移、轻微旋转，远处的加 `filter: blur()` 和更低的不透明度）→ 上层文字。素材用 `process-image.mjs` 出透明图，卡片用真实组件渲染（不是截图），这样能动、能点。
- 不要照搬他们的 three.js 场景：先按 `特殊渲染.md` 第 1 节三问，CSS + 透明图能做到的不上 WebGL。
