# 六层拆解法

由表及里拆，但写报告时由里及表读（先目标，后像素）。每层都必须回答两件事：**是什么**（可观察、可测量的事实）和**为什么**（它服务哪个目标、利用了哪条认知规律）。“为什么”要能指回 `设计原则库.md`（同目录） 里的某一条，或者指回第 1 层的目标。

取证顺序：先跑 `../scripts/capture.mjs` 截 375 / 768 / 1440 全页图 → 跑 `../scripts/extract-tokens.mjs` 拿实测字体、颜色、字号、间距 → 再开始写。无障碍扫描和Lighthouse仅按用户要求另作工程检查，不是设计取证前置门槛。工具细节见 `工具清单.md`（同目录）。

---

## 第1层 目标层

问题清单：
- [ ] 网站为谁？（具体到情境：谁、在什么时候、带着什么问题来）
- [ ] 解决什么？用户离开时应该得到什么？
- [ ] 核心转化动作是什么？（只认一个主动作；次要动作列出来）
- [ ] 首屏和全页有几个按钮/链接指向主动作？
- [ ] 网站在说服谁“相信”什么？（证据类型：数据、客户、演示、价格、口碑）

怎么判断“为什么”：看主动作出现的位置和次数、首屏文案说的是“我是谁”还是“你能得到什么”。

## 第2层 信息架构层

问题清单：
- [ ] 主导航有几项？命名用的是用户的词还是内部术语？（NN/g 启发式 #2）
- [ ] 页面区块顺序（逐块写一句话目的）
- [ ] 内容优先级：哪些在首屏、哪些在折叠后、哪些只在子页
- [ ] 信息按什么组织：功能模块 / 用户任务 / 时间 / 人群 / 问题
- [ ] 有没有“分块”（chunking）：长内容是否被切成有意义的组
- [ ] 结尾怎么收：最后一屏让用户做什么（峰终定律）

## 第3层 布局层

问题清单：
- [ ] 网格：列数、最大内容宽度、侧边距（DevTools Grid 叠加层可直接看）
- [ ] 留白：区块之间间距是否成体系（提取脚本统计出现频率最高的 margin/padding/gap 值）
- [ ] 视觉动线：第一眼 → 第二眼 → 第三眼落在哪（看 1440 截图，眯眼看哪块最重）
- [ ] 首屏策略：放的是产品本身、口号、人物、数据还是工具？
- [ ] 移动端是重排还是简单缩放？哪些内容在 375 宽度被隐藏或降级？
- [ ] 分组靠什么实现：靠留白（接近律）、靠底色（共同区域）、还是靠边框？

## 第4层 视觉层

问题清单：
- [ ] 字体：家族、字号阶梯（实测）、字重数量、行高
- [ ] 配色：主色、中性色阶数量、强调色用在哪里（CSS Overview 的 Colors 区）
- [ ] 层级靠什么建立：字号 / 字重 / 颜色深浅（Refactoring UI：不要只靠字号）
- [ ] 图像风格：真实产品截图 / 摄影 / 插画 / 3D / 无图
- [ ] 品牌感来自哪里：哪 1～2 个元素拿掉后就“不像它了”
- [ ] 对比度：正文与背景是否达到 WCAG AA（axe / DevTools 会标出低对比文字）

## 第5层 交互层

问题清单：
- [ ] 反馈：点击、悬停、提交后多久有反应（目标 < 400ms，Doherty 阈值）
- [ ] 动效：哪些元素在动、动效是在表达层级/状态，还是装饰
- [ ] 状态：hover / focus / active / disabled / loading / empty / error 是否都有
- [ ] 微交互：有没有一个“可玩”的小交互承担说服任务
- [ ] 键盘可达性：Tab 顺序、焦点可见
- [ ] `prefers-reduced-motion` 下是否降级（DevTools Rendering 面板可模拟）

## 第6层 原则层

从 1～5 层推导 5～10 条可复用原则。每条用下面的四栏模板：

| 原则 | 网站里的证据 | 为什么有效 | 怎么迁移到我的项目 |
|---|---|---|---|
| 可执行的判断句 | 具体到区块、元素、实测值 | 指回目标层或设计原则库中的出处 | 改写成用户项目自己的内容 |

写原则的检查：
- [ ] 是判断句，能拿来对一个设计说“符合/不符合”
- [ ] 遮掉参考站名字后仍成立
- [ ] “迁移”栏没有出现“像 X 一样”
- [ ] 至少 1 条来自目标/信息架构层，至少 1 条来自交互层（避免全是视觉原则）
- [ ] 标出哪些原则是“推断”（没有实测证据的）
