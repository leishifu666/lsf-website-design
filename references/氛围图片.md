# 氛围图片：来源、生成、处理与上线规则（2026-10-19 核对）

图片的作用：给页面加氛围和质感，让主视觉成立。不是填满空白。每张图都要回答“它替页面讲了什么”，答不出就删。

## 当前生图要求（用户2026-11-02）

网页需要新制作的图片时，必须实际调用Codex内置生图工具，用户指定名称为GPT Image 2.5。工具没有model字段时不编造参数、不自称已锁定后台版本；记录实际工具、提示词、回执和落地路径。用户自有素材继续优先复用，真实UI与模型交互仍按真实机制实现。

透明单体明确设置`transparent_background: true`，生成后核验alpha与浅/深背景边缘，不能用白底/棋盘格冒充透明。每一条生成、编辑、重生成和变体提示词都原样以“画面干净通透，材质完整自然，纹理平滑统一，主体清晰，避免过度锐化、色斑、噪点、碎纹、崩坏和畸变。”结束。结构化参数放在提示词外，不在句后追加文字。

本技能默认不切换Midjourney、Nano Banana、图库或外部API。旧的其他渠道说明只在用户之后明确改选时适用；本次每条提示词固定结尾的要求覆盖历史Midjourney例外。内置工具失败时保留证据并继续独立工作，说明待生成素材；只有用户明确接受替代路线才改走其他方式。只更新技能/分析/反推提示词不为了执行规则而实际生图。

## 素材优先于工具惯性（用户2026-10-31补充）

展示型网站的新建与整页改版，主动规划并实际使用适合主题的照片、透明底物件、插画、产品渲染或模型素材。不把全页文字卡片、CSS渐变、Canvas平面图形或几个Three.js基础几何体当作默认成品。图片和建模是核心设计材料，代码负责布局、真实UI、状态和运动；素材不能只出现在计划或提示词里却没有落地。

根据记忆点选择“拍摄/品牌原图、生成、图库、建模或模型复用、预渲染”的组合。每张图、模型或视频有明确的区块用途和构图角色，统一镜头、透视、色温、材质、光线与阴影。透明前景和主体可与排版穿插，并由GSAP驱动；背景有环境和留白，不遮住主要内容。用户明确要求纯排版或保持现有视觉体系时以该方向为准，不按数量硬塞图片或三维。

### 接入页面后的检查

先看主视觉和代表性内容区是否真正有主题、材质与空间关系，再检查浅/深底透明边缘、文字遮挡、移动端裁切及实际动效。真实UI和文字保持可操作、可选择。增加素材不等于增加评审轮次；同次自查和评审记录其与页面的融合，素材未加载或仅有占位不能当作完成。

## 按参考网站规划生图与透明底单体（用户2026-10-19补充）

- 主动判断参考设计中哪些人物、产品、道具、雕塑、装饰与前景物件适合用内置生图制作；不能因为少调用工具，就把它们全部替换成完整背景图、占位图或粗糙代码拼图。数量由页面和主题决定，不硬凑生图数量。
- 对需要与标题穿插、跨区块、叠放、独立移动/旋转或形成前中后景的物件，优先规划独立透明底素材；一张图聚焦一个主体或不可拆的有意义组合。完整背景、环境与氛围图按参考需要保留，不把全部图强行透明。
- 先区分背景层、主体层、前景道具层、阴影/光效层与真实UI；文字和可交互控件使用HTML/真实组件，不把整张网页烘焙成图片。原站是一张合成图时，建议拆层必须标【建议】，不能假称原站已有透明层。
- 先统一画风、透视、镜头尺度、光源方向、色温、材质和主体比例。每项记录用途/区块、主体、透明与否、画幅/留白、锚点、遮挡和层级、桌面/移动布局、GSAP运动方式、来源或生成方式；能分离的物件不全部画进同一个固定背景里。
- 用Codex内置image_gen，并读取实际已安装imagegen技能；工具后台型号未暴露时不猜型号。透明素材明确设置 transparent_background: true，提示词说明真实alpha、完整主体、干净边缘、无背景/地面/相框/棋盘格；需要背景时设false并描述环境。不能只写“PNG”或“透明”却遗漏工具参数。
- 逐张检查主体、边缘和实际透明像素；白底/黑底/绘制棋盘格都不是真透明，只有alpha通道但像素全不透明也不合格。导出和落入项目保留alpha；在浅色与深色底上检查白边、黑边、残留色、裁断和透明材质。检查脚本只是辅助，不把有通道等同于合格素材。
- 每张图、每个变体、每次重生成/编辑的完整提示词都必须以以下中文句子原样结束。透明、构图、光线等要求放在此前；句子后不再接参数、英文翻译或补充指令。该要求以2026-11-02指令为准：

> 画面干净通透，材质完整自然，纹理平滑统一，主体清晰，避免过度锐化、色斑、噪点、碎纹、崩坏和畸变。

- 模式F只生成完整素材计划及逐项可直接使用的生图提示词，按【建议】标明尚未生图。用户要求实际制作网站或明确生图时才实际调用、检查并保存到项目，不将计划写成已生成/已落地。

## 1. 来源优先级
1. 品牌自己的真实照片（产品、人、场地）。永远第一位。
2. 当前环境可用的生图/建模与渲染能力：Codex优先内置生图（适合透明底素材），其他已授权工具按实际能力使用，不自动开通付费服务。
3. 免费/开放授权图库与模型库只在用户明确接受替代路线或确需授权模型/材质时使用，不因生图失败自动切换。
4. **网上别人的图（含别人生成的 Midjourney 图）：本地可用作示例图，不能上线。**
   - 用途：开发阶段放进页面当占位示例，让用户直接在真实版式里判断“这种类型和风格的图适不适合这个网站”。
   - 存放：统一放 `public/_samples/`，文件名加前缀 `sample-`，并在 `public/_samples/SOURCES.md` 记下每张图的来源链接。
   - 页面上给示例图加角标“示例图，上线前替换”（只在开发环境显示）。
   - 上线前必须全部替换成自己生成或有授权的图。`npm run gate` 会检查：构建产物里出现 `_samples/` 或 `sample-` 文件就判失败。
   - 原因：Midjourney 服务条款（2026-05-27 版）写明资产归生成者所有，社区准则要求未经许可不得分发或公开转发他人的作品。来源：https://docs.midjourney.com/hc/en-us/articles/32083055291277-Terms-of-Service
   - 用户确认风格后，把示例图的构图、光线、色调提炼成提示词，调用Codex内置生图重新生成；不自动切换Midjourney。
   - 年收入超过 100 万美元的公司或其员工，需订阅 Pro 或 Mega 才拥有所生成资产（同上条款）。

## 2. Codex内置生图与透明底
- 在Codex且工具可用时，默认使用已安装imagegen技能和内置image_gen工具。工具说明提供 transparent_background 字段，透明素材必须显式设true；完整环境图按用途设false。不从旧型号名、API能力或历史问题推测当前内置工具的后台版本；其他环境或能力缺失时按上表获取素材。
- 只更新技能/反推提示词时规划素材；实际网站制作需要原创位图时积极使用内置生图，不自动换外部账号、CLI或付费API。
- 需要图像编辑/去背景时仍用内置生图编辑；本地图先用view_image查看，保留所需主体与已有透明度。
- 导入项目后辅助运行check-alpha.mjs检查PNG，同时查看主体和真实透明像素；该脚本的部分格式分支只检查通道，不代表边缘、主体和透明度已全面合格。其他格式用可用的图像读取工具核验，不凭扩展名判断。

```
画面干净通透，材质完整自然，纹理平滑统一，主体清晰，避免过度锐化、色斑、噪点、碎纹、崩坏和畸变。
```

参考画风、构图、透明底、光线、材质和尺寸等要求先写在前文。这里的质量约束不表示默认把参考的油画、纸张或有意纹理磨成塑料；参考风格照实描述，避免不受控的碎纹与畸变。需要工具参数时放在相应结构化字段，不附在固定结尾之后。

## 2.6 素材处理：生成的图不能整张丢进页面
先根据用途决定透明单体、环境背景或卡片配图，再生成与构图。不能默认每张都画完整背景，再用CSS伪装成分层素材：

| 用途 | 需要的素材 | 怎么得到 |
|---|---|---|
| 主体压住标题、跨出区块、和文字穿插 | 透明底抠图（PNG / WebP 带 alpha） | 见下方三种方法 |
| 满版背景 / 主视觉 | 不透明大图，留出放文字的暗区或空区 | 生成时在提示词里写清留白位置；页面上加渐变遮罩保证文字对比度 |
| 卡片配图 | 统一比例裁切 | `object-fit: cover` + `object-position` 指到主体 |
| 质感统一 | 纹理 / 颗粒叠加层 | 小尺寸平铺纹理 + `mix-blend-mode` |

**透明素材的默认获取方式**
1. 原生生成：image_gen设置transparent_background: true，并描述完整主体与干净透明边缘；固定质量句放在提示词最后。
2. 已有图片去背景：先查看原图，再使用image_gen编辑请求真正透明背景。保留主体和所需半透明材质，不用生成白底/黑底代替透明结果。
3. 保存/转换：保留alpha，项目素材落入原项目，另存版本避免覆盖。只有用户明确要求脚本抠图等其他处理方式时再采用，不静默改走旧黑白配对或色键流程。

**放进页面时的处理【归纳】**
- 透明主体：写死宽高或 `aspect-ratio`；用 `filter: drop-shadow()` 做贴合形状的阴影（`box-shadow` 只会给矩形）；需要穿插时主体放在标题上层，标题的一部分被主体压住。
- 满版图：`object-fit: cover`，`object-position` 指到主体；文字区加渐变遮罩；移动端换构图（`<picture>` 给不同裁切），不要直接缩小。
- 多张图：统一色温、颗粒、阴影方向；必要时用同一层颗粒纹理叠在最上面。

## 2.7 参考原站的图片是怎么处理的
和组件、动效一样，图片处理方式也先看参考站：
`node scripts/extract-media.mjs <参考站> ref/media 1440`
输出每张图 / 视频 / 背景图的：格式和是否带透明通道（读文件头判断）、显示尺寸、裁切方式、圆角 / 遮罩 / 裁形、混合模式 / 滤镜、上面有没有叠加层、是否压住文字、是否跨出所在区块、是否是平铺纹理，并归类成“透明抠图主体 / 满版背景 / 卡片配图 / 矢量图形 / 纹理叠加”，配截图。
实测 apple.com/airpods-pro（2026-10-19）：80 个图片 / 视频 / 背景里，34 个是带透明通道的 PNG 抠图主体，20 个满版主视觉（多为 jpeg 或视频，`object-fit: cover` 或 `contain`），大量主视觉压住文字。这类站的产品图都是抠好的透明素材，不是整张矩形照片。
模式A：图片的处理方式（透明主体、遮罩、穿插、混合模式）写进 `reference-spec.json`，图片本身换成自己的。

## 3. 让图不像 AI 图
- 先定“一套图的规则”再生成：同一光源方向、同一色温、同一颗粒度、同一镜头语言（焦段、景深）。多张图风格不统一是最明显的 AI 味。
- 色调从页面色彩令牌来（把 oklch 主色写进提示词），图和页面是一套东西。
- 避开 AI 图常见问题：过度光滑的皮肤和塑料质感、对称居中构图、紫蓝渐变光、手指与文字错误、无意义的发光粒子。
- 透明底主体图配合排版穿插（主体压住标题一角、跨越区块边界），比方框里摆照片更有设计感。
- 加一层轻微颗粒或纸张纹理（CSS 叠加），可以把不同来源的图统一质感。

## 4. 上线规则
- 格式：照片用 AVIF / WebP，透明素材用 WebP 或 PNG；提供 `srcset` 和 `sizes`。
- 首屏主图 `fetchpriority="high"`，其余 `loading="lazy"`；写明宽高或 `aspect-ratio`，防止 CLS。
- 装饰性氛围图 `alt=""`；有信息的图写实际内容。
- 文字压在图上时，正文对比度仍需 ≥ 4.5:1（加遮罩或选图时就留出暗区）。
- 当前阶段图片与分层数量按视觉设计需要确定，不以LCP或性能指标设美学门槛，也不据此减少生图、透明物件或动画。工程优化在用户要求时另行处理。
