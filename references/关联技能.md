# 内置方法交接、Gemini委派与三维主体

本文件只说明交接方式。主任务范围由用户请求、适用的 AGENTS.md 与 `lsf-website-design` 决定；被关联技能不另行扩大范围。

## 已安装入口

- 参考取证：本技能内置[参考取证与组件规格](参考取证与组件规格.md)及[组件模板](../templates/组件还原规格模板.md)，不需另装克隆类技能。
- Gemini 委派：[`lsf-ai-agent`](../../lsf-ai-agent/SKILL.md)。它是通过用户中转、浏览器或 API 协作的外部模型技能，不是 Codex 内置 `spawn_agent` 的 Gemini 型号。
- 生图：已安装的 `imagegen`，从宿主技能目录定位；默认使用 Codex 内置 `image_gen`，不自行改走付费 CLI/API。
- 按图建模：[`img2threejs`](../../img2threejs/SKILL.md)。依据参考图进行程序化 Three.js 重建，保留模型源码、分组、状态和渲染证据，不是一个自动网格生成 API。

只在需要对应能力时读取入口；不用整套加载，不复制另一技能的脚本、密钥或浏览器状态。相对链接用于同级安装目录；位置变化时按当前技能目录查找准确名称。

## 内置参考取证的交接

适用：模式A、明确的网页复刻，以及复杂交互的取证。

1. 沿用URL、用户主题、页面/区块范围和375/768/1440视口，按[内置方法](参考取证与组件规格.md)取得页面地图、驱动模型、状态覆盖、素材层和组件实施合同；已有证据直接复用。
2. 锁定值归入reference-spec.json并生成令牌，DESIGN.md概述设计语言；组件合同引用令牌和证据，不重复建立矛盾规格。未知项标清，冲突回到实测核对。
3. 内容和素材按目标主题与授权适配。用户允许模式A多个构建Agent，按内置分工稳定共享基础、划分文件所有权后在原目录并行；主Agent统一装配，不创建worktree或自动提交，不固定框架。
4. 将实际可消费的组件/状态摘要和同条件参考证据交给现有自查与评审。实现并行不增加最多两次成品设计评审；外部模型、文案和仅提示词任务仍按各自授权执行。

## 与 Gemini 技能衔接

适用：本机用户已保存的网站制作 Gemini 文案偏好（见 workflow-defaults.json），或用户另行委派的前端、设计等任务。新对话按网站 skill 制作时不要求再出现“Gemini”才调用；只分析、更新技能不触发。该专项偏好不等于委派整站前端给 Gemini。

| 任务 | Gemini task | 最小交接材料 |
|---|---|---|
| 页面／组件实现、CSS、响应式、交互、视觉修正 | `frontend` | 已确认主题与事实、原项目相关源码、锁定规格和令牌、实际截图、修改文件边界与验收项 |
| 视觉方向、布局与设计审查 | `design` | 目标卡、同视口参考与当前截图、组件规格、需要解决的具体问题 |
| 页面文案、标题、UX 文字或改写 | `copywriting` | 有独立用途的 blocks 及 purpose、facts、voice、保留项与输出格式；固定原文留在本地审核，空槽不索要候选 |

- **入口和型号只有一个来源**：读取 `lsf-ai-agent/SKILL.md`，沿用其当前模型分工与已选入口；Codex 子 Agent 使用用户指定的极高（xhigh），外部产品按本次明确选择，不在本技能另存易过期的型号或伪造可调用 API。
- **沿用当前专项偏好和会话选择**：用户于2026-10-31更正，网站文案默认 **Google AI Studio**，按 `lsf-ai-agent` 的 AI Studio 浏览器流程操作。此前贞贞 API 偏好已被替代，不能凭历史记录继续调用；只有用户之后明确指定时才启用 API，浏览器失败不自动换 API。用户明确选择中转时沿用中转；仅准备材料或更新技能时不执行 `doctor`、登录或发送请求。
- **交接只带必要材料**：参考链接加可访问材料，UI 任务提供实际截图及相关源码，不只发 localhost、本机路径或整仓；不发送凭据与无关聊天。
- **用户中转**：提示词直接在聊天代码块中给出；必要附件集中到一个文件夹，默认不压缩。主 Agent 等用户回传，不自动改走网页或 API。
- **直接调用**：只执行关联技能已有的浏览器或 API 流程；失败时遵循其有界重试与型号核验，不自行降级或换入口。
- **回收**：候选或补丁回到原始项目，核对业务事实、文件边界与完整性，实际落地后再运行本地检查。AI Studio候选沿用 `copy/gemini/*.json`，记录 `by: "gemini"`、`via: "aistudio"`、实际页面URL、界面回读型号、提交/回收时间、原始回答与 `candidates`；不伪造API回执或 `provider_reported` 身份。模型说“已修改／已测试”不能替代证据。
- **文案审核**：Gemini 候选由主 Agent 统一获取；独立审核员只复核已回收材料，不递归外发。本机网站制作已要求独立文案审核，必须收回实际审核结果；不能自检替代，也不递归外发。
- **失败与等待**：继续取证、素材整理和其他不依赖回传的工作；用户已指定 Gemini 的定稿不自动改由 Codex 生成，不把未收到候选记为已完成。

## 生图 → 按图建模 → 三维叙事主体

适用：本次网站已选择原创三维主体，或用户要求先设计主体形象、再变成可操控模型。完整操作见 [特殊渲染 §2.5](特殊渲染.md#25-先生成参考图再按图建立三维叙事主体)。

1. 主 Agent 明确主体在分镜里的用途、风格、动作与设备条件；已有图片足够时复用。只有文字设想时由 Codex 内置生图工具生成建模参考，不因没有用户上传图而中断已获授权的概念创作。
2. 交给 img2threejs：实际可读的参考图、主体识别特征、用途、分镜动作、页面风格与性能目标。先读其入口并按当前状态和质量契约分阶段建模，不复制或编造其脚本命令，不跳过已有质量门槛。
3. 回收：模型工厂/组件源码、可动部件与枢轴、规格和必要状态、实际多角度渲染、资源和降级图。仅需网站内运行时直接集成 Three.js 模型，不把导出 GLB 当作固定前置条件。
4. 网站侧绑定进度、相机、灯光和部件动作，并完成真实滚动与响应式验收。建模技能的预览、拆解能力可用于内部验证，不把其展厅、导出或调试面板自动加到用户网页。
5. 如确需骨骼、蒙皮或角色动作，再依 img2threejs 的当前入口显式选择角色路径；不能因主体是牛、马或人物就默认启动全部角色插件。缺依赖或模型不合格时保留实际阻碍，不用一张平面图冒充已完成的三维模型。

这条路线不改变现有 Gemini 文案与独立评审要求，不自动委派额外代理，也不因更新本技能就执行生图、建模或安装。

## 典型走法

- 「只分析这个网站」：用内置取证方法拆解指定页面及复杂状态；不实现、不自动调用Gemini。
- 「按这个网站风格做一个新主题」：模式A → 五站轻量调研与主参考深入取证 → 状态/素材规格和全局基础 → Gemini文案与独立审核 → 原项目组件实现（可多Agent） → 同条件自查 → 现有独立评审与最终检查。
- 「让Gemini按这个风格写页面／文案」：网站设计确定目标与事实 → 内置取证 → Gemini沿用已选入口 → 主Agent落地与验收。
- 「先画一个小模型，再让它随滚动讲故事」：分镜目标 → 内置生图参考 → img2threejs 按图重建 → 多角度验收 → Three.js 模型与章节进度联动 → 网站级验收。
- 「更新网站设计技能或内置参考方法」：只更新本次相关技能文件，不开网站制作或外部模型任务。


## 视觉评审专项路由（2026-11-02）

默认优先按lsf-ai-agent的design路线使用可用Gemini或用户已选Claude；没有可用Gemini/Claude才用继承当前模型的独立子Agent，详见[外部视觉评审](外部视觉评审.md)。该授权仅包括必要评审材料，不授权整站开发外发。网页生图继续强制Codex内置image_gen，不被lsf-ai-agent的其他生图默认渠道覆盖。首次安装依赖引导只按[首次安装与依赖](首次安装与依赖.md)触发。
