# A 模式 · 原站侦察与回放

[当前实际制作提示词](../templates/风格参考统一提示词.md)用于直接制作和预览。本页是该提示词的执行办法。以用户的主参考为准；站内侦察范围可以大于本次要制作的页面。给长沙换题材，不会自动放弃对原站主角、排版、输入和转场的核对。

## 第一次进站

在用户原项目中准备好网站目录，执行下面的命令。`<技能>` 指本次实际选中的 lsf-website-design 目录。命令会登记项目，并真的打开浏览器。保留现有工作；重复执行会读取已有侦察和手工台账。

```text
node <技能>/scripts/start-reference.mjs <参考URL> --root <原项目> --site <网站目录>
```

会得到网站目录下的 `ref/scout/topology.json`、独立运行的截图/DOM/资源记录，以及 `ref/source-survey.json` 草稿。拓扑是发现线索；草稿初始状态为“未检查”。先目视首屏是否真的加载，打开实际目录、代表内章与详情，继续查不同模板、所有不同的转场及返回路径。对被遮挡或超时的操作，保留先前成功的记录，换真实入口、浏览器或显示模式重试。检查本机 headless 和有界面浏览器的渲染路径，特别留意静态 fallback。若浏览器访问受限，按该阶段已经掌握的事实交付侦察缺口，不能将未看见的页面打包为已完成的网站。

补采某页面或区块时从网站目录执行，以下选择器和下一页 URL 换成原站实际值。

```text
node <技能>/scripts/scout-reference.mjs <内页URL> ref/scout --source <参考URL> --width 1440 --selector ".chapter" --all-styles --label chapter
node <技能>/scripts/scout-reference.mjs <参考URL> ref/scout --width 375 --actions ref/steps.json --label phone
```

每次采集独立存档。同一原站的条目在总清单中汇合；覆盖表把每个站内去向裁为纳入、同模板、范围外或受阻，再关联区块。类别与具体状态从实际操作得出。导航、页脚、卡片、锚点、弹层和返回都要查看。查到链接与打开它分开记录。范围内的无穷列表、登录分支或特殊设备写明边界；需要用户决定的只询问影响范围的一点，同时继续其他明确部分。

## 同一输入看两侧

为六类行为各做检查。每种有区别的行为取一个 ID。相同模板可复用一条操作计划，保留各实例及不同响应。固定 CSS 视口、DPR、缩放、指针类型、滚动起点、加载条件与减少动画偏好。原站和目标站可各自映射选择器。每侧用独立输出目录，复测不覆盖旧证据。

```text
node <技能>/scripts/replay-behavior.mjs ref/plan.json reference ref/replay/source-01
node <技能>/scripts/replay-behavior.mjs ref/plan.json implementation ref/replay/built-01
```

计划字段和各动作见[动态输入回放](动态输入回放.md)及[可编辑示例](../templates/behavior-replay.example.json)。点击章节、返回列表与直接访问是三种不同实验。打开菜单要同时观察按钮、面板、遮罩与页面滚动锁。鼠标离开到再次进入应发生在上一段动画结束前。缓动取帧需含输入前与实际变化的中途，重复同一输入再报阈值或时间范围。字体未加载、页面失焦或 GPU 降级时的数值单列。仅凭截图、CSS 声明或 canvas 标签不能声称真实帧率、三维资产或原项目使用了某个库。

## 吃透决定画面的资产

取到原站公开 GLB / glTF 后，在本地运行 `python <技能>/scripts/inspect-gltf.py <模型文件> --out ref/hero-model.json`。它读取容器内的场景节点、mesh、材质、蒙皮、镜头与动画时长，外部 buffer 不可读时如实留空。结合页面代码确认哪些对象真的被播放、灯光是否启用。

从面积最大、最能改变这段体验的对象开始。记录实际资源地址、运行对象和绑定它的代码，按层查看几何/骨骼、纹理/材质、相机、灯光、文字叠层、遮挡及合成输入。在固定视口标出主角、标题、目录及交接中心的位置和占比。调试候选包括公开模型与动画轨、CSS/WAAPI、DOM/Canvas 分层、视频帧和可光栅化的遮罩。资源有权使用时先复跑原结构再换主题；需新建素材时，沿用它在原镜头里的占幅、前后关系、运动和显示精度。原站用平面或视频时，保留相应技术路径即可。

例如原站两个人物之间出现一道笔触，露出下一场景。一次对照要看人物、背景、目录、遮罩和下一幕：停在相同滚动位置，观察两幕各露出多少，反向时是否退回。在 Three 中把单张画混成纯色，或只给边角的茶杯做立体材质，无法解释这些观测。Canvas 内部状态读不到时，记录源码定位、可见区域/连续帧测量与不确定性。从 GLB 读取节点、蒙皮、材质、动画片段和时长，再回到网页找实际绑定。舞台文件有额外轨道时，核对它是否连到当前资源，默认光强和可见性是否启用。新模型可以有不同的面数；优先比较同一镜头里可见轮廓和占幅、前后两层独立的位移、材质受光与遮挡。原始三角形计数只用于诊断资产，不直接换算成视觉还原度。

## 一份台账，从规格到验收

- `coverage` 对应拓扑中的实际 ID。对重复模板注明代表与理由，保留未打开的目标。锚点要有进入该目标后的画面或现场激活章节记录。
- `sections` 绑定区块规格、现有状态与样本的 ID。规格见[组件模板](../templates/组件还原规格模板.md)。在区块对应的源和成品状态中保存真实 DOM 层级、rect、computed style、可读原 CSS、关键帧、媒体/字体/图层以及截图。对浏览器不允许读取的原样式标注限制与替代取证。取证遇到截断就缩小选择器继续采。
- `categories` 按 `load / scroll / hover / pointer / component / navigation` 审视对应范围，写操作、观察及证据。没有效果也须有实际输入依据。行为状态只使用未检查、已确认无此效果、已测量、已实现、已验证、受阻。作为范围裁定的“范围外”和“同模板”与行为状态分开。
- `behaviors` 记录独立 ID、所属区块、输入目标与前置、初/过渡/终态、时长/延迟/缓动、离开、反向、重复和响应式差异。每项关键断言按 `direct / measured / fitted / unknown` 区分直接读取、重复实验测量、采样拟合或尚未确认。拟合附采样条件和误差；尚未确认的机制没有资格写成原站事实。引用实际观测文件中的标量、数组或具体源码片段，重复实验要保留原始记录。为两幕合成分别取出场层与进场层读数，在模型场景核对运行中的几何、骨骼或相机。只写“相似”“都是 WebGL”不能代表测量。
- 区块的 `layout` 指向对应截图状态下的真实组件树，例如 `{"state":"hero-ready","file":"ref/scout/runs/实际运行/states/实际状态/component-01.json"}`（文件名以实际输出为准）。成品侧 `built.layout` 对应本页相同视口、相同状态的记录。一个共享 DOM 文件可用 JSON pointer 引用子节点。
- 每块完成时分别核对静态和动态差异，记录修正操作，或中文排版、主题素材及无障碍等明确适配的影响。沿用同一次源记录，逐步补成品侧。用原站测量波动或明确的排版约束解释容差。全页差值与截图不能代替逐块核对。区块与行为的 `built` 分别写 `difference`、`action` 和实测结果 `verdict`（`match / adapted / fixed`），仍有偏离用 `drift` 并继续修正。台账的[完整可运行字段示例](../scripts/tests/fixtures/source-survey.mjs)仅展示格式。

原站的 `source`、关键样段的 `prototype`、整站的 `paired` 继续使用[阶段命令](A模式证据格式.md)。命令失败时输出所缺的事实或未达成的比较；在原站状态和样段未通过时，下一步是补当前阶段证据。浏览器能打开导出文件、外部评审给出印象分，都不能代替同输入的复演和逐区块结果。
