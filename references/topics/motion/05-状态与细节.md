# 交互动效：状态与细节

[专题索引](../../交互动效.md) · [先读使用边界](00-使用边界.md)。命令与代码路径仍以技能根目录为基准。

## J. X原帖中的状态与节奏判断（2026-10-20补充）

来源文字已通过Egolite读取，以下迁移做法未在本次项目实测。不是新增的动画框架、全部必做效果或参数门禁；在GSAP负责的编排层沿用对应技能，并遵守当前禁用hover；模式A核心驱动继续按已锁定机制实现。补充到现有动效清单和实际检查即可。

### J1 用透明状态层统一hover与press

- **问题 / 适用**：按钮、菜单等组件的悬停/按下颜色各自调整，状态关系不一致。
- **来源观点 / 应用建议**：Adham建议在交互元素上叠加透明层；本技能可复用组件已有状态层，GSAP只驱动该层的颜色或透明度，内容和图标保持位置稳定。
- **限制与替代**：叠加层不能拦截点击、盖住文字或焦点，也不能替代禁用、选择、加载与错误等语义状态；已有等效状态令牌时直接复用，不要求新增DOM。触屏不依赖hover。
- **验证**：比较不同底色组件的hover、按下、键盘焦点、快速移入移出及减少动态效果；不为此加入按钮上浮或hover图标运动。
- **来源 / 状态**：[Adham原帖](https://x.com/AdhamDannaway/status/1745090031453196359)，已读文字，未核定统一透明度数值。

### J2 动画节奏同时考虑体量与距离

- **问题 / 适用**：小图标和整屏面板共用同一移动节奏，或不同移动距离显得忽快忽慢。
- **来源观点**：Emil建议大元素更慢、长距离移动持续更久。
- **应用建议**：在同类动作、相近缓动和参考条件下比较大小与路径，必要时选择不同的已有时长档位；把原因写入现有动效清单，不凭空建立距离到毫秒的公式。
- **限制与替代**：不机械按尺寸线性增时，不让控件等待动画结束才能用；模式A优先遵从实测节奏。减少动态效果按既有策略收束，非必要大位移可用短淡化替代。
- **验证**：实际播放比较小/大、近/远的代表状态，检查中途反转、重复触发和结果响应；单张截图不能证明节奏合适。
- **来源 / 状态**：[Emil原帖](https://x.com/emilkowalski/status/2108531407786242389)，已读文字，视频中的速度未逐帧测量。

### J3 高频操作先保持即时反馈

- **问题 / 适用**：命令面板、快捷键、快速连续选择因装饰动画感觉跟不上操作。
- **判断 / 最小做法**：沿A4及[GSAP联动第2节](../../GSAP动效联动与审查.md)执行。业务状态、输入和焦点不被动画阻塞；按实际频率选择短反馈或直接切换，保留适用的其他GSAP状态与编排，不用这条删除整页动画。
- **限制与替代**：Raycast示例不是所有键盘操作、面板或普通网页的强制零动画要求；不从“每天数百次”推导统一次数阈值，也不因此取消当前用户的动画覆盖要求。
- **验证**：连续快捷键、快速开关、输入中反向操作，检查结果是否立即可用、是否排队或丢失焦点；与现有实际操作记录合并。
- **来源 / 状态**：[Emil原帖](https://x.com/emilkowalski/status/2054264701790421135)，已读文字，实际用户使用频率及具体页面感受待验证。

### J4 给AI或开发者描述可观察的动效

- **问题 / 适用**：只写“丝滑、高级、灵动”，无法对应实现或验收。
- **来源观点 / 应用建议**：Emil建议使用明确词汇；在已有动效清单中写出触发、方向、先后、起止及中断行为。例如“列表逐项出现”“前进和返回采用相反方向”“旧内容淡出同时新内容淡入”，再映射为适用的GSAP实现。
- **限制与替代**：词汇不是特效清单，不要求每页都用stagger、morph或布局动画；不因原帖提到AI而自动调用外部模型或安装库。
- **验证**：观察者能根据描述复现触发并判定起止与方向；继续用实际播放核对，不以术语数量代替效果。
- **来源 / 状态**：[Emil原帖](https://x.com/emilkowalski/status/2061426518333571576)，已读文字；示例表述为本技能归纳。

## K. 视觉运动优先transform，布局变化按需处理（2026-10-23补充）

- **问题 / 适用**：移动、展开或尺寸表现通过每帧修改`left/top/width/height`实现，产生重复布局工作；主线程繁忙时容易掉帧。
- **判断 / 最小做法**：最终占位由CSS与业务状态确定。只需视觉位移时优先用transform的translate，视觉缩放用scale，显隐用opacity；沿用GSAP时分别选择`x/y`、`scale/scaleX/scaleY`和`opacity`等属性，复用项目已有封装，不与另一套动画系统争用transform。
- **限制与替代**：transform不改变正常文档流占位；scale不能等价替代需要重新换行的容器宽度或推动相邻内容的展开，且可能拉伸文字与边框。需要真实尺寸变化时可以测量起止布局、在适合的场景用已安装GSAP Flip等机制过渡，或保留必要的尺寸动画；不为这条提示新增依赖。已有transform时复用/组合既有控制，不覆盖已有旋转、缩放或定位。
- **流畅性边界**：transform通常可避免该视觉变化本身触发布局，并可能在合成阶段完成；这不是主线程脱离保证。GSAP仍需主线程执行JS更新，昂贵绘制、图层与GPU负担等也可能掉帧。不承诺“用了transform就一直流畅”，不强制全站添加`will-change`或`translateZ(0)`。
- **验证方式**：实际应用时核对占位、文字清晰度、邻项与点击区域、快速反向和减少动态效果。排查卡顿或用户要求性能检查时，在相同内容、路径和设备条件下录制对照，检查Layout、Paint及掉帧；未录制时只说明采用了属性策略，不报告性能提升。沿用现有验收范围，不新增Lighthouse门禁或降低动效美学要求。
- **来源与验证状态**：用户于2026-10-23提供的动画性能提示；同日核对[web.dev《How to create high-performance CSS animations》](https://web.dev/articles/animations-guide)的布局/绘制规避与合成建议。具体GSAP迁移和布局例外为本技能应用建议；本次仅更新技能，未在网页实测。

## L. Craft：按压、可打断与高频反馈（2026-10-28）

来源为 Gustavo Fior 的已发布文章，以下是结合本技能现有 GSAP 约定的应用建议，数值只作对照，不增加全站必做效果或新门禁。禁止按钮 hover 上浮、hover 带动图标运动的现有用户偏好继续优先。本次仅阅读正文和示例，未在具体项目实测。

### L.1 按压反馈要跟手

- **问题 / 场景**：用户按按钮、可点击卡片或标签时，需要明确知道输入已被接收。可用轻微缩放或项目已有的颜色、边框等反馈，保持 `focus-visible` 和禁用态清晰。
- **来源示例**：缩放 0.97～0.98、约 100～150ms；大面积控件用同样缩放比例时边缘位移更大，应更克制。不要把示例变为所有控件的硬性数值；遵循既有 GSAP 实现，不因示例 CSS 新引入第二套动效系统。
- **验证**：实际用鼠标、触屏、键盘快速按下与松开，检查反馈是否及时、禁用控件不触发、减少动态效果时保留非位移反馈。来源：[Button Press](https://craft.gustavofior.com/button-press)。

### L.2 中途反向与新的布局目标

- **问题 / 场景**：弹层、菜单、侧栏未完成打开就关闭，或 toast 在队列移动时插入新项。动画应从当前位置回应新目标，避免瞬间跳到旧终点；不要仅因动画进行中而丢弃用户输入。
- **做法**：保持同一可控状态，从当前视觉状态重定向已有 GSAP 动画或 timeline；必要时处理后续项目的位置变化。弹簧适合需要保留手势速度或明显惯性的场景，普通菜单不必强制使用弹簧；并非所有 keyframe 或动画库都天然不可中断，具体取决于实现。
- **限制 / 验证**：业务中确有提交防重复、权限、关闭确认等约束时仍按业务处理，不能以动效可打断绕过；快速开关、插入/移除、焦点回收和最终状态要实际验证。来源：[Interruptibility](https://craft.gustavofior.com/interruptibility)；补充本文件 I 节相关判断。

### L.3 高频悬停、快捷键与提示

- **问题 / 场景**：频繁扫过导航或反复操作侧栏时，长过渡可能令反馈落后于操作。优先即时或极短的颜色/状态响应；低频且有空间关系的弹层仍可依据上下文设计动效。
- **提示**：来源建议首个 tooltip 等待约 400～700ms，同组连续查看时即时显示；作为可调试起点，而非固定标准。应支持键盘焦点、触屏替代入口和可读持续时间，不能把关键内容只藏在 hover 中。
- **验证**：快速扫过多个项目、连续调用快捷键，确认反馈、关闭和输入不被动画拖住；用真实键盘与触屏检查提示可发现性。来源：[Hover Restraint](https://craft.gustavofior.com/hover-restraint)。
