# 视觉评审模型与现场分工

用户2026-11-02指定：视觉评审优先Gemini或Claude。当前模型的独立子Agent是没有可用Gemini/Claude时的备选，不因派发方便就优先使用。

## 选择和派发

1. 用户指定了可用Gemini或Claude就沿用；未指定时按已安装[lsf-ai-agent](../../lsf-ai-agent/SKILL.md)的设计任务路由，优先可用Gemini，其次已授权可用Claude。型号、思考和真实入口只读该技能，不在本技能硬编码版本。没有账号或可用渠道时，不要求用户付费开通。
2. 读取[视觉评审浏览器取证](视觉评审浏览器取证.md)。Ego Lite现场工具由独立评审Agent操作；优先外部模型评分时，该Agent负责取证、交接和回收，不能把自己的预判当作外部结论。外部模型没有本机浏览器工具时，实际上传截图/状态帧与必要测量，不能只发localhost或本机路径，也不能声称外部模型亲自操作过页面。
3. 模式A成品按[固定提示词](../templates/独立评审固定提示词.md)在两侧复演。随附件注明原站/成品、状态ID、视口、输入、进度或相对时间；提供能看清中途交接与返回的片段或连续帧，并附现场操作结果。评分端按实际收到的材料区分所见画面和审核员的操作记录。原站无法复演或附件不可读时，注明影响哪一项判断。
4. 在既有prepare-review调用和台账中发送同一份固定提示词、规则快照、schema、同视口参考、当前截图与可消费的动效证据。保留首审盲评、定向复核与两次调用预算；不得按不同模型各算两次。现场取证不是额外评分轮次。
5. 通过`lsf-ai-agent`已授权浏览器渠道提交一次，核对完整回答与本轮身份。保存原始JSON、页面/入口、实际产品、可核对型号、时间和附件记录；不读内部推理，不发送凭据或无关源码。回收仍用现有record-review，真实协调Agent ID与外部产品/会话来源分别注明，不伪造Codex的Gemini模型名。
6. Gemini缺少账号、当前渠道不可用或用户明确不用时，检查是否有已授权可用Claude；两者均不可用才开一个继承用户当前模型的全新独立子Agent加载同一审查包。不要给spawn_agent编造Gemini/Claude型号，也不由主Agent自评。明确记录外部模型不可用的原因与实际备选模型。

## 失败与预算

原站调研、样段制作与开发自查不调用正式评分，不登记评审轮次。成品首审达标即止，需要复核时集中修改一批；正式派发最多两次，切产品沿用同一台账。技术故障区分未提交、已提交仍生成、回收失败和账号不可用，已登记的失败及超时均占额度。用户接管或要求等待时按原入口等待。只更新技能时不登录、不测试账号、不发送外部评审。

`design_reviewer`角色是现场取证/评审协调及必要时的当前模型备选；最终分数注明实际评分来源。单次报告不混合多个模型的意见拼成虚假独立评审，主Agent仍不得改写分数。

当前模型备选优先使用宿主的新子Agent以直接继承模型。`review-round.mjs`仅作必要的exec通道备选，必须传`--fallback-reason`及已核对的当前模型ID `--model`；不知道ID时使用宿主继承，不猜CLI默认型号。exec保持只读，使用独立现场Agent已经取得的Ego证据，不冒称自己实际操作过页面。缺少备选依据时脚本在登记/派发前退出，不消耗预算；真正派发后失败仍计数。
