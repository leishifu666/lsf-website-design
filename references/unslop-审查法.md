# unslop 评审专用适配

改编自 [unslop](https://github.com/heydamir/unslop)，作者 Damir Sokolovsky（[@heydamir](https://x.com/heydamir)），提交4652254daff586ff4739849395a127b56f7f8cc7，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。2026-10-31翻译、删减和改写；删除创作、生图、视频和重新确认流程，不代表原作者认可本改编。

## 适用与优先级

这是design_reviewer同一次评审使用的方法，不另增Agent、轮次或建站流程。用户要求、项目品牌与设计系统、模式A的参考优先。来源是作者的设计取向，不是普适定律。

先判断改动幅度：重度问题才提出结构性修改；轻度只修可见问题，保留已选方向；已不错就写无阻塞项，不为求不同改画面。换产品名仍然成立，是辨识度诊断问题，不是强制重做的判据。

## 从现象到意见

逐组观察间距、色彩、图标、文案表现、排版、布局、细节、素材、动效。每项定位具体元素/视口/状态/时刻，写“现象→对目标的影响→修法→验收条件”。不将单个来源偏好直接升为阻塞项。

| 现象 | 优先检查/修法 | 关联现有条目 |
| --- | --- | --- |
| 装饰、颜色、发光互相竞争 | 看是否抢走真正内容重点，减少无关强调；丰富表现可集中在有意义的内容时刻 | A4、B3、B6 |
| 页面像通用模板 | 看产品自己的对象、动作、内容与专属细节是否可辨认 | C1、C2、C7、C8 |
| 间距随意、同行不齐 | 同类尺寸/容器对齐，组内紧于组间；4px仅起点，允许光学校正 | 查排版细节，不新增固定格点门槛 |
| 图标大小/描边/文字起点不一致 | 复用项目图标体系，统一容器和角色；无意义图标可删 | 查图标与插画 |
| 字体、数字、圆角细节不协调 | 检查层级、数字精度与等宽数字、嵌套轮廓；按品牌适配 | A5、A7及排版细节 |
| 文案空泛，素材只是填充 | 指出其对主题和视觉表现的影响；修改定稿须回原文案来源流程，不由评审另写定稿 | C2、C7及文案审核 |
| 每段相同上浮、持续循环却无作用 | 核对叙事、节奏和实际状态，提出同方向修法 | A10、A11、M0–M8 |

B6的单色相不是“颜色越多越好”；用实际层级和用户色彩系统判断。嵌套圆角公式也不是所有控件必须通过的数值门槛。

## 与原版取向冲突时

- 不强制中性底、单一强调色、400–500字重、禁止斜体/大写、单一缓动；依据用户参考和已选体系判断。
- 不一律删除视差、pin、scrub、循环或丰富场景；判断是否服务已选叙事，是否出现实际视觉冲突。
- 不要求全页只一个入场或一两个动态元素；要有主次、时序和阅读停顿。禁用hover按用户要求执行。
- 不导入九遍改稿、生图、网页抓取重建、故事视频、素材连接或重复确认。图片、图标、GSAP与组件源码继续走原技能相应专题。

## 评审输出与收尾

沿用五维评分表，不另设unslop分数、不重复扣分。阻塞项须有可见依据且影响分数、底线或三项视觉约束；建议最多5条；未看到的状态列证据缺口。没有问题时可以返回空数组。

首审全量盲评；第二次带冻结问题、处理证据和受影响维度，核对修复与回退，不重新发散。三项视觉约束未验证不能算通过，但不能据此无限派发。共享预算、分数合成、状态和命令见[自动化与门槛](自动化与门槛.md)。
