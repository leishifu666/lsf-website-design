# 模式 J · 制作 DESIGN.md

把网站的设计体系写成编码助手可使用的 `DESIGN.md`。默认交付这一份文件。用户明确要求时再交付独立的 `DESIGN.html` 或导出令牌。读当前项目约定，沿用既有文件位置和已确认的规范。运行取证、写文件和校验即可，范围限于设计文档及明确要求的附属产物。

## 选择输入

| 输入 | 取证与落点 |
|---|---|
| 本地项目或仓库 | 从现有设计说明、实际加载的主题与令牌、共享组件和代表性路由追到页面。确认样式或组件确实被目标站使用。默认在对应网站源码根目录创建或更新 `DESIGN.md`，例如多应用仓库里的前台目录。 |
| 网站网址 | 实际渲染目标页，定位可见组件和加载的公开样式。采样桌面和窄屏，有主题切换时按可达状态核对。整站请求再选不同模板的代表页，同类页面点到为止。默认写在当前工作区，交付时标明是从外部页面还原的规范。 |
| 设计要求、品牌资料或截图 | 按用户已确认的要求起草。新增设计决策仅在用户授权设计时提出。截图能确认层级、形态和视觉关系，精确令牌应有源码、测量或用户确认作依据。没有实站时标明为拟议规范，记录实测所缺的输入。 |

用户只要求分析时停在分析。目标站和落点能由上下文确定时直接推进。目标不明确且会使规范落到不同产品时再澄清。

## 从实现提取可复用规则

- 查配色角色和主题、字号与行高、响应式网格与间距、连续曲线圆角和遮罩、阴影与材质。检查可复用组件的层级、变体和对应状态。选择会影响下一次实现的规则，避免抄录页面或 CSS 清单。
- 记录来源、页面或组件、主题与视口、实际属性和值。源码里有明确的共享令牌就沿用语义。外站用计算样式与已加载声明交叉验证，或确认同一角色的值在代表样本中一致。必要时可用技能已有的 `scripts/extract-tokens.mjs` 辅助采样，用频次统计定位待核对的值。单处样式按页面或变体记录。外站需要整理新的语义名称时，明确它是还原文档里的角色名。
- 实际操作导航、按钮、表单和弹层，覆盖有影响的悬停、键盘焦点、按压、选中、禁用、加载和开合状态。动效记录触发、变化的属性、时长与曲线、退出或中断、减少动态效果时的行为。计算样式有 `border-radius: 50%` 时也核对 `corner-shape`、`clip-path` 和素材自身轮廓。需要保真的组件细节写进适用段落，例如品牌图标的连续曲线、适用位置及兼容写法。
- 优先使用已确认的设计决定作为规范依据。现有产品与规范冲突时报告具体现象和来源，已接受的决定只有在用户或新权威依据明确替换时才修改。访问受限、字体未加载或状态无法触发时保留已获得的证据，说明未验证范围。

## 写成 Google DESIGN.md

先读取技能内的[完整 Google DESIGN.md 规范](../vendor/google-design-md/upstream/docs/spec.md)。J 模式新文档从[固定 Markdown 骨架](../templates/DESIGN.md)起稿。顶部 YAML 统一字段顺序，正文使用官方英文二级标题和顺序。中文说明写在标题下，缺少内容的章节可省略。更新已有文档时保留已确认内容和用户要求的格式。

- 按本地规范填写 `name` 及相关字段，例如 `colors`、`typography`、`rounded`、`spacing`、`components`。字体条目使用字段映射，例如 `typography.body.fontFamily`。组件引用写为 `"{colors.primary}"`。主题分组、属性与单位也按本地规范。项目锁定较早的 CLI 时，用其 `spec` 核对兼容范围并交代差异。
- 按骨架顺序选用二级标题。曲线、阴影和行为参数无法写为令牌时，放进对应段落。本地规范包含 `motion`。以 npm 0.4.0 为兼容目标时，在 `## Motion & Micro-interaction` 用 Markdown 记下时长、缓动和适用组件。
- 能减少重复说明时，用 `@相对路径` 指向规范目录下确实存在的组件源文件或示例。将文档写成可以直接指导实现的规则。抽样明细、未确认项和已知冲突在交付说明中交代。

使用[本地官方 README](../vendor/google-design-md/upstream/README.md#cli-reference)查 CLI 命令。[上游与更新说明](../vendor/google-design-md/UPSTREAM.md)提供官方示例和维护入口。

## HTML 预览参考格式

用户需要可视化时，从[可运行的 HTML 参考样板](../templates/design-preview-example.html)理解结构与交互，用项目自己的设计系统制作独立的 `DESIGN.html`。样板里的配色、字体、顶栏、栅格、材质和示例项目都可换。以产品中最有辨识度的界面或操作组织首屏，图形化章节入口按内容需要使用。颜色、排版与材质等章内可以采用不同的构图和背景。

| 章节 | 锚点 | 页面应看得到的内容 |
| --- | --- | --- |
| 概览 | `overview` | 产品名与代表性场景，直接看见设计语言和核心体验。 |
| 配色 | `colors` | 语义色、色值和它们用在界面的什么地方。 |
| 排版 | `type` | 用项目字体展示标题、正文或数字的实际层级。 |
| 布局 | `layout` | 代表性网格、间距和响应式变化。 |
| 材质与形状 | `surfaces` | 用实际表面、边缘、圆角或阴影显示差别。 |
| 动效与交互 | `motion` | 代表性反馈的触发、状态和已确认参数。 |
| 组件样例 | `components` | 至少一个可操作的组件小样，控件、状态和代码或令牌随同一个状态变化。 |

- `main` 内的七个直属章节按表中顺序排放，目录直接跳转各章。概览使用项目名作为 `h1`，其余章节使用 `h2`。提供源 `DESIGN.md` 链接，同目录默认使用 `./DESIGN.md`。
- 展示真实组件或从已确认设计规则做本地可操作样例，把规则、样件和控制放在同一区域。禁用、换主题、展开或改参数应实际影响当前样件。用清晰的键盘焦点、响应式布局和减少动态效果的写法。需要说明的演示值标注为演示，缺证据的规格标注待核对。
- 对照时两份预览使用同一章节顺序和链接锚点，各自用自己的品牌资产、首屏、章节构图和表现方式。只有确有第二份时提供互跳链接。首屏与章节入口参考 [Webflow Brand](https://brand.webflow.com/)，实时操作与同步代码参考 [Adobe Spectrum Button](https://spectrum.adobe.com/web/rsp/components/button)。
- 已用 `design-preview.json` 管理的旧页面，沿用[旧模板](../templates/design-preview.html)、[旧数据结构](../templates/design-preview.json)及[生成器](../scripts/render-design-preview.py)维护。新的项目化预览以本节的可运行参考样板为起点。

## 验证并交付

仓库已有官方 CLI 时优先用其锁定版本。以下命令使用已核对的 npm 版本 `0.4.0`，`designmd` 别名兼容 Windows 和其他平台。PowerShell 把 `npx` 解析到不可执行脚本时使用 `npx.cmd`。在目标产品目录运行，保留实际退出码与告警结果。

```sh
npx --yes --package "@google/design.md@0.4.0" designmd lint "./DESIGN.md"
```

- 更新已有文件时先保留原内容到临时位置，再运行 `designmd diff <修改前文件> ./DESIGN.md` 检查令牌、段落和告警变化。使用上面同一个 CLI 版本。核对删掉或替换的规范确有依据。
- 有结构化令牌时可用 `designmd export --format dtcg ./DESIGN.md` 验证兼容性。对使用 Tailwind v4 的项目可验证 `css-tailwind`，v3 可验证 `json-tailwind`。检查实际输出是否覆盖目标格式支持的令牌，只有用户需要时才留下导出文件。
- 修复 lint 的错误并复跑，说明保留的告警或工具故障。Lint 验证格式、引用和可计算的规则，组件状态、动效和响应式仍依据实际核对结果。HTML 打开实测 375、768、1440px 的章节、导航、键盘焦点与组件状态，确认样例和代码或令牌同步。维护旧生成页面时还用 `render-design-preview.py --check` 核对输出。
- 交付时给出文件位置、取证范围和 CLI 结果，点出无法确认的设计状态。说明文档是本地实现提取、外站还原还是按需求拟定。
