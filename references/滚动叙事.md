# 滚动叙事（Scrollytelling）

设计模式库条目｜2026-10-19。技术机制按文末一手文档核对；模式分类、分镜方法及示例为本技能的设计归纳，不是浏览器规范。

## 1. 解决什么问题，何时使用

让用户通过滚动逐步理解一个过程：每段内容对应一个有意义的场景状态，文字、物件、界面和空间关系共同推进故事。适合产品演示、品牌专题、过程解释、时间线和主题体验。

出现以下信号时读取本条目：用户明确要求滚动叙事；参考站用滚动推进场景；一个主体跨章节连续变化；需要把步骤、因果或时间进程可视化。模式A 应还原参考中承担叙事的机制，不把它替换成通用卡片堆叠。

任务型表单、频繁使用的工具、需要快速查找的列表优先保持直接浏览。普通长页面也可使用少量叙事区块，无须整站都做。是否采用以用户目标、参考和设备条件为准。

## 2. 区分四种机制

| 机制 | 控制什么 | 能否单独证明有滚动叙事 |
|---|---|---|
| 平滑滚动 | 页面滚动位置追随输入的手感，如 Lenis | 不能，平滑只改变手感 |
| 滚动触发入场 | 到达位置后播放一段按时间运行的动画 | 不能，还要有信息与场景的对应关系 |
| 滚动进度驱动 | 滚动位置直接决定动画进度，可停在中间、反向浏览 | 可用于连续演示，但仍需叙事目的 |
| 章节状态切换 | 进入某段内容时切换相应场景，可保留短过渡 | 可用于逐段讲解，不必每个属性都绑定滚动 |

视差、sticky/pin、横向画廊和视频都是可用手段，并非必须配置。不要把“加 Lenis”“每屏 fade-up”“多放几张漂浮卡片”当成完成叙事。

## 3. 先做分镜，再选动效

沿用现有 DESIGN.md 或拆解报告，写一张分镜表即可，不新增审批或强制多版方案。

| 章节/区间 | 读者此刻理解什么 | 主体与背景状态 | 场景如何变化 | 正文、操作入口与结果 | 倒滚/跳转/恢复/移动端/减少动态效果 |
|---|---|---|---|---|---|
| 一段实际内容对应一行 | 一个信息重点 | 进入、强调、退出时的状态 | 触发式或进度式，明确起止 | 区分装饰/叙事主体/控件，注明可发现的入口、预期结果与反馈 | 写清跳转后当前章、场景与用户选择如何恢复，以及适配或替代状态 |

在这张表旁用一句话说明“用户怎样推进故事、怎样知道当前状态”，例如“滚动推进一天，章节导航可跳转，时间与场景同步”。出现入口、反馈或恢复问题时查 [以人为中心的交互设计](以人为中心的交互设计.md) I1–I5；机制不确定、精细建模代价高时，先用简单替身验证关键章节，不为此新增多版或审批。

设计判断：
- **先有故事主线**：一个区间解决一个理解问题，滚动前后应有信息上的变化，不只换位置。
- **保持主体身份**：同一物件跨段移动、变形或换状态时保持视觉连续；非连续章节可以自然换场，不强行共享所有元素。
- **分清层次**：背景建立环境，中景承载主体/浮动 UI，前景给出当前信息和操作。不要让所有层同速、同时变化。
- **安排阅读停顿**：标题与正文有稳定、足够长的可读状态；不要求用户把滚动位置停到某个精确像素。
- **互动服务情节**：可操作的闹钟、待办或仪表应产生明确反馈；点击不是继续滚动的强制关卡，除非用户要求闯关机制。

**「牛马的一天」概念示例，不是参考站的测量值：**早起时闹钟与人物苏醒 → 通勤时票据和环境变化 → 工作时任务出现并可勾选 → 午饭时场景放松 → 下午用咖啡和能量状态表达疲惫 → 下班时物件收拢并形成票根。既可选一个主体贯穿，也可分成几个独立章节；不要求六段全部钉住。

## 4. 拆解参考站时量什么

复用 [风格还原](风格还原.md) 与 [交互动效](交互动效.md) 的取证。录屏、截图、运行时参数共同佐证；有动画库或全页截图本身不能证明已拆清叙事。

1. **章节与主体**：实际区块顺序、叙事对象、前中后景、文字与场景怎样对应。
2. **控制模型**：是进入区间后按时间播放，还是持续由滚动进度驱动；是否 pin/sticky；正文和场景谁在滚动。
3. **关键状态**：对每个代表区间采集进入、若干中间位置、结束和倒滚状态；快滚跨越一章、锚点直达时也要观察。
4. **空间与参数**：起止滚动位置、固定区域大小、移动方向、缩放/旋转/透明度、层间关系、解除固定方式、移动端差异。
5. **分开量两种延迟**：页面滚动的跟随曲线与场景动画追随滚动的延迟分别记录。不能看到动画慢就断定页面用了平滑滚动，更不能把两层平滑参数叠加到拖沓。

证据沿用 `ref/motion/motion.json` 及录屏/帧截图：记录参考 URL、视口与输入条件，区分 observed / estimated / unverified，并在 implementation_check 对账实现。看不到的配置标未验证，不猜参考站的精确 start/end、scrub 或滚动距离。

## 5. 实现路径与最小落地顺序

| 需求 | 优先考虑 | 注意 |
|---|---|---|
| 正文顺序推进，旁边保留一个主视觉 | CSS sticky + 章节状态观察 | 先检查滚动祖先、可用高度和解除固定位置 |
| 简单属性随滚动连续变化 | 原生 CSS scroll/view timeline | 先核对目标浏览器支持；用渐进增强保留静态内容 |
| 多轨道编排、pin、复杂进度同步 | 项目已有 GSAP ScrollTrigger 或同类方案 | 复用已有动画系统，不并装几套控制同一场景 |
| 真正需要三维空间、程序化形变 | Canvas/WebGL/Three.js | 另读特殊渲染约束；叙事形式本身不要求 3D |

**三维主体可先生图再建模**：需要原创角色或物件时，由 Codex 内置生图工具准备主体参考图，再联动 `img2threejs` 按图重建 Three.js 模型，接入同一张分镜表。详细流程、交接物与验证见 [特殊渲染 §2.5](特殊渲染.md#25-先生成参考图再按图建立三维叙事主体)。已有合适图片时跳过生图；本条目不自动要求所有叙事使用 3D。

最小顺序：完整可读的语义内容 → 明确章节与场景容器 → 绑定状态或进度 → 配置阅读停顿与层次 → 处理反向/跳转 → 移动端与减少动态效果 → 同条件复测。

连续进度可按 `p = clamp((当前滚动位置 - 起点) / (终点 - 起点), 0, 1)` 建模；起终点须由实际布局和参考确定，分母为零或区间不存在时恢复静态显示。按 p 直接求状态，避免只靠“播放下一段”累积状态，导致倒滚和锚点跳转错乱。

具体 API 以当前依赖为准：CSS 的滚动时间线按位置推进；ScrollTrigger 的 pin 固定一个区间，scrub true 直接关联进度，数字 scrub 指追平时间。它们解决不同问题。平滑滚动继续复用既有参数与集成，不因采用叙事就额外开启。

交互结果与叙事进度分开保存：倒滚可以复原视觉状态，不应意外取消用户已经勾选的任务。只在需要时更新场景，避免滚动事件里反复读写布局。

三维主体跨章节时复用同一个模型和渲染舞台，由章节进度驱动位置、朝向、部件姿态或相机变化，不在每一章重建模型。模型动作要推动当前情节；静态网格、可动部件与骨骼动画分别验证，文件存在不等于动作已实际播放。

## 6. 适配与验收

- **顺序与控制**：正常滚动、快速跨段、停止、倒滚、锚点直达、刷新恢复位置后，场景、章节导航与当前内容一致；用户能正常离开固定区间。选取与本页相关的实际任务记入已有评审表，例如直达后倒滚、完成交互后返回；记录起点、预期、观察和证据，不用截图存在代替实际操作。
- **阅读与键盘**：正文不依赖一次动画才出现；视觉重叠时不要让隐藏控件仍可聚焦。语义阅读顺序与叙事一致，键盘和触摸可用。
- **375 / 768 / 1440**：实际检查主体裁切、文字覆盖、导航遮挡、固定区解除和总滚动负担；移动端按内容重排，可改成纵向章节，不机械照搬桌面距离。
- **减少动态效果/降级**：保留故事和全部信息，可换为静态分镜与普通文档流，关闭非必要视差、长位移及平滑追赶。不支持动画能力或 JS 失败时也能阅读。
- **性能与证据**：检查真实滚动过程，不能仅凭静态截图判通过；按现有流程保存关键状态截图、滚动录屏和性能检查。控制大图、模糊、视频和渲染负担，明确未验证项。

该清单仅用于实际采用滚动叙事的区域，纳入已有设计评审和响应式验收，不新增全站 Hook、独立评分轮数或所有网站必须采用的效果。

## 7. 来源与验证状态

2026-10-19 已读取：
- [MDN：CSS scroll-driven animations](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll-driven_animations)：滚动/视图时间线的技术依据；兼容性在具体项目中另查。
- [MDN：position](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/position)：sticky 与滚动祖先、定位边界。
- [GSAP：ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)：pin、scrub 与进度等机制；本条目没有引入依赖或实跑新动画代码。
- [W3C：Understanding SC 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)：非必要交互动效的关闭与减少动态效果。该准则属于 AAA，不将它误称为 AA 条款；本技能仍沿用用户的动效降级要求。
- [Shopify Winter ’26](https://www.shopify.com/editions/winter2026)：本次用户指定的案例入口。精确分镜与动效参数使用项目中实际取得的证据，不从页面文字推断动画实现。
