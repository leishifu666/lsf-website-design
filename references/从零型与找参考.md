# 模式C/D：从零型与帮用户找参考

仅在明确原创（C）或先找参考（D）时进入这两条路径。普通建站没有参考时，由AI五站调研并选主参考走A，不默认让用户在C/D之间选择。用户的主题、事实、原项目、已有授权与设计约束继续沿用；选方向不是重新索要开工许可。只更新或讨论技能时，不实际启动预览制作、联网搜站或外部模型调用。

两条路径都先按[五站调研与记忆点](五站调研与记忆点.md)实际研究至少5个不同网站，分析特色、产品关系、形成机制及项目取舍，再做方向预览或制作。2026-10-31用户的新要求替代旧C默认不调研外站的约定；C原创自己的概念，D让用户选择参考站，二者按产物区分。

两条路径都按[表现技术选择](特殊渲染.md#01-所有模式先选表现技术再制作)处理核心体验，不能把原创理解成只写HTML平面排版。C为每个方向确定场景、渲染/资源/驱动方案，选定后真实实现；D为候选说明核心机制的技术证据与采用方式，未知如实记录，选中后再补齐深入取证。

## 1. 先确定路径

| 路径 | 用户意图 | 先交付什么 | 后续进入哪里 |
|---|---|---|---|
| C 原创三方向 | 研究方法后原创，不先指定一个还原对象 | 五站调研与三个有核心记忆点的真实视觉预览 | 用户选择甲/乙/丙，留在模式C制作选定方向 |
| D 联网帮找参考 | 想用参考站，但没有链接、不会找或想让 AI 找 | 至少五个真实参考候选，附截图或链接与特色分析 | 用户选参考站后转模式B或模式A |

- 用户已明确路径就直接执行，不重复询问。
- 用户没有明确原创或先看候选时，AI按[自动路由](模式与入口.md)判断；一般制作默认A，不再给模式菜单。
- 用户明确B但没有参考时，AI研究并选择适用参考继续B；只有用户要求先看候选才进入D，不把提供链接作为前置条件。
- 用户中途换路径，保留已确认的主题、内容和项目状态，继续对应路径，不重启整个需求访谈。

## 2. 路径C：调研方法后，原创三个主基调

先完成五站调研，再为用户主题构思甲/乙/丙各自的核心记忆点。借用适合的内容组织、视觉或交互原理，不拼接别人的品牌资产或默认首页结构，也不要求用户先选一个网站才能原创。

### C的构图方法库与随机种子探索

五站调研后读取[原创构图方法库](原创构图方法库.md)，运行`draw-original.mjs`，把种子与候选保存到现有ref目录。按行业、气质、实际可用素材与品牌约束筛选，并联动构图、阅读路径、文字和移动布局；Agent补全主题专属概念与真实技术后再做预览。不在A/B/D/E/F/G/H或已选定方向中抽签。

仅在**模式C的从零原创方向探索**中使用外部随机种子，帮助摆脱模型熟悉的构图和审美组合。模式B参考型、A风格还原、D寻找参考、F反推提示词不默认调用这套方法；已有选定方向的制作与局部修订也不重新抽签。用户明确不用随机，或已有品牌、参考、设计系统的约束时，服从用户和现有约束。

- **真实生成，保留记录**：用脚本等外部随机源生成字符串或数字种子，记录种子与使用方式；不能凭模型口头挑几个数字后声称已经使用外部随机。用户无需提供种子，不增加选择随机方式的确认环节。
- **布局也参与**：让种子影响信息组织与阅读路径、构图骨架、网格密度、留白比例、主次尺寸、位置与裁切关系，再联动字体角色、色彩/材质与动效节奏。不能只随机配色，或给“极简/复古/赛博”等现成风格编号后抽签，却保留同一首页结构。
- **先定解释或映射，再做预览**：每个方向简要说明种子怎样改变布局和其他视觉维度，然后按这些规则实现；不要先画熟悉的页面再补写种子解释。可以采用字符串模式启发，也可以采用固定哈希/取模映射；后一种应先固定候选池或参数范围。具体主题的票据、玻璃层等实验结果不沉淀为所有网站共用的三套模板。
- **保留设计判断**：数字没有天然的风格含义。Agent仍需把抽到的条件组织成与主题有关的体验；事实、必要任务顺序、状态反馈、可读性、焦点、触屏和响应式约束不随机。说明为满足这些约束作出的适配，不悄悄把抽签布局换回默认模板。固定种子与映射只保证参数可复现，不承诺模型生成结果逐像素一致。

首批仍为三个方向预览；用户全不满意时按[预览与确认](三方向预览与确认.md)反馈驱动补充新方案，直到确认，不增加独立设计评分轮次、发布或委派授权。随机性只是C的构思方法，后续制作要求继续适用：

- **交互设计**：有导航、滑杆、叙事控制、展开/关闭等操作时，按[以人为中心的交互设计](以人为中心的交互设计.md)的对应问题检查入口、操作预期、反馈、状态映射、撤销/恢复和打断。把实际操作与观察写入现有设计或检查记录，不把“做了动画”当作已经完成交互设计。
- **组件源码**：落实到页面组件前，继续按[组件书签与源码复用](组件书签与源码复用.md)从指定网站找合适组件，查看演示、取得可复用源码和许可，再按当前方向适配。已有且适用的同源组件可沿用来源记录；但复用了一个数字计数器，不代表其他新做的叠层、切换、拖动等组件已经完成检索与复用。原站组件是实现材料，不能反过来把已确定的原创布局改成组件库的默认展示。

来源与边界：[Sakana AI的String Seed of Thought](https://pub.sakana.ai/ssot/)研究提示内字符串生成及操作带来的采样和输出多样性；[Anshu Chimala的网页设计实践](https://www.lennysnewsletter.com/p/how-to-turn-your-ai-into-a-world)采用脚本生成外部随机字符串。本节是将该实践用于C的流程约定，不把多样性研究当作“随机后必然更好看”的证据。

### 必须交付的三个方向

根据用户主题首批提出 **三个可选方向甲/乙/丙**；后续按真实反馈继续新方案，不把三版当上限。它们是三种不同的风格主基调，不是三张同版式换色稿，也不是旧六版流程中不允许选择的“前三个基线”。

每个方向说明：

- 名称与一句话主基调：让用户能说出这一版给人的感觉。
- 核心记忆点：记住什么、为何属于当前产品、怎样感受并延续、实现及触屏适配；概念不能只靠换配色或特效成立。
- 排版与布局：字体角色、信息层级、页面组织和留白节奏。
- 色彩与素材：配色关系、图像/插画/材质的处理方式。
- 交互与动效：适用的节奏、反馈与核心机制，说明怎样服务主题。
- 表现技术：核心场景由什么渲染、素材与驱动实现，已有组件/资源如何复用，预览展示什么动态或操作；不能仅写“高级动效”“用GSAP”，也不为凑差异硬选三种引擎。

三个方向保持相同主题与核心内容，以便比较；至少在布局组织、排版、色彩/素材、交互表达中的三个维度有明确差别。方向名称和风格由实际主题决定，不固定套用三套模板。

### 必须给用户看到预览

- **三种风格都必须有真实可见的视觉预览**，只给形容词、文字方案卡、配色条或生成提示词不算完成。
- 默认做可打开的HTML预览：每种风格先认真完成最有特色的关键片段，配齐判断它所需的标题、内容、主体及代表性交互，能切换、放大或分别打开，避免缩略图掩盖差异。按[共用预览标准](三方向预览与确认.md)实际检查375/768/1440和相关状态。用户明确只要静态方向时可交清晰图，说明动效未实现。
- 预览直接使用用户的主题与已知标题。文案未定时可保留已确认原文或明确标记占位，不为制作方向预览编造业务事实；正式页面定稿继续执行适用的文案流程。
- 预览只做到足以判断主基调，不要求同时做三套完整生产网站，不默认增加六方案技能、独立评分或多轮发散。
- 先调研至少五站再做预览；预览展示核心记忆点和代表性反馈。用户之后明确要求不联网时记录该次覆盖，不自行沿用旧“不调研”惯例。

### 等待选择与继续制作

交付首批三个可见预览及访问入口，简明比较甲/乙/丙，并让用户选择。三版全不满意则根据反馈补新方案；具体差异分工、独立上下文和后续数量以[预览与确认](三方向预览与确认.md)为准。未取得选择且未授权AI代选前，不默认挑一版制作正式网站；可继续检查预览。用户明确“你来选”时，说明取舍并继续。

用户选择后，将主基调、记忆点、令牌、素材层次、表现技术与交互原则写入项目DESIGN.md，并只制作选定方向。摄影、透明底生图、图库素材、建模与预渲染按主题和能力选择，见[氛围图片](氛围图片.md)。将选定的核心动态/交互场景实际做成，不把静态预览、平面代码拼图或通用淡入当成该体验已经完成；是否采用滚动叙事、Canvas或实时三维由具体方案决定。

## 3. 路径D：联网寻找不同风格的参考站

### 按主题搜索与分析

从用户的主题、用途和想表达的气质提炼关键词，到 [Minimal Gallery](https://minimal.gallery/websites/) 等网站灵感图库，以及 Awwwards、FWA、CSS Design Awards、Webby 等获奖网站目录或奖项官方站点寻找案例，实际打开候选网站。无需每个目录都查一遍；目标是找到与当前主题有迁移价值的案例。

Minimal Gallery 可按主题分类筛选，如作品集、品牌、电商、SaaS、建筑等；把它作为网站灵感图库使用，收录不等于获奖。找到案例后继续打开原站核对内容、视觉与交互。

- **至少找到五个真实网站，覆盖不同的特色形成方法**。同一网站的多个区块、页面或截图不重复计数；一批相同模板换色不满足研究目标。
- 优先找主题或用途相关的案例；相关案例不足时可扩大到叙事形式、产品展示方式或交互目标相似的跨行业网站，说明为何适用，不假装它属于相同行业。
- 核对原站链接、能否访问、实际视觉与核心交互。奖项名称/获奖身份只有查到官方证据才写；入围、提名、目录收录与获奖分开说明，不编造日期、奖项或评分。
- 检查每个案例的内容结构、排版、配色、素材与交互，说明适合用户主题的地方，以及迁移时要调整什么。只检索到标题或搜索摘要，不能称已经完成页面分析。

### 给用户看的参考候选

每个候选至少包含：

| 项 | 内容 |
|---|---|
| 站名与风格 | 网站真实名称，以及易理解的主基调 |
| 视觉证据 | 对应页面截图或可点击的原站链接，优先两者都给；不能只报站名 |
| 来源 | 找到它的图库/目录/奖项页；是否获奖如实标注 |
| 分析 | 布局、排版、配色、素材与代表性交互的实际观察 |
| 主题适配 | 可借鉴什么、为什么适合、哪些地方需要替换或简化 |
| 限制 | 无法访问、动画无法验证等具体未验证项 |

截图失败但网站仍可访问时，给原站链接与已核对的分析并说明截图缺失。网站无法访问、也没有足够证据支撑分析时，寻找替代候选，不能用虚构截图补数。工具或网络限制阻止取得五个合格候选时，展示已取得的材料并报告缺口，暂停依赖该调研的方向定稿，不宣称达标或无限重试。

### 选参考，再转模式

候选齐备后，让用户选择 **参考站 + 处理方式**，可一次问完，不必拆成两轮：

- **模式B 参考型**：学习所选网站的结构、叙事和交互原则，为用户主题设计自己的风格。
- **模式A 风格还原型**：实测所选网站的视觉与动效，贴近其设计语言，替换成用户自己的内容和原创/授权素材。

用户说“选一”时依据当前候选上下文识别第一项，不把它固定解释为旧编号模式；制作请求未明确只学方法时默认A。已说“按这个风格做/还原”就直接转模式A，已说“只学思路”就转模式B，无需重复问。

选定后明确说明模式转换及采用的参考 URL，沿用已取得的证据，不重复搜索同一批案例。转入模式A后沿用研究证据并按风格还原取证，默认直接制作一套；用户明确先比较时才做三个同提示词、同主题、同网址的参考预览，不追加C原创方向；转入模式B后按用户范围提炼原则与制作，也不自动增加六版探索。

## 4. 完成判定

- C：先完成至少五站调研，首批三个不同记忆点均有真实关键片段预览；不满意按反馈继续，用户确认后才展开正式整站。
- D：至少五个真实参考候选有截图或链接及特色、机制和迁移分析，随后按用户选择转换为模式B或A；沿用本批证据，不再重搜五站。
- 搜站、预览、正式实现与评审分别报告实际完成情况；预览选择不等于网站已经交付，也不构成新增子代理、发布或提交授权。
