# 交互动效：操作与工程

[专题索引](../../交互动效.md) · [先读使用边界](00-使用边界.md)。命令与代码路径仍以技能根目录为基准。

## 滚动手感：实时还是有延迟（2026-10-19 补充）
有的站滚轮一下立刻到位（原生滚动），有的有延迟、带惯性（Lenis 等平滑滚动，更“丝滑”）。参数必须从参考站量，不凭感觉写：
- `extract-motion.mjs` 的 `smoothScroll` 字段：滚轮一次后逐帧记录 scrollY，给出 t10 / t50 / t90 / t99（到达 10%～99% 位移的毫秒数）和估算的 lerp（按 60fps）。`runtime.lenisOptions` 读得到时以它为准。
- 实测（2026-10-19）：lenis.darkroom.engineering：t50 220ms、t90 405ms、t99 684ms，估算 lerp 0.121（Lenis 默认值 0.1，接近）；Shopify Editions 冬季 ’26：60ms 时只走了一半；普通原生滚动测试页：23ms 内全部到位，判“实时滚动”。
- 写进 `reference-spec.json` 的 `motion.smooth_scroll`：`{ "type": "lenis", "lerp": 0.12, "t90ms": 405 }`。实现后用同一个脚本量自己的页面，t90 和参考站差 ±20% 以内才算还原。【阈值为归纳】
- 平滑滚动的代价【归纳】：键盘、锚点跳转、`position: sticky` 和 ScrollTrigger 都要接到 Lenis 上；`prefers-reduced-motion` 时关闭平滑。

## I. 按场景选用的动效工程技巧（2026-10-19 补充）

本节合并用户提供的提示。API 按下列官方资料核对；【归纳】为设计判断，参数为示意，不是参考站实测或全站默认值。仅在项目已选择相应技术时使用 Motion，实施前检查依赖版本和实际导出，不为技巧自动安装或升级依赖。减少动态效果时去掉位移、抖动、变形与装饰编排，保留状态反馈。本节不增加 Hook 门禁或所有页面必做项。

### I.1 拖拽边界、阻力与吸附

**问题 / 适用**：自定义拖拽越界后伸展无上限，或分屏需要反复微调。仅用于已有拖拽、分屏或边界反馈需求，不接管普通网页的原生滚动。

**写法**：用户的橡皮筋公式按非负距离定义；双向使用时先取绝对值再恢复符号，防止负值处出现奇点。只对越界距离应用，约束内继续跟手。

```js
function rubberBand(x, d, c = 0.55) {
  if (![x, d, c].every(Number.isFinite) || d <= 0 || c <= 0) return 0;
  const t = Math.abs(x) * c / d;
  return Math.sign(x) * (1 - 1 / (1 + t)) * d;
}
```

- `d > 0` 为渐近位移上限，`c > 0` 调节响应。单侧斜率为 `c / (1 + c * x / d) ** 2`，随距离增大而降低；理论上渐近 d，浮点计算可能等于边界。公式与 0.55 来自用户，以上为数学推导，不标为已核验的 iOS 官方实现。
- Motion `dragConstraints` 设置范围；`dragElastic={0.08}` 设置**越界后的移动比例**，不等于边界内阻力或上述非线性曲线。`dragMomentum={false}` 关闭释放惯性，回到边界与吸附仍需设计。
- 分屏可提供 25% / 50% / 75% 常用点【归纳】，结合可用宽度和两侧最小尺寸计算合法位置；仅在释放时接近点位才吸附，其他位置保留精细调整。释放弹簧不应让直接拖动延迟跟手。
- 手柄支持键盘调整，标明方向、名称、当前值及范围。比例、吸附阈值和回弹参数按参考与产品决定。

**来源 / 验证**：[Motion 拖拽](https://motion.dev/docs/react-motion-component#dragelastic)、[WAI 分割视图模式](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)。公式来自用户；2026-10-19 本机验证了双向对称、单调、有界、斜率递减及无效输入处理。真实触控、键盘和滚动边界手感仍需项目实测。

### I.2 可打断弹簧与视觉时长

**适用 / 做法**：快速悬停、按压和反向切换时保持同一节点与动画值，从当前状态更新目标，不重设起点。Motion 物理弹簧（stiffness / damping / mass）会考虑已有速度；时长型弹簧不能等同于保留速度的物理弹簧。

- 物理参数示意：`{ type: "spring", stiffness: 520, damping: 38 }`，不是通用预设。
- 协调主要运动的视觉到达时间可用 `{ type: "spring", visualDuration: 0.5, bounce: 0.2 }`。尾部回弹可能在该时间之后；visualDuration 不是移动规模或保证最终停止的时间。
- visualDuration 覆盖 duration；设置物理参数又会覆盖时长型配置，避免混用两套参数。不把“同样 0.5 分别移动 96ms / 231ms”当通用结论，必须固定版本、距离和测量阈值。

**来源 / 检查**：[Motion transitions](https://motion.dev/docs/react-transitions)。验证快速连续反向、重复点击与减少动态效果，没有回到初始位置或排队阻塞。

### I.3 重排身份、文字尺寸与弧线路径

**问题 / 做法**：列表重排与卡片展开先保持业务身份，再选择动效。

- 列表使用稳定业务 `key={card.id}`，不使用数组下标或随机数。`layout` 动画化布局变化，`layoutId` 匹配共享元素，不能代替 React key。
- 最终几何由布局状态决定，避免 layout 与另一套 left/top/width/height 动画争夺同一变化。圆角和阴影按 Motion 要求设置在可读取的 style 中，并沿用项目令牌。
- 父级布局通过 scale 动画尺寸时，文字可能变形；子元素可用 `layout="position"` 只动画位置，尺寸直接更新。它不保证文字不重新断行，仍要检查宽度、长文本和图片裁切。
- 微妙弧线适合有空间关系的移动【归纳】。显式 x/y 用 `transition.path`，布局与共享元素用 `transition.layout.path`。当前文档支持从 motion 或 motion/react 导入 arc，motion/mini 不支持；旧版本先查导出。

```jsx
import { arc, motion } from "motion/react";

// 稳定实例；组件内也可用 useMemo，避免每次渲染重建。
const cardPath = arc({ strength: 0.08, rotate: 0.08 });

<motion.article layout
  transition={{ layout: { duration: 0.6, path: cardPath } }}>
  <motion.p layout="position">保留真实字号的文字</motion.p>
</motion.article>
```

**限制 / 来源**：上述参数仅示意。strength 为 1 时弧高可达两点距离，不把 0.9 默认叫作“微妙”。旧版本或减少动态效果时改为直线或即时更新；弧线不是重排必需项。[Motion layout](https://motion.dev/docs/react-layout-animations)、[arc](https://motion.dev/docs/arc)、[React 列表 key](https://react.dev/learn/rendering-lists#keeping-list-items-in-order-with-key)。检查节点身份、焦点、文字与打断行为。

### I.4 动画叠加、层级揭示与共享轴

**叠加**：两组动画都控制 transform 时，可按动画顺序设置 `animation-composition: replace, add`。保持基础浮动动画，再叠加短反馈；或把它们放在内外两层。add 的变换组合有顺序，不是所有属性都作简单数值相加。

```css
/* float 和 shake 是项目已定义的 transform keyframes。 */
.layered-motion {
  animation: float 6s ease-in-out infinite, shake 250ms ease;
  animation-composition: replace, add;
}
```

**层级与交错【归纳】**：容器、卡片、关联文字依次出现可表达组织关系，小网格可用短 stagger；长列表限制总等待，只处理新进入的可见项，不阻止操作或假造加载过程。from: center 指匹配列表的中央，不自动计算二维网格的空间中心。

```js
import { animateView, stagger } from "motion";

// update 是真实 DOM 更新；先确认当前版本导出 animateView。
if (matchMedia("(prefers-reduced-motion: reduce)").matches ||
    !document.startViewTransition) {
  update();
} else {
  animateView(update).add(".item").enter(
    { opacity: [0, 1], transform: ["translateY(12px) rotate(-2deg)", "none"] },
    { duration: 0.26, delay: stagger(0.05, { from: "center" }) }
  );
}
```

**共享轴【归纳】**：下一步沿流程方向进入、返回反向退出；RTL 和纵向流程相应调整。退出步骤移出交互与辅助技术读取，焦点交给新步骤适当位置，关闭动画后仍能辨认当前位置。

**来源 / 验证**：[MDN animation-composition](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-composition)、[Motion animateView](https://motion.dev/docs/animate-view)、[stagger](https://motion.dev/docs/stagger)。测试叠加顺序、长列表等待、快速前后切换与减少动态效果。

### I.5 按意图显现控件与不可用反馈

**适用 / 做法【归纳】**：次要操作可在 hover、focus-within、进入相应区域或开始操作后显现。主操作保持可发现，触屏没有 hover 时也能找到；不可见控件不能意外留在可交互状态。

- 操作不可用时先给原因、解除条件或下一步；轻微抖动只能是一次性的补充，不能替代文字或每次 hover 都触发。
- 原生 disabled 控件通常不在 Tab 序列；需要说明原因时把提示放在可读取的位置，或使用有完整阻止执行逻辑的 aria-disabled 方案。aria-disabled 不会自动禁止点击。
- 减少动态效果时取消抖动；键盘、触屏和屏幕阅读器可获取同样信息。

**来源 / 检查**：[WAI disabled 与 focusability](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_disabled_controls)。验证首次使用能否发现操作并理解不可用原因。

### I.6 方向、速度、接近度与形变

**方向【归纳】**：根据光标进入边缘确定图片与内容的初始偏移。getDirection() 是需要实现的项目辅助函数，不是内置 API。可比较相对中心的归一化坐标，避免长宽比带来偏差。

```js
function entrySide(event, rect) {
  if (rect.width <= 0 || rect.height <= 0) return "top";
  const x = (event.clientX - rect.left - rect.width / 2) / rect.width;
  const y = (event.clientY - rect.top - rect.height / 2) / rect.height;
  return Math.abs(x) > Math.abs(y)
    ? (x < 0 ? "left" : "right")
    : (y < 0 ? "top" : "bottom");
}
```

**速度与形变【归纳】**：运动速度可映射轻微旋转、沿运动方向拉伸和模糊；文字与操作目标不跟着变形。Motion 使用实际驱动位置的同一个 MotionValue，接 useVelocity 和 useTransform；不要另建一个从未变化的 x 来测速度。

```jsx
// 组件内，从 motion/react 导入对应 hooks；数值仅为示意。
const x = useMotionValue(0);
const v = useVelocity(x);
const scaleX = useTransform(v, [-1200, 0, 1200], [1.05, 1, 1.05]);
const blur = useTransform(v, [-1200, 0, 1200], [1, 0, 1]);
const filter = useTransform(blur, b => `blur(${b}px)`);
// <motion.div drag="x" style={{ x, scaleX, filter }} />
```

- Motion 速度通常按单位/秒，手写 dx/dt 若 dt 是毫秒则为 px/ms，不能直接共用参数。手写速度要初始化上一采样点、防止零时间差、限幅、平滑并在离开后复位；CSS transition 自身不等于物理阻力。
- Dock 可用 `max(0, 1 - distance / radius)` 映射接近度；测量稳定命中容器，不测已缩放的图标，以免反馈抖动。限制半径与缩放，避免盖住邻项。
- 光标特效仅在细指针且可 hover 设备启用；键盘与触屏保留明确状态。缓存稳定几何，先批量读再在一帧内写样式，清理监听，避免读写交错造成布局抖动。

**来源 / 验证**：[Motion useVelocity](https://motion.dev/docs/react-use-velocity)、[useTransform](https://motion.dev/docs/react-use-transform)。方向算法和参数为【归纳】；2026-10-19 已验证非正方形矩形的四边方向判断，未验证完整 Motion 渲染。项目中再验证快速移动、重新进入、窗口缩放与减少动态效果。

### I.7 阴影、景深与滚动期间的模糊

**适用 / 做法【归纳】**：需强调的抬升可把物体与地面阴影分层，物体上移、阴影淡出并收窄；仅在透视合理时使用，不成为所有卡片的默认 hover。

- 模态出现时可轻微缩小背景内容层；不缩放包含弹窗的祖先或整个 body，避免定位、清晰度受影响。退出恢复原状态，减少动态效果时保留静态层级即可。
- 玻璃效果可用模糊、色调与边框，但须保证文字对比和实色降级。10–15% 黑色或 40% 遮罩都不是通用配方。
- 滚动中降低模糊、停滚恢复是可选性能策略。用户的 120ms debounce 检测的是“正在滚动”，不是“快速滚动”；按速度降级需计算 abs(deltaScroll)/deltaTime，设置阈值、滞回和每帧更新上限。
- 不在每个 scroll 事件里反复动画滤镜，也不把 GPU 开销下降写成未测量的事实。静态低模糊可能更合适。

**来源 / 验证**：[web.dev 动画性能](https://web.dev/articles/animations-guide)、[MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter)。深度与视觉选择为【归纳】，用真实背景检查对比、滚动帧时间及减少动态效果。
