# 以人为中心的交互设计

按问题取用的设计库条目｜2026-10-19。用于设计或评审实际交互，沿用当前目标、模式、参考与设计系统，不为普通任务增加整套研究流程。

## 按问题查阅

| 问题 | 条目 |
|---|---|
| 看不出哪里能点、拖动或旋转 | I1 操作入口 |
| 不知道按钮会做什么，或点完不知道结果 | I2 预期与反馈 |
| 导航、文字、场景各说各话 | I3 一致的使用逻辑 |
| 翻页后忘记信息，控件与结果难对应 | I4 记忆与映射 |
| 误点、理解错、失败或中断后无法继续 | I5 防错与恢复 |
| 效果很多，却影响操作或缺乏体验重点 | I6 动效与体验 |
| 想法未确定，就开始制作昂贵素材 | I7 小原型 |
| 评审只有分数，没有复现过程 | I8 任务观察 |
| 越加越多，下载、运行和维护成本失控 | I9 功能取舍 |
| 简单修改被弹窗反复打断 | I10 直接操作 |
| 静态稿无法判断交互手感或空间关系 | I7 小原型、I11 代码原型 |
| 只需训练某一项设计能力 | I12 单项练习（仅训练场景） |

以下网页做法和例子是本技能的应用建议；I1–I9以书中概念作依据，I10–I12另引X设计师公开分享，不混同来源。均不是每站必做的功能清单。取当前问题对应条目，写进已有分镜、素材计划、动效清单或评审记录即可。

## I1 操作入口

**依据：**可供性是用户能力与物件性质之间的操作关系；示意线索帮助发现如何操作。二者不能混同。原书第1章10–20页。

- 区分装饰、滚动驱动的场景和可操作物件。可操作物件有能被发现的入口与名称；只展示的物件不制造假按钮或无效点击。
- 例如闹钟可点击时，给出适合主题的操作线索及键盘/触屏入口；只有鼠标拖动实现，不等于其他输入方式也能操作。箭头、光标、hover是提示手段，不能代替实际能力，关键入口也不只靠hover出现。
- **验证：**不先解释，观察测试者能否发现并完成目标操作；没有真人参与时，仅报告实际完成的键盘、触屏或浏览器检查。

## I2 预期与反馈

**依据：**前馈帮助判断可以做什么，反馈帮助理解已经发生什么；执行与评估都需要清楚的信息。原书第1章23–25页、第2章38–43、71–73页。

- 用实际用途写操作名称；在相关控件附近呈现结果。按压回弹提供触感，但不能代替待办状态、提交结果或错误说明。
- 异步任务区分提交、进行、成功和失败。进度来自真实状态；无法量化就不编百分比。反馈按重要性安排，不把每个状态变化都变成弹窗或长动画。
- **验证：**比较用户操作前能预期的结果与操作后看到的实际状态；检查重复点击、失败及返回后是否仍能理解。
- 卡点难定位时，用行动七阶段诊断：目标→计划→确定动作→执行→察觉结果→理解结果→对照目标。它不是必须依次发生的流程，不增加七步审批或每次必填七栏。

## I3 一致的使用逻辑

**依据：**概念模型是帮助理解和预测系统行为的简化解释；用户依靠可见界面与反馈建立认识，未必知道实现方式。原书第1章25–32页、第3章118–122页。

- 在现有设计说明中，用一句话说清用户如何推进任务、怎样知道当前状态。时间线、导航、正文和主体状态要对应；操作方向也要符合目标人群习惯。
- 例如“滚动推进一天，章节导航允许跳转，当前时间与场景同步”。直接打开下班章节时，不应仍显示通勤场景。模型可以简化技术细节，但网络断开或保存失败时仍要解释得通。
- **验证：**正常操作、中断、倒滚、跨章、锚点直达与刷新恢复后，实际界面仍表达同一套逻辑。

## I4 记忆与映射

**依据：**头脑中的知识和外界线索可以互补；控件与结果之间清楚的空间、方向和时间关系有助理解。原书第3章74–79、109–122页。

- 在需要时显示当前章节、已选条件和操作结果；让控件靠近其影响的内容。保留任务必要的输入和选择，不要求用户跨屏记住并重新填写。
- 例如咖啡按钮与精力变化放在同一处；打开说明后返回，仍能找到原来的任务。低频帮助可以展开，熟练用户可以有快捷方式，不要求所有信息常显。
- **验证：**离开再返回能否继续，操作与结果能否对应；文化或设备不同的方向习惯不能只按设计者直觉认定。

## I5 防错与恢复

**依据：**约束可以限制不合适的操作；目标正确但执行偏离的失误，与目标/计划本身不合适的错误，处理方式不同。原书第4章125–145页、第5章170–180、198–209页。

- 误点时检查位置、目标区分和撤销；理解错时检查名称、提示及使用逻辑。按实际风险使用输入校验、拖拽边界、吸附和必要顺序。
- 能安全恢复的小操作优先让人直接操作并撤销；不可逆或高代价操作显示具体对象与后果。错误说明给出下一步，保留已完成的合理输入，不用反复“确定吗”替代防错。
- **验证：**故意误点、输入不完整、操作到一半中断，检查能否发现问题并继续。此网页交互建议不扩大 Agent 的执行授权。

## I6 动效与体验

**依据：**反馈需可理解且不过度打扰；本能、行为、反思是理解认知和情感的简化模型。原书第1章23–25页、第2章49–55页。

- 沿用用户指定的GSAP覆盖要求，在现有动效清单说明“帮助理解什么变化，或营造什么体验”。第一眼的吸引、操作中的掌控、结束后的感受都可考虑，不要求每个控件各配三套效果。
- 例如人物造型吸引阅读，闹钟和待办操作清楚，结尾票根呼应一天的经历。趣味与戏剧性可以保留；正文有可读停顿，直接操作及时响应，动画反向或被打断后仍保持正确状态。
- **验证：**动画没结束就反向操作、快速连点或跨章，检查能否继续使用。滚动跟随延迟、缓动、时长按参考与项目实测，不从本书推导技术参数；细节沿用 [GSAP动效联动与审查](GSAP动效联动与审查.md)。

## I7 小原型

**依据：**先确认问题，再通过观察、构思、原型和测试迭代；实际工作受预算、排期与协作限制。原书第6章217–241页。

- 交互不确定、返工代价高时，先用简单替身验证关键机制，再投入精细素材。已有明确方案或成熟组件时直接复用，不为套方法而重开方案探索。
- 例如先验证主体贯穿章节时的状态、文字空间、控制与跳转，再制作正式图片、模型和材质。原型暴露卡点后修对应环节，不自动重做整页。
- **验证：**写清这次试做解决哪个不确定点、实际看到了什么；继续使用已有 [双钻与设计思维](方法论库.md)，不增加审批、六版方案或文案替代流程。

## I8 任务观察

**依据：**围绕目标活动观察和测试，与反复修订配合。原书第6章222–230页。

- 按当前页面选择真实存在的关键任务，记录起始状态、预期、实际操作/观察、问题与证据。例如跳到下班再回早晨，或勾选待办后撤销；不要求每站都具有这些功能。
- 沿用 [评审评分表第5.1节](../templates/评审评分表.md)，区分Agent检查、浏览器自动化与真人参与。Agent模拟不证明目标用户已理解，未测就注明；真人未参与不自动触发招募。
- **验证：**问题能定位到具体任务与状态，修复后复做同一任务。“把票根误认为可下载，点击无结果”比“交互不够好”更便于改。现有分数线与独立评审继续执行，不把评分当成本书的标准或真人研究结果。

## I9 功能取舍

**依据：**区分复杂与混乱，考虑功能膨胀、商业约束、完整体验与设计责任。原书第6章247–255页、第7章258–281、291–298页。

- 在已有素材/功能计划里，说明效果服务哪段内容、制作与维护成本、下载和运行负担及降级方式。参考中的每个特效不必在主题中各复制一份；已选方向内优先做好有作用的部分。
- 例如一个贯穿故事的模型可以投入精力；额外物件是否需要，按情节价值和设备成本判断。检查后续换文案、素材或章节时能否维护，网络差或低性能设备仍能读完内容。
- **验证：**按实际选用的功能检查价值、成本和降级，沿用现有性能验收；不因此取消用户已要求的动效或引入未经授权的第三方服务。

## I10 直接操作，减少不必要的阻塞

**问题 / 适用：**修改名称、勾选、调整局部参数等小操作被整屏覆盖层或重复对话框打断。

- **来源观点：**Rauno在X分享了减少阻塞式覆盖层、在表单上采用直接操作的探索，这是个人设计方向，不是全面禁用dialog。
- **应用建议：**需要时在对象附近编辑并呈现结果，保留取消/撤销及真实保存状态；与I2、I5合用，不为去弹窗隐藏错误或丢失输入。
- **限制与替代：**不可逆操作、复杂流程或确需集中注意的任务仍可使用合适的模态界面；按语义、风险和设备决定，不以“直接操作”扩大Agent授权。
- **验证：**完成修改、取消、失败和返回，检查对象与结果是否对应；测试键盘、触屏与移动端，不把弹窗数量少当成自动通过。
- **来源 / 状态：**[Rauno原帖](https://x.com/raunofreiberg/status/2109991552215031963)，2026-10-20经Egolite读取文字；演示机制未逐项实测，网页做法为应用归纳。

## I11 在最终媒介中验证交互原型

**问题 / 适用：**静态稿无法判断拖拽、内容重排、场景过渡等行为，且这项不确定会影响方案。

- **来源观点：**Rauno分享，用代码在最终媒介制作原型，意外发现有时能反过来改变设计方向。
- **应用建议：**沿I7只试当前不确定的机制，复用原项目组件与技术栈，观察真实尺寸、操作和状态；先记录发现，再决定是否调整已选方案。
- **限制与替代：**成熟模式或已验证机制直接复用；不是强制把所有草图编码，不增加三个方向、网站重做或审批。低成本草图已足以回答问题时无需代码原型。
- **验证：**用明确任务操作原型，记录它实际解决哪个未知点；样机播放成功不能冒充正式页面、全设备或真人测试完成。
- **来源 / 状态：**[Rauno原帖](https://x.com/raunofreiberg/status/1911153766306308559)，2026-10-20已读文字；以上原型范围是本技能建议，本次未制作新原型。

## I12 隔离单项设计能力练习（可选训练方法）

**问题 / 适用：**用户要求学习排版、对齐、留白、配色或阴影，单看教程难判断是否掌握。

- **来源观点：**Erik建议隔离新技能反复练习；其课程作业提供接近完成的设计，让学习者只处理剩余的一类问题。
- **应用建议：**选择已有且有权使用的页面，固定其他变量，一次只练一项，例如只整理对齐线、只调整留白；比较前后并说明依据。
- **限制与替代：**这是学习/专项练习的方法，不是制作网站前必须完成的作业；“90%完成、10%练习”是作者示例，不是阶段门槛。原帖提及学习科学，本次未读其底层研究，不称已验证的科学定律。
- **验证：**看该单项是否改善及为何改善，不以练习次数或整体换皮冒充掌握；正常制作仍走当前任务范围。
- **来源 / 状态：**[Erik完整原帖](https://x.com/erikdkennedy/status/1811443710623907912)，2026-10-20经Egolite读到展开正文；本次未开展教学效果测试。
