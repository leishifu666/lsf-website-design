# 动画取证与逐帧对照

A 的核心动画与 I 复刻动画共用此工具，不另起整站流程。内置源码来自 [NiazMorshed2007/reanimate](https://github.com/NiazMorshed2007/reanimate)，保留 MIT 与版本记录；不是只引用其提示词。先确定真实目标，再使用对应脚本，避免把整个网页盲录成一个难以比较的大视频。

## 可用入口

```text
node <技能>/scripts/animation-tool.mjs doctor
node <技能>/scripts/animation-tool.mjs setup
node <技能>/scripts/animation-tool.mjs capture --help
```

`doctor` 只检查依赖；`setup` 是显式的局部依赖准备，不装全局工具。先复用可用运行时和 Chrome；细节以 doctor 输出为准。支持 `CHROME_PATH`、`LSF_PROXY`，采集条件记入证据。Windows 不运行上游 `setup.sh`。脚本在 `vendor/reanimate/scripts/`，按需可读其源文件。

A 的 scout/replay 仍使用原有 Playwright 依赖，animation-tool 的局部 setup 不代表它们也已就绪；按[原回放的依赖说明](动态输入回放.md#两侧运行)检查即可，不重复安装已有环境。

每次采集使用新目录。I 用原项目 `.reanimate/<目标>/`；A 从已有网站目录使用 `ref/animation/<行为ID>/`，与现有 source-survey 中的行为 ID 对应。现有有效录屏/资源可以直接分析，不为凑流程重采。上游脚本可能清理输出，统一入口拒绝覆盖非空输出；不绕过保护覆盖历史轮次。

## 网页：原始体验与逐帧分析

以下 `#hero`、`.title` 是占位选择器，须替换为实际已观察的元素。普通 CSS 动效无需 `--gl --assets`；Canvas、WebGL、WebGPU、Three.js 核心场景使用它们。

```text
node <技能>/scripts/animation-tool.mjs capture --url <参考URL> --out ref/animation/hero/ref-real --viewport 1440x900 --selector "#hero" --clip 0,0,1440,900 --trigger scroll --scroll-to 900 --scroll-steps 30 --scroll-ms 1800 --duration 3000 --fps 30 --track "#hero .title" --clock real --gl --assets
node <技能>/scripts/animation-tool.mjs capture --url <参考URL> --out ref/animation/hero/ref-01 --viewport 1440x900 --selector "#hero" --clip 0,0,1440,900 --trigger scroll --scroll-to 900 --scroll-steps 30 --scroll-ms 1800 --duration 3000 --fps 30 --track "#hero .title" --clock virtual --seed 1 --gl --assets
node <技能>/scripts/animation-tool.mjs gl summary ref/animation/hero/ref-01
node <技能>/scripts/animation-tool.mjs sheet filmstrip --frames ref/animation/hero/ref-01/frames --out ref/animation/hero/ref-sheets
```

先检查加载画面和最终截图，确认真正渲染了目标，不是黑屏、加载层或低能力 fallback。需要就绪条件时，按实际页面使用 `--wait-before` 或 `--pre-js`；这些会改变采样起点，须保留实际命令。窗口缩放、DPR、裁切、GPU 模式和字体必须一致。默认 selector 裁切使用采集结束时的元素框，并把该框应用到所有帧；元素会移动或滚出视口时，用固定 `--clip x,y,w,h` 覆盖整个运动范围。`--selector` 还会参与滚动起点准备，核对两侧的实际起始位置。

真实时钟采集使用浏览器录屏；视频本身约 25 fps，设更高提帧率不增加真实时间精度。虚拟时钟逐步推进主页面的时钟、rAF 和动画，每个指定时刻截图，再组装视频。`--fps 30` 是截图采样率，`--raf-hz` 是页面推进频率，两者不是同一个数。视频编码失败时检查现有帧，不能声称已生成视频。

真实时钟的 `--duration` 是输入派发完成后的观察期，提帧包含实际输入耗时；虚拟时钟的 duration 从触发点计。慢渲染可能把名义上的短滚动拉长，读取 `capture.json.realTiming` 与 `frames.json` 的实际窗口，不只看请求值。真实录屏起点仍按墙钟估计；首帧已在动画中途时增加 `--pre-roll` 并重采、目检前后状态，不用自动对齐藏掉缺失开场。

虚拟时钟有助于比较，但会改变正常调度，还会禁用浏览器合成器平滑滚动。先与真实时钟对照，再用同样条件重复采一次原站，测得自身差异；不要直接照抄“任何场景必定零误差”。Worker 的时钟、网络/服务端随机性、GPU、字体及页面变体仍可能带来差异。虚拟时钟导致页面停住时保留失败证据，用真实时钟及原站重复采样继续；不要据此判断原站没有动画。

## 实际抓到了什么

| 证据 | 抓取机制与用途 |
|---|---|
| `assets.json`、`assets/scripts/` | 监听本次浏览器真实网络响应，保存已加载的 JS；按 shader/uniform/资源名在 bundle 中定位控制代码。不是原工程仓库，也不保证有 source map |
| `assets/models/` 等 | 保存实际请求到的模型、纹理、场景等资源；核对 URL、字节、加载代码及对象绑定。未触发的懒加载、失败响应或未命中的格式要补采 |
| `gl/shaders/`、`gl/gl.json` | 页面脚本运行前注入 API hooks，记录实际 shader 源码、uniform、texture、buffer、framebuffer 与绘制状态；可追出多 pass 合成，不只猜截图 |
| `gl-track.json`、`gl/draws.json` | 每帧变化通道及 draw 顺序/数量；看滚动进度、遮罩、材质、相机和对象值怎样联动。通道确实存在时才引用 |
| `three/scene-*.json` | 通过引擎可被捕获的调试/渲染入口取得 scene、材质/几何和相关对象；并非所有封装版本都能导出完整场景 |
| `inspect.json`、`track.json` | CSS/WAAPI 动画、样式、字体/库线索、DOM 位置与变换、时间及实际 scrollY；DOM 外框不能代表 canvas 内部运动 |
| `frames/`、`frames.json`、录屏、拼图 | 同一目标的初态、全部采样中间帧、终态与回程；判断形状、遮挡、细节和技术数值是否对应实际画面 |
| `frame-state.json` | 本地适配新增：虚拟帧关联截图前实测 pageTime、scrollX/Y、URL 和截图请求/完成时间；真实视频抽帧只标注近似样本，精确逐帧字段为 null |

更多字段与引擎细节按[上游 WebGL 说明](../vendor/reanimate/references/webgl.md)读取。Canvas 2D 会记录调用计数与抽样帧调用列表；WebGPU 常是 buffer 浮点偏移，需要结合 WGSL 找语义。Worker 使用 CDP 附加并注入采样/随机种子，子 Worker、跨 iframe、私有实例不保证完整。抓不到场景树时仍可从底层绘制、源码、模型与画面建立证据，不能编造导出结果。`--gl-buffers 16` 可按需导出受限大小的 buffer，避免为了“全量”无边界抓取。

本固定版本有实际采样上限：普通 uniform 值会截断，长数组不全部成为动态通道，buffer 主要是预算内首次上传；默认最多记录 1500 帧、每帧 300 draw。长动画按保持前置状态的区段拆采。资源只覆盖本次命中的成功响应，内联/动态生成代码、失败或分片响应、未触发资源要另查；没有出现在索引里不等于不存在。GLB 的原文件继续交 `inspect-gltf.py` 分析节点与片段，运行绑定另核对。

## 滚动按位置与时间分别比较

`--scroll-steps` 把输入拆成真实滚轮事件，`--scroll-ms` 调整派发间隔，`--scroll-to` 是用来计算输入量的目标；它不保证平滑滚动最终精确停在那里。以 `track.json` 的**实际 scrollY**和画面里的场景进度为准。增加步数不等于浏览器为每一 CSS 像素绘制了新帧。

逐图定位时，虚拟帧优先读取 `frame-state.json` 中截图前实测坐标，再核对对应轨迹。真实录像的 `estimatedTrackSample` 仅近似，不冒充截图同刻的实际坐标。嵌套滚动容器与自定义章节进度用 replay 读取对应对象；`window.scrollY` 不变不能说明它们没滚动。

- 对确定性的滚动叙事，比较相同 scrollY/章节进度时主角、文字、相机、出场幕和进场幕的姿态。取关键转折附近的小步输入；定位用的 `scrollTo` 样本与真实滚轮实验分开标记。
- 对惯性、scrub 追赶、方向反转和中断，使用同一真实输入和事件后的相对时间，另跑[输入回放](动态输入回放.md)。只按最终 scrollY 对齐会掩盖错误手感。
- 上游 `compare` 默认按时间/帧比较，**不会自动按 scrollY 重采样**。滚动位置不同的帧不能直接作为姿态一致性证据；先校准输入或列出实际位置对应帧，再核对姿态与独立时间响应。
- 上游的单次 scroll 捕获不等于走完“前进、停止、倒滚、打断”的复杂状态机。分段采集并保留前置状态，复杂导航与多次输入继续用现有 replay。二者的真实输出同时进入同一行为规格。

## 对照与修正

成品沿用原命令，仅修改 URL、输出目录，以及有明确对应关系的选择器；换主题不能擅自改输入、视口、时钟和等待来凑相似帧。先用 ref-repeat 与 ref-01 做一次稳定性比较，再与 clone 比。

```text
node <技能>/scripts/animation-tool.mjs compare --ref ref/animation/hero/ref-01/frames --clone ref/animation/hero/clone-01/frames --out ref/animation/hero/compare-01 --offset 0
node <技能>/scripts/animation-tool.mjs sheet compare --ref ref/animation/hero/ref-01/frames --clone ref/animation/hero/clone-01/frames --diff ref/animation/hero/compare-01/diff --out ref/animation/hero/compare-sheets
node <技能>/scripts/animation-tool.mjs gl compare --ref ref/animation/hero/ref-01 --clone ref/animation/hero/clone-01
node <技能>/scripts/animation-tool.mjs easing --track ref/animation/hero/clone-01/track.json --selector "#hero .title" --prop translateY --compare-track ref/animation/hero/ref-01/track.json
```

这条 DOM easing 对照仅适用于两侧都有相同 selector 名。该 CLI 没有独立的参考 selector 参数；名称不同时分别拟合两侧并按规格里的对象映射核对，或从保留原文件的轨迹另产明确映射副本，不向空轨迹强行比较。GPU 通道映射使用 gl compare 的实际 `--map`。

`--offset 0` 保留真实触发延迟。自动对齐可用于分析，但报告原始与对齐后的时间差，不能把迟到藏掉。`setupWarnings`、覆盖帧数、`pass`、最差帧和实际对照图一起看；上游像素 compare 的退出码 0 只表示报告写成。工具会自动缩放尺寸不同的成品帧，需先重采相同尺寸，不能用缩放后的数字验收布局。空白、截断、双方都没有运动、通道没有匹配或只有少量帧重叠均不能称为完成。

在 A 或 mixed 中，中文和长沙资产改变像素是正常的。整体像素差保留为诊断；对未替换的控件、布局与效果区域比较像素，对主题主体比较轮廓占幅、图层、材质/光照关系、交接机制、输入到通道的轨迹。先列明主题适配，不可把配色、按钮或层次失真都归为换主题。`gl compare --map` 用明确的语义映射对齐命名，不把缺失的原站关键通道排除后宣称通过。顶点计数与原素材不同可以解释，缺少模型/两幕/合成 pass 不可以仅凭解释验收。

`gl compare` 的设置/绘制结构差异主要是诊断列表，退出码不能覆盖它们；持续 `clock` 通道另查速率与周期。没有有效通道时不能验收。`inspect.json` 的一次动画快照也可能漏掉已经结束的 CSS transition，使用现有 replay 的运行中 WAAPI 记录补齐。

两幕溶解至少看出场幕、进场幕、遮罩与合成输出，不能拿整张画淡成纯色代表。模型同样同时看几何、相机、材质与可见轮廓，不能仅用“已导入 Three.js”作证。直接源码、实测轨迹、拟合 easing、未知项按原四种等级写进规格。

## 接回 A 的已有台账

`source-survey` 的行为继续指向实际采集文件。`assertions.source.file` 可以引用 shader/JS 的真实 `excerpt` 或 JSON 的真实 pointer；逐帧 uniform/对象值标 `measured`，从 bundle/模型直接读取的常量标 `direct`，拟合结果标 `fitted`。成品侧引用另一采集目录的对应值，保留 capture 参数、原始录屏与映射。JSON pointer 含通道名里的 `/`、`~` 时按 JSON Pointer 规则转义。

旧的 `source → prototype → paired` 不变；无需另造一套打分、审批或模型评审。来源脚本允许读取很多状态，但“工具运行过”不等于已看全：只对实际查看、实现和比较过的行为标记已验证。

## 文件动画与边界

```text
node <技能>/scripts/animation-tool.mjs frames --in <本地视频> --probe
node <技能>/scripts/animation-tool.mjs frames --in <本地视频> --out .reanimate/clip/ref/frames --fps 25 --start 0:03 --end 0:05 --crop 0,0,1280,720
```

先看片段与裁切，再读全部目标拼图。视频缩放后的像素换算为 CSS px；GIF 时间精度受原始帧延迟限制。Lottie 的实际关键帧可直接读取；Rive/其他二进制文件先用对应运行时或现有录屏观察，不承诺任意文件都能解析。网页只有截图时无法还原时间关系，继续分析可见部分并标明缺口。

原站公开 JS/模型的技术可读性不等于它们都获得 MIT 授权。内置工具的 MIT 与抓取网站的资源权利分开；在已获授权范围内复用原资源，主题成品保留自己的内容及资产。不要把研究下载的原站全量素材混进技能发行包。
