# 排版细节：断行、对齐（2026-10-19 核对）

AI 做页面最常见的两个细节错误：一个词被拆到两行、元素差几像素没对齐。两者都用脚本查，不靠肉眼。

## 1. 断行

### 现象
- 中文标题「手工拉坯的日 / 用陶瓷工作室」：「日用」被拆开。中文默认可以在任意两个汉字之间换行，浏览器不知道哪几个字是一个词。
- 最后一行只剩一两个字（孤字）。
- 标点跑到行首。

### 规则
1. **标题、按钮、标签、导航、卡片标题**（短文本）：不允许词被拆开，不允许孤字。
2. **正文段落**：中文正文在字间换行是正常排版，不强求按词断；只要求最后一行不是孤字（用 `text-wrap: pretty`）。
3. 不靠手动 `<br>` 控制断行：换个视口宽度就错。要固定断点，用 `<wbr>` 标出允许断开的位置。

### 修法（按优先级）
| 场景 | 写法 | 依据 |
|---|---|---|
| 中文短标题 | `word-break: keep-all` + 在词与词之间插 `<wbr>`，再加 `text-wrap: balance` | MDN：`keep-all` 时 CJK 文字之间不再断行，只在空格、标点和 `<wbr>` 处断。https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/word-break |
| 自动插 `<wbr>` | 构建时或组件里用 `Intl.Segmenter('zh', { granularity: 'word' })` 分词，把词用 `<wbr>` 连起来（见下方组件） | MDN Intl.Segmenter：可按词切分不用空格分词的语言，Baseline 2024。https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter |
| 标题行长不均 | `text-wrap: balance`（Chromium 只对 6 行以内生效） | MDN text-wrap-style。https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-wrap-style |
| 正文孤字 | `text-wrap: pretty` | 同上 |
| 品牌名、产品名、数字+单位 | 包一层 `<span style="white-space: nowrap">` | 【归纳】 |
| 日文 | `word-break: auto-phrase`（需要 `lang="ja"`，Chrome 119 起）。**目前只支持日文，中文无效** | Chrome 官方博客 https://developer.chrome.com/blog/css-i18n-features |

```jsx
// 中文短文本按词断行：<Phrase>手工拉坯的日用陶瓷工作室</Phrase>
const seg = new Intl.Segmenter('zh', { granularity: 'word' });
export function Phrase({ children, as: Tag = 'span' }) {
  const parts = [...seg.segment(String(children))].map(s => s.segment);
  return <Tag style={{ wordBreak: 'keep-all', textWrap: 'balance' }}>{parts.flatMap((p, i) => i ? [<wbr key={i} />, p] : [p])}</Tag>;
}
```
分词器会把一些词切得更碎（实测「拉坯」被切成「拉|坯」），关键标题人工检查一次，必要时手写 `<wbr>`。

### 反例：改容器宽度不算修好
把标题容器从 255px 加宽到 420px，「日用」不拆了，但换成「手工拉坯的日用陶瓷工 / 作室」，把「工作室」拆开了。宽度一变、视口一变，断点就跑到别的词上。修法只能是 `keep-all` + `<wbr>` 标出允许断开的位置（实测改成「手工<wbr>拉坯的<wbr>日用<wbr>陶瓷<wbr>工作室」后，375 / 768 / 1440 都断成「手工拉坯的日用 / 陶瓷工作室」）。

### 检查
`node scripts/check-text-wrap.mjs <本地地址> --viewports 375,768,1440`：逐字读出每一行，用 Intl.Segmenter 判断断点是否落在词中间，并查孤字、行首标点，每处截图（红框）。
实测（2026-10-19）：255px 宽的 40px 标题「手工拉坯的日用陶瓷工作室」报出「日用」被拆开；同一句改成 `keep-all + <wbr> + balance` 后通过。
注意：服务器上没有中文字体时汉字不会正常排版，检查前要装好页面用的字体。

## 2. 视觉对齐

### 规则【归纳】
1. 同一区块里，文字、图片、按钮、卡片共用少数几条对齐线（左边缘、右边缘或中线）。
2. 量的是**看得见的边**：文字按字形实际左边缘，不按盒子；带内边距的按钮按按钮外框。
3. 小幅几何偏差先核对共用对齐线、组件内边距和光学原因；脚本发现的1～6px偏差是排查线索，不能仅凭数值判错。没有设计依据的偏差统一修正，有意错位或光学修正保留理由与对照证据。
4. 光学修正是例外：圆形、三角形图标、引号、大号标题首字母，可能需要向外挪 1～3px 才“看起来”对齐，修正值写进设计说明。

### 常见原因【归纳】
- 卡片有 `padding`，卡片外的标题没有，两者文字差一个 padding。
- 按钮文字和上方段落文字左对齐，但按钮外框没对齐（或反过来），要先定“对哪条边”。
- 图片自带透明留白，图片盒子对齐了，主体没对齐（透明素材先用 `process-image.mjs` 裁掉透明边）。
- 混用 `margin` 和 `gap`，或不同组件各自写死左边距。

### 检查
`node scripts/check-alignment.mjs <本地地址> --viewports 375,1440 [--tol 6]`：每个区块里找出现最多的对齐线，报出和对齐线差 1～6px 的元素，并输出整页截图（蓝色虚线 = 对齐线，红框 = 没对上）。实测：故意多写 3px 左边距的段落被报出“左边缘偏 3px”。

## 3. 网络字体与备用字体的度量匹配（2026-10-19 补充）

**问题 / 适用**：备用字体与品牌字体的宽度、行高、基线不同，网络字体切换后可能改变断行和周围布局。外观相似不能代替度量匹配；沿用项目字体加载策略，为具体字体对校准。

**做法**：本地备用字体单独声明 font-face，用 size-adjust 缩放字形及相关度量，再用 ascent-override、descent-override、line-gap-override 校准行度量。品牌字体排在调整后的备用字体之前，并保留通用后备。

```css
/* 用户提供的示意数值：必须针对实际字体对重新测量。 */
@font-face {
  font-family: "Brand Fallback";
  src: local("Verdana");
  size-adjust: 87.6%;
  ascent-override: 95.2%;
  descent-override: 24.1%;
  line-gap-override: 0%;
}
h1 { font-family: "Brand Font", "Brand Fallback", sans-serif; }
```

**限制与替代**：一个比例不能保证所有字符、字号、字重、语言和可变字体轴同宽；中文回退还可能按字形分拆。Verdana 并非每个平台都有。不承诺“0px 偏移”，没有真实品牌字体时不生成伪测量参数。

**来源与验证状态**：已核对 [web.dev size-adjust](https://web.dev/articles/css-size-adjust) 与 [字体造成的 CLS](https://web.dev/articles/optimize-cls)。这组示例未针对品牌字体实测。项目使用时在冷缓存、限速与加载失败下比较标题/正文断行、盒子尺寸和 CLS，覆盖实际语言与字重；不能凭一次截图或 font-display 声称零偏移。

## 4. 感觉不协调时，先只调整间距

**问题 / 适用**：组件、字体和颜色看起来都合理，整体却显得挤、散或不协调，暂时找不到具体原因时，先做一次只改间距的对照。它是排查方法，不代表所有视觉问题都由间距引起。

**做法**：

1. 保留当前截图或版本。在相同视口、内容、组件、字体、字号、颜色和交互状态下比较，不同时换皮肤、图标或布局结构。
2. 先查容器内边距（`padding`），再查元素和分组之间的间距（`gap`，必要时调整`margin`）。复用已有间距令牌；模式A按参考实测值检查，不另套固定数列。
3. 每轮围绕一个间距问题调整，例如内容太贴边、标题与正文脱节、不同消息组挤在一起。保持同组与组间的距离有区别，不把所有空隙统一成一个值，也不一律增加留白。
4. 对比改前与改后：内容分组是否更清楚，对齐线是否一致，阅读节奏和空间密度是否更合适。间距调整没有改善时，再检查字体、颜色、层级或结构，不继续盲目加大数值。

**聊天窗口示例**：保持同一组消息、头像、气泡样式、字体和颜色，只调整气泡内边距、同一发言人的消息间距、不同发言人的组间距以及输入区内边距。观察信息是否更容易分组、消息是否仍易读；不把这个示例变成所有组件的固定参数。

**限制与验证**：已有明确的内容、对比度或交互问题时，按证据处理，不强制先改间距。实际修改页面后，在同条件下查看受影响区块，检查换行、溢出和控件位置，并按修改范围核对响应式状态；截图可帮助比较，不能代替真实阅读和操作。仅收录本技巧时不启动网站制作或增加评审轮次。

**来源与验证状态**：用户于2026-10-19提供“同一聊天窗口、字体和颜色，只改变内边距与间距”的设计技巧；上述排查步骤为本技能应用归纳，未在本次对具体页面实测，不另归给某本书或作者。

## 6. Craft：数字、光学对齐与字体渲染（2026-10-28）

以下依据 Gustavo Fior 的 Craft 已发布文章整理；这是按场景选用的技巧，数值是文章示例而非通用标准。本次阅读了文章文字与示例代码，未在本机实际网页或各系统复现。

### 6.1 数字稳定与纵向扫描

- **问题 / 场景**：计时器、计数、实时指标变化时，比例数字宽度不同可能让邻近内容跳动；表格数字不易逐位比较。
- **做法**：变化数值或表格数字列使用 `font-variant-numeric: tabular-nums`，数字列右对齐；正文中的数字可保留比例数字，不必为了等宽数字把整段改成等宽字体。
- **限制 / 验证**：所用字体须支持 OpenType `tnum`，不生效先检查实际字体文件；分隔符、符号和小数位未必等宽，右对齐与小数位格式仍应按内容设计。使用真实数值、不同位数、负数和加载状态核对跳动与对齐。来源：[Tabular Numbers](https://craft.gustavofior.com/tabular-numbers)。

### 6.2 看视觉重量，而非只看盒子

- **问题 / 场景**：播放三角、星形、下载图标及带图标按钮即使几何居中，也可能视觉偏移；引号可能使段首看起来缩进。
- **做法**：分别查看每个图标、其透明留白与容器内边距，必要时微调个别图标位置或图标侧内边距；可在检查器暂时模糊图形，看视觉重心后与原样对比。引号悬挂可按支持情况用 `hanging-punctuation: first`；固定开头字符才考虑经过实测的负 `text-indent`。支持光学尺寸轴的字体可检查 `font-optical-sizing: auto` 的实际效果。
- **限制 / 验证**：不把某个图标偏移值复制到所有图标，不机械负缩进所有语言；检查实际字号、图标、字重及不同视口。来源：[Optical Alignment](https://craft.gustavofior.com/optical-alignment)；与第2、5节合用。

### 6.3 深色界面字体平滑

- **问题 / 场景**：作者观察到 macOS 深色背景上的浅色字可能显得更粗；可针对实际字体比较默认渲染与 `-webkit-font-smoothing: antialiased`。
- **限制 / 验证**：这是非标准属性，平台、浏览器和显示器效果不同，不能称为跨平台修复，也不默认全局启用；细字重在灰阶平滑后可能变得难读。对目标 macOS 浏览器、深浅主题、实际字重及普通/高分屏比较，保证可读性；不以其他平台无差异证明效果。来源：[Font Smoothing](https://craft.gustavofior.com/font-smoothing)。
