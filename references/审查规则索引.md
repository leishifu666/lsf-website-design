# 审查规则索引

本文件是评审规则的读取指引，不是额外评分表。固定提示词要求先核对当前规则和适用范围，再看页面证据；不要通读所有资料或凭记忆引用。

## 每次都要有

- 用户当前要求、项目适用AGENTS/AGENTS.override、DESIGN.md及目标卡。主Agent在prepare-review前整理实际适用的项目内skill规则与组件合同，必要时用`.lsf/review-rules.json`列出；生成包包含这些文件的正文及来源。不能只说“参考项目skill”。
- [评审共用约束](评审共用约束.md)与本轮制作模式对应的[适用口径](评审适用范围.md)、[独立评审固定提示词](../templates/独立评审固定提示词.md)、[五维评分表](../templates/评审评分表.md)、[unslop方法](unslop-审查法.md)、[评审策略](design-review-policy.json)。
- 当前375/768/1440截图与可消费的动效/交互证据；缺失按evidence_gaps记录，不把截图或文件存在当成已经看过。

## 按模式与问题补读

| 需要判断什么 | 对应规则 |
|---|---|
| 模式A是否沿用真实渲染、资源和核心驱动 | [风格还原](风格还原.md)、[技术/公开代码取证](参考取证与组件规格.md)、项目reference-spec与组件合同 |
| 原创方向与产品记忆点 | [五站调研与记忆点](五站调研与记忆点.md)、[从零型与找参考](从零型与找参考.md)、项目DESIGN.md |
| 字体、断行、对齐、层级、间距 | [排版细节](排版细节.md)、[设计原则库](设计原则库.md)相应章节 |
| 动效、滚动、打断、状态与触屏 | [GSAP分工](GSAP动效联动与审查.md)、[交互动效](交互动效.md)、[滚动叙事](滚动叙事.md)、[交互设计](以人为中心的交互设计.md)相关小节 |
| 图片、透明边缘、材质、模型和图层 | [氛围图片](氛围图片.md)、[特殊渲染](特殊渲染.md)、[图标插画](图标与插画.md)及项目素材计划 |
| 通用模板感和机械套路 | [反套路清单](反套路清单.md)；A不因参考本来使用某手法就扣套路分 |
| 成品文案冗余、文字与模块的边界 | [文案审核第6节](文案审核.md#6-成品页面冗余审核page模式)、项目page-review结果；不代替独立视觉判断 |
| 用户明确要求获奖打磨 | [获奖标准](获奖级品质标准.md)，不自动启用额外预算 |
| 其他收藏的方法 | 先查[资料索引](资料索引.md)，只读取与具体问题相关的原条目 |

审查包按`--design-mode A|B|C`或流程中的design_mode加载对应章节；模式未知按目标卡核对，不默认原创。整份建站入口不再自动注入，制作细节仅在具体问题命中时补读，完整项目规则正文仍保留。

每项意见在现有evidence/deductions或问题字段里注明规则文件与条目、实际视口/状态和证据。用户偏好、原始规范、从业者建议、推断分别说明，不把技巧升级为硬门槛。性能、加载、包体不计设计分；未知和未验证不得写成通过。


每轮同读[视觉评审浏览器取证](视觉评审浏览器取证.md)和[外部视觉评审](外部视觉评审.md)：Ego Lite实测与截图、Gemini/Claude评分及有依据的当前模型备选。趣味交互按[选型与输入反馈](趣味动效与交互选型.md)检查，图标按最新开源库要求判断。
