# A风格参考：统一制作提示词

这是用户确认的A模式制作提示词，供直接制作与三预览流程共用。只填写用户主题、主参考完整网址和本次范围，保留下面的共同规则；不预先指定构图、传达策略、素材内容或具体交互方案。主Agent不把模板另行改写成三份设计任务。

## 统一正文

```text
调用 $lsf-web-replica，在现有项目按 A 风格参考制作网页。
主题：{用户主题}　主参考：{完整网址}　范围：{一套网站或一个方向预览}
以同视口 1:1 像素级布局和动态行为一致为对照目标。标出主题、中文排版或无障碍适配的局部差异，按实际证据说明达到的程度。
直接制作时由当前主 Agent 负责；用户明确要比较时才分成三个同提示词预览，每位构建者只完成本次范围。

制作前先用 Playwright 打开主参考。用 start-reference.mjs 登记目标，生成真实的页面、区块及入口清单。先在入口、代表章节、详情、返回、结束处走一遍，再逐区块深入。沿导航、页脚、列表、卡片、锚点、菜单、弹层追踪站内去向。外部链接止于边界；相同模板列出实例和有差别的状态，无限列表记录边界并确认影响范围的部分。无头浏览器显示加载页或降级版时，用有界面浏览器复核实际渲染路径。

先发现原站的行为，再确定设计和技术。下面六类都要实际检查；每个发现的行为分配 ID，记录页面/区块、目标或图层、输入和前置条件、初态/过程中/终态、触发阈值、时长/延迟/缓动、退出/反向/重复/中断、响应式差异和证据位置。
1. 首次进入与加载。分别看冷启动、图片/视频/字体准备好、刷新、站内返回，检查加载层、文字分组和图层入场顺序。
2. 滚动与视差。从顶到底再回来，试慢滚、快滚、停住、倒滚；查真正的滚动容器、sticky/pin、吸附、横向段、前后景速度、惯性追赶、目录和配色变化。
3. Hover 与按钮。查容器、子元素、::before / ::after。试进入、停留、未结束便离开和再次进入，以及按下、焦点、选中、禁用；测字组、填充、遮罩和图标的独立时序。
4. 指针。试缓移、骤停、转向、快速跨元素、移出窗口，观察光标和目标是否分别发生直跟、插值、弹簧或拖尾。比较触屏替代。
5. 组件。实际打开并关闭菜单、抽屉、弹窗、标签、手风琴、轮播及视频控件；测试遮罩、滚动锁、焦点归还、Esc、外点、拖动和快速重复。
6. 页面切换。实际点站内链接并返回，分别核对直接访问、刷新、前进后退、连续导航。记录旧画面退出、新画面进入、共享元素、URL 更新和滚动恢复的先后与重叠。

访问每个不同区块，保存代表状态截图、DOM 父子树、实际文案、素材所在层、字体、可读 CSS 声明/变量/媒体查询/关键帧，同时保留 computed style 和 getBoundingClientRect()。量标题、按钮、目录与主角在画面中的位置、大小、留白、按钮多态、配色和可见边界。把实测值连同视口、缩放、输入和时间一起记下。证据标明直接读取、重复实验测量、采样拟合、尚未确认。行为状态只用“未检查、已确认无此效果、已测量、已实现、已验证、受阻”。缺证据时保留缺口；“已确认无此效果”须附实际操作和观察。

固定视口、DPR、缩放、设备输入、字体/资产就绪条件、起始滚动与 reduced-motion 偏好。用相对输入时间对齐多次实验，先定义实测容差，再比两侧。正常、触屏、键盘、减动效和渲染降级分别记录。

遇到 Canvas、CG、WebGL 或视频合成，定位实际资源和运行对象。分清背景、主角、前景、文字、道具；查模型/骨骼/材质、相机、灯光、动画轨、滚动映射、两幕渲染与转场遮罩。看它们在中途停住或倒滚时如何遮挡、怎样交接。原资产可用时先以原件跑通；需更换的对象按同一结构和精度制作。为每个主题替换说明保留什么。可以换人物身份、城市和语言；主角占幅、动作、明暗关系、景深、时序和输入反馈须有原站依据。原站没有的效果不自行添加。

先锁定 source，再在真实页面做一段能操作的关键样段。以同视口、同输入序列复演两侧，比较起点、中途、结束和适用的反向/打断；关键交接读两边的输出。prototype 通过，再展开其他章节、素材和文案。每个区块按观察 → 规格 → 实现 → 静态与动态并排对照推进。只在看到了差异并修复或记录明确的适配理由后标“已验证”。最终完成 paired 及正式评审。只交付已有证据支持的完成程度，列明仍受阻的区块。
```

## 填写与分流

- 普通参考制作默认填写“直接制作一套网站”，由当前对话的主Agent直接完成，不另开用户聊天或派出构建Agent。用户给网址并说“按这个做”时直接制作，不额外让用户比较三版。独立文案审核与视觉评审仍按既有职责执行。
- 用户明确选择先比较三个预览时，三份都填写“完成一个方向预览”；完整正文、主题、网址和执行范围逐字相同。每位构建者只完成一个预览，不在子任务中再次启动三预览。
- 主题使用用户原话；没有提供主题就省略主题行，不另造品牌定位、营销目标或业务事实。网址沿用用户指定的主参考；没有指定时先按A的研究规则选定一个，三份仍使用同一网址。
- 不在正文之外为三个构建者追加不同的设计任务、暗示、种子、参考站、图片要求或差异指标。文件隔离与共同质量规则由主流程统一管理，见[预览分流](../references/三方向预览与确认.md)。
- 用户的明确约束和技能禁用项优先；参考交互包含禁用hover效果时按技能适配。实际取证、源码与资源许可、真实生图和验证继续执行，不为追求外观而越过授权。

## Shopify填写案例

下面展示不同用户任务的填写方式，正文一律复用上方模板，不从案例补写额外设计要求。[Shopify Editions Winter ’26](https://www.shopify.com/editions/winter2026)仅作示例网址，实际任务使用用户给定的完整网址。

| 用户输入 | 主题字段 | 本次范围 | 主参考网站 |
|---|---|---|---|
| “参考这个网站做一个AI知识库网站” | AI知识库 | 直接制作一套网站 | https://www.shopify.com/editions/winter2026 |
| “主题是AI知识库，先让我看三个预览” | AI知识库 | 完成一个方向预览；同一正文复制三份 | https://www.shopify.com/editions/winter2026 |
| “按这个做精品咖啡品牌网站” | 精品咖啡品牌 | 直接制作一套网站 | https://www.shopify.com/editions/winter2026 |
| 只给网址并说“照这个做” | 省略主题行 | 直接制作一套网站 | https://www.shopify.com/editions/winter2026 |

这是建站任务提示词，不是图片生成提示词；实际生图的每一条请求仍必须使用技能规定的固定画质结尾。
