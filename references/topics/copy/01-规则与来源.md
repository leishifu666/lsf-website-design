## 2. 网络资料

| 资料 | URL | 读到的要点 |
|---|---|---|
| NN/g《Concise, SCANNABLE, and Objective: How to Write for the Web》1997 | https://www.nngroup.com/articles/concise-scannable-and-objective-how-to-write-for-the-web/ | 81 名用户三项研究。用户扫读，不逐字读；讨厌 marketese。同一网站：简洁版（字数约为对照组一半）可用性 +58%，易扫读版 +47%，客观版 +27%，三者合并 +124%。用户先读每段第一句，所以一段一个意思、主题句在前；喜欢倒金字塔（结论在前） |
| NN/g《How Users Read on the Web》 | https://www.nngroup.com/articles/how-users-read-on-the-web/ | 79% 用户扫读，16% 逐字读。要求：关键词高亮、有意义的小标题（不要“巧妙”的）、列表、一段一意、结论在前、字数为传统写法的一半或更少。宣传腔增加认知负担：用户读到“享誉国际的景点”先在心里反驳 |
| NN/g《Cringeworthy Words to Cut from Online Copy》 | https://www.nngroup.com/articles/cringeworthy-words/ | 删 utilize（用 use）；删 enables / allows you to（改写成用户能做什么）；删 very/really/extremely；删 “We understand that…”“In today's fast-paced world…”（改成事实）；删 end user |
| GOV.UK《Writing for GOV.UK》（content design 手册，2023-11-30 版，Wayback 存档） | https://web.archive.org/web/20240118103840id_/https://www.gov.uk/guidance/content-design/writing-for-gov-uk | 只发布用户完成任务需要的内容；短句、小标题、常用词；超过 25 词的句子检查能否拆开；段落不超过 5 句；标题 ≤65 字符；摘要 ≤160 字符；首段不重复摘要；倒金字塔；不要“Introduction”小节；不用 FAQ；小标题不用问句；“emotionless – adjectives can be subjective and make the text sound more emotive and like spin”；“-ion/-ment”词让句子变长；每多 100 词理解压力增加 |
| GOV.UK《Use clear language》（现行版） | https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/ | 同上 25 词、5 句；避免 buzzwords，“把这个词拆成你实际在做的事”；可选的事用 can，不用 may be able to；主动语态，列出被动可用的两种情况 |
| GOV.UK Design System《Error message》 | https://design-system.service.gov.uk/components/error-message/ | 说清发生了什么、怎么改；不用技术术语、forbidden/illegal/you forgot、please、sorry、valid/invalid、oops；屏幕上已有示例就不在报错里重复；报错用词沿用字段标签；不同错误不同提示，避免“This field is required”这类泛化提示；保留用户已填内容 |
| Mailchimp《Writing Goals and Principles》 | https://styleguide.mailchimp.com/writing-principles/ | Clear / Useful / Friendly / Appropriate；“Don't market at people; communicate with them”；“Avoid dramatic storytelling and grandiose claims” |
| Mailchimp《Voice and Tone》 | https://styleguide.mailchimp.com/voice-and-tone/ | Plainspoken：去掉夸张、加价推销、过度承诺；避免 fluffy metaphors、cheap plays to emotion；“always more important to be clear than entertaining”；不要硬凹幽默 |
| Mailchimp《Web Elements》 | https://styleguide.mailchimp.com/web-elements/ | 按钮必须含动词、简洁；表单尽量短；不用“Click here”；标题、小标题放主题关键词 |
| Mailchimp《Writing for the web》 | https://styleguide.mailchimp.com/writing-for-the-web/ | 404，读不到 |
| Google developer documentation style guide《Voice and tone》 | https://developers.google.com/style/tone | 避免：buzzwords、占位短语（please note、at this time）、所有句子同一开头、感叹号、let's、在步骤里用 simply/It's easy/quickly；指令里不用 please；三栏示例（太随意/刚好/太正式） |
| Google《Avoid excessive claims》 | https://developers.google.com/style/excessive-claims | 不用 best、simplest、fastest、never、always；ensure、guarantee 只在真能保证时用；性能数字要给来源；安全宣称改成“helps with / designed for” |
| Microsoft Style Guide《Top 10 tips》 | https://learn.microsoft.com/en-us/style-guide/top-10-tips-style-voice | Bigger ideas, fewer words；Get to the point fast（关键词前置）；Be brief；删不必要的 you can；避免 there is/there are；多数句子以动词开头 |
| digital.gov《Writing for understanding》（原 plainlanguage.gov 内容迁移） | https://digital.gov/guides/plain-language/writing | 主动语态、现在时；hidden verbs：conduct an analysis of → analyze；识别方法：-ment/-tion/-sion/-ance 结尾，或与 achieve/effect/give/have/make/reach/take 连用 |
| plainlanguage.gov 原 guidelines | https://www.plainlanguage.gov/guidelines/ | 已跳转到 digital.gov 系列索引页，原全文只在 GitHub 存档，本次未读 |
| Ant Design《文案》规范（中文） | https://ant.design/docs/spec/copywriting-cn | 以用户为主体，不写“我们为你提供”；省略无用词汇，不重复用户已知事实；不用生僻、过于“文雅”的词；同一事物用词统一；重要信息放最前；报错说清下一步；用“你”不用“您”；不同时混用“你”“我”；不用“不能/不要/请勿”式命令；不用“绝不”等极端说法；标签、标题、输入框提示、按钮不加句号；谨慎用感叹号；全角半角之间加空格 |
