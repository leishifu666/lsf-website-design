# GSAP 动效联动与审查

用户于2026-10-19明确指定：任何内容（包括组件、图标、交互）都要添加动画并审查，页面动画使用已安装的 GSAP 技能制作。这是本技能网站制作的执行要求，不仅是可选技术建议；仅讨论或更新技能不实际启动网站动画制作。

2026-10-31更正：所有模式先按[表现技术选择](特殊渲染.md#01-所有模式先选表现技术再制作)选定真实表现机制。GSAP承担适合的编排与属性驱动，可以配合Canvas、Three.js/WebGL及shader，不能替代它们；模式A沿用参考核心渲染、时间线/状态机与合成机制，不强制统一迁移到GSAP。本更正优先于旧“整页由GSAP包办”的表述。

## 当前设计优先级

按用户最新更正：当前只看设计感、美感及动效视觉表现，性能不占分、不作硬门槛，不因性能指标削减动画。禁用按钮hover整体上浮、hover图标平移/旋转/缩放/弹跳。组件先按[组件书签与源码复用](组件书签与源码复用.md)取实际源码，不用通用上浮或图标摆动充数。

## 1. 先列清单，再按需联动

每次制作先查项目组件、设计令牌、现有动效预设和依赖。复用已有结构，明确GSAP、渲染循环、模型动画或状态机各自负责什么，避免多个系统同时控制同一属性。按实际需求读取技能，不一次加载全部家族：

| 用途 | 技能 |
|---|---|
| 页面元素、组件、图标、hover/按压/状态反馈与缓动 | [gsap-core](../../gsap-core/SKILL.md)，必读 |
| 开场、多元素协同、交错、菜单/弹窗进退场 | [gsap-timeline](../../gsap-timeline/SKILL.md) |
| 章节、滚动推进、scrub、pin、倒滚和锚点状态 | [gsap-scrolltrigger](../../gsap-scrolltrigger/SKILL.md) |
| 用户明确要求后期性能优化 | [gsap-performance](../../gsap-performance/SKILL.md)，当前设计阶段不默认调用、不用于设计评分 |
| React 的作用域、卸载与 Strict Mode | [gsap-react](../../gsap-react/SKILL.md) |
| Vue/Nuxt/Svelte 等生命周期 | [gsap-frameworks](../../gsap-frameworks/SKILL.md) |
| Flip、Draggable、路径等真实需要的插件 | [gsap-plugins](../../gsap-plugins/SKILL.md) |
| 进度映射、吸附与插值工具 | [gsap-utils](../../gsap-utils/SKILL.md) |

技能提供实现方法，不扩展为无关重构、额外方案、全局配置或自行发布。用户后续明确改变技术选择时按新指令执行。

## 2. 覆盖全部内容类别

在已有设计/素材文档中维护动效清单，每项写：**元素或组件 / 触发方式 / 帮助理解的变化或营造的体验 / 开始与结束状态 / 实际驱动（GSAP tween/timeline或核心场景的时间线/状态机）与渲染对象 / 时长与缓动来源 / 可打断或反向行为 / 移动端与减少动态效果 / 实测证据**。

- 页面内容：首屏、标题、正文组、图像/场景、章节过渡、页尾均有适合主题的动效编排；不要整页机械复制同一个fade-up。
- 组件：卡片、导航、按钮、表单、标签、进度条、列表、菜单与弹窗覆盖实际存在的进入、退出及状态变化。
- 图标：与所属操作或组件联动，例如点击展开旋转、完成勾选、下载回执；hover不带动图标运动；不让每个图标无目的地持续旋转。
- 交互：鼠标、点击、触屏、键盘、选择、撤销、加载、成功/错误等实际状态都有可见反馈。键盘和高频输入保持即时响应，不等待装饰动画才完成操作。

“所有内容有动画”要求逐项设计和验证，不要求所有元素同时动或永久循环。文字可以按语义组编排；保持正文阅读停顿、控件可点击、焦点可见和减少动态效果的静态/短淡化替代。不能拿降级需求为由省略正常模式动效。

状态反馈要说明发生了什么：按压回弹不能代替提交结果，错误抖动不能代替原因与下一步。装饰场景可提供吸引力，交互动画支持操作掌控，结尾编排可以呼应体验；无需给每个控件拆三套动效。需要判断时查 [以人为中心的交互设计](以人为中心的交互设计.md) I2、I6。直接操作及时响应，叙事场景的延迟跟随仍按参考证据和阅读效果判断，不从心理学原则猜技术参数。

## 3. GSAP 作为实际驱动

- GSAP负责的页面层使用真实tween、timeline、ScrollTrigger等；只引入库不算联动完成。场景引擎自己的渲染循环、模型求值及模式A沿用的参考核心驱动不必改成GSAP，也不能冒称由GSAP驱动。
- CSS负责布局、静态起止状态与无脚本降级；不要与GSAP争用同一transform/opacity。场景参数由合同指定的控制者更新，外围编排可以接入GSAP；渲染器与时间线分工明确。
- 视觉移动/缩放优先用GSAP的`x/y`、`scale`等transform属性，避免以`left/top/width/height`逐帧模拟同样运动；真实布局变化、缩放变形及主线程限制见[交互动效K节](交互动效.md)。这是属性选择建议，不改变GSAP要求、禁用hover或当前美学评分范围。
- 模式A的参考时长、缓动、滚动关系继续取证并沿用真实核心机制；不能因熟悉GSAP改写参考的核心时间线/状态机，更不能把实时模型或shader降成DOM位移。具体见[取证第4.1节](参考取证与组件规格.md#41-核心场景的渲染技术与公开源码取证)。
- 用timeline编排顺序与交错，用overwrite或复用timeline支持中途反向；高频指针使用quickTo等复用机制，避免每帧创建新动画。
- 通过matchMedia/context和框架生命周期管理清理；减少动态效果时取消非必要长位移、视差、循环及滚动追赶。无脚本或库加载失败时保留可读正文与可用的基础流程。

## 4. 主 Agent 自查与独立动画评审

主 Agent 满意后，动画证据与页面证据一起交给本轮全新的独立评审子 Agent。静态截图不能证明动画完成；提供实际操作、关键状态截图/录屏及检查结果。评审至少检查：

1. 清单覆盖是否完整：内容、组件、图标、交互状态是否遗漏；选定的渲染与驱动技术是否真实工作，GSAP负责的部分是否真正驱动。模式A核对实现机制合同，图片近似不能代替真实场景完成。
2. 节奏与层级：清单写明的信息作用或体验是否成立，操作结果是否能看懂；触发是否合理，是否有阅读停顿、交错和前后景关系，是否阻挡操作或过于喧闹。深浅场景交界时，逐项检查固定导航和焦点实际所在区域的对比度；不能只按页面顶部判断整组导航颜色，也不能用初始axe结果代替滚动状态检查。
3. 连续与可打断：全新页面的首次打开、关闭、再次打开均逐项检查，再测快速重复点击、hover进出、开关反转、倒滚、跨章节与锚点直达是否出现跳变、闪烁或状态错乱。GSAP活动tween或清单登记不能单独证明播放；至少核对实际中间帧的属性变化，防止CSS先设成终点导致零位移的空动画。
4. 输入与降级：375/768/1440、触屏、键盘、减少动态效果及刷新恢复状态是否成立；动态切换减少动态效果与恢复普通模式时，保留当前阅读位置和可见焦点，不以“活动动画已清零”代替上下文连续性检查。除稳定状态外，还须在旋转、填充、回弹、菜单/弹窗进退场中途切换：清理本页拥有的活动反馈，静态收束到正确业务终态；检查是否只移除了ScrollTrigger却遗漏事件中新建的tween。恢复后新操作必须可重新播放，减少动态效果下的pointerleave等输入也不得重新创建非必要动画。
5. 视觉审美：检查构图、时序、缓动、层次和主题表现，以及是否混入两类禁用hover。生命周期、减少动态效果与清理另作基本功能记录，不换成性能分或以指标要求减少正常模式动画。

动画评审并入同一次网站主审，不另加Agent或调用。主Agent核对后集中修改，再按需由全新Agent定向复核；默认两次总调用、一批修改，首审通过即止，到限如实报告，见自动化与门槛。动效覆盖缺项、无法证明播放或存在影响使用的动画问题，不得仅凭“看起来有动”判通过；评分只依据五维美学表；性能未测不扣分、不阻断设计达标，未经实际播放不伪称动画已审查。
