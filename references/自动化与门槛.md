# 自动化与门槛（v23，2026-10-31）

## 1. 范围与预算

A 制作登记后按[原站证据格式](A模式证据格式.md)先用[原站侦察与回放](原站侦察与回放.md)获取源证据，依次锁定原站、核验可运行样段、核对各区块与整站。新制作省略制作模式时默认 A，B/C 须显式登记。仅评审的任务只判断收到的证据；参考材料不足给可定位的问题与未验证结论。

新建、整页改版、重新生成在原项目登记begin；只分析、更新技能、局部Bug不运行网站制作。A 的整站文案在样段通过后开始；需新写的候选经独立审核后进入正式页面。当前评审最多两次独立调用、一批集中修改，首审达标即止，到限未达标/未验证如实收尾，不为用户已授权的步骤反复确认。

begin默认review_plan=default，两次预算覆盖本次约定交付范围，不是每个页面、每个文件各两次。宿主优先；exec只作兜底，两条通道同一份台账。失败、超时、无效报告占预算，不能通过改目录或换通道重置。

```
node <技能>/scripts/workflow-check.mjs begin --root <原项目> --site <网站目录> [--reference <参考URL>]
```

仅用户明确要求完整探索/获奖打磨时，begin加本脚本参数`--review-plan exploration|polish|both`：默认成品2次；完整方案卡对比另加1次，总3次；获奖专项另加2次，总4次；都明确要求合计5次。分别使用default/exploration/polish范围，不自动启用旁支。

## 2. Gemini 与独立文案审核的记录

- 网站文案默认 **Google AI Studio**，通过 `lsf-ai-agent` 的浏览器流程生成并回收本轮完整回答，不自动调用任何API。型号与思考沿用关联技能当前路由，并以实际界面核对为准。保留原始候选与真实页面/型号/时间信息，独立审核后回填。
- `gemini-copy.mjs` 仅保留为贞贞 API 可选适配器；只有用户之后明确指定时才用 `--via t8star`，默认入口为AI Studio时脚本在发送前退出。API启用时，型号、思考、凭据只有 `lsf-ai-agent` 一处来源；密钥只放进程环境或 Windows 凭据管理器，不放brief、命令行、项目或回执。API首次实调前的doctor只证明模型列表可读，不代表生成成功。
- 中转或浏览器仅在用户切换入口后按关联技能处理，手工落盘真实回传，标明入口、时间、候选和可用证明；不能捏造 API 回执。
- `approved.json` 例：`{"hero.title":{"type":"hero_title","text":"原候选或保留原意的小改","from":"copy/gemini/真实记录.json#hero.title#0","reviewed_by":"copy_reviewer"}}`。用户明确给定的原文、品牌、数字可放 `_exempt`，禁止把整页临时文案都塞进去绕过流程。
- `copy/review.json`：实际子代理返回的审核表、每块选择与原因、`verdict: approved|通过|达标`；主 Agent 只补 `_meta: {agent_id, at, approved_hash}`，其中 approved_hash 是定稿文件 SHA256。只读审核员不能递归调用外部模型。
- `check-copy --approved ...` 检查确切来源，空定稿、错误引用、缺审核标记均失败；`--style-only --url ...` 独立查标题标点，不代表来源通过。相似度、by 字段和服务商回传型号不能独立证明上游模型身份。
- 实现完成后另用现有 `copy_reviewer` 的page模式实际查看整页与相关状态，回收 `copy/page-review.json`。具体格式和删除判断见[文案审核第6节](文案审核.md#6-成品页面冗余审核page模式)。这项检查主Agent后加的文字，不能用候选审核或视觉评分替代；新流程最终check要求通过回执和当前构建摘要一致。一次集中删除、一次定向复查，不增加设计评分预算。


## 3. 首审和定向复核使用同一审查包

固定职责位于[独立评审固定提示词](../templates/独立评审固定提示词.md)，按[审查规则索引](审查规则索引.md)选择用户收藏的适用规则。prepare-review会把固定提示词、主入口关键约束、评分表及方法正文加入同一审查包，并自动收集项目根到site的AGENTS/AGENTS.override、DESIGN.md及site的ref/reference-spec.json。项目内其他skill规则和组件合同通过根目录`.lsf/review-rules.json`的`files`数组显式列出（路径相对项目根）；正文随包发送，不只提供路径。项目规则变动使旧结论过期。意见在现有evidence/deductions或问题字段引用规则出处，无需改报告schema。

只有独立视觉评审、尚无台账时可用`begin --root <项目> --site <站点> --purpose review`登记，只检查本次设计评审，不自动启动Gemini/建站，check的通过不等于完整制作验收。已有台账必须沿用其预算，不能靠换命令重置。详见[独立评审入口](独立评审入口.md)。

先准备目标卡（含已选方向和参考）、changes.md、实际375/768/1440截图及本节的动效证据。相对路径均相对实际site；exec命令中的轮次/target路径按命令工作目录解析，建议在site运行或用绝对路径。

宿主派发前先运行：

```
node <技能>/scripts/workflow-check.mjs prepare-review --root <原项目> --round rounds/round-01 --target target.md
```

返回真实call编号，生成reviewer-prompt.md、review-schema.json、review-input.json并消耗一次预算。把prompt全文、schema、实际截图和可用播放证据交给新的design_reviewer；不要只说“参考unslop”。当前会话角色若尚未刷新，也必须显式给这份审查包。method_hash只证明发送材料版本一致，不证明模型理解或角色已重新注册。

回收真实JSON到本轮review-response.json，然后：

```
node <技能>/scripts/workflow-check.mjs record-review --root <原项目> --call <真实编号> --result <回执绝对路径> --agent <实际AgentID>
```

失败或超时同样回收，`--status failed|timeout --reason <实际原因>`；不填虚假报告。record-review保存独立原文review.json和来源，机械生成final-score.json、score.json及review.md；不能由主Agent调整评分。台账只追加，按真实登记计数而非目录号；正常使用须顺序派发，不同时绕过同一台账。

exec兜底在内部完成相同登记与回收：

```
node <技能>/scripts/review-round.mjs rounds/round-01 --root <原项目> --target target.md --fallback-reason <实际不可用原因> --model <当前模型ID>
```

不在已有宿主结果后为“验证脚本”重复评审。exec图片入口不能播放视频；视频单独输入会前置失败，不冒充看过。改用有播放能力的宿主，或可消费的帧及真实观察记录，并说明流畅度仍需实际播放证据。

## 4. 复核与分数合成

首审full_blind，五维全量独立评分。通过立即收尾，不为建议项改画面。

未达标时主Agent核对阻塞项，集中修改。响应文件示例：

```json
{
  "scope": "local",
  "touched_dimensions": ["字体与排版", "构图与空间"],
  "items": [{"id":"B1", "decision":"accept", "evidence":["rounds/round-02/shots/375.png"]}]
}
```

partial/reject说明范围；reject须给citation（确切用户原话/已保存字段/参考或测量证据），由复核确认，不自动放行。全局字体/令牌/布局或无法可靠限定影响时scope=global。受影响维度至少取原问题维度与实际touched_dimensions的并集；评审可按实际回归扩大，不用未经验证的像素差阈值判断。

新轮次更新截图和证据后：

```
node <技能>/scripts/workflow-check.mjs prepare-review --root <原项目> --round rounds/round-02 --target target.md --mode verify --responses responses.json
```

换全新评审，给生成的审查包，不给旧分或主Agent辩护。targeted_verification只给受影响维度新分，total=null；新分须对整页该维度负责，看足够上下文。无法限定时同次full_rescore_with_issue_list覆盖五维，明确非盲评，不另派发。

脚本继承未受影响维度，按来源合成最终分，标“首审＋局部复核合成，非第二次全量盲评”。不把合成分称为全新盲评，不由主Agent加分。五维底线20/16/16/16/12、总分85、三项视觉约束均已验证、无未解决阻塞才达标。建议最多5条，不凑3个问题。

exec复核同样使用`--mode verify --responses <路径>`。明确要求的获奖专项使用`--scope polish`；完整六版方案卡对比使用`--scope exploration --mode comparison`，只作对比，不判网站完成。

## 5. 动效、hover与构建证据

每轮motion-evidence.json声明实际构建输入及观察。先列build_files为实际运行源码/素材文件或目录（覆盖所有相关输入，勿列rounds、生成报告和依赖缓存），用以下命令取得源码摘要，再对该构建实际观察并填build_hash：

```
node <技能>/scripts/workflow-check.mjs evidence-hash --root <原项目> --round rounds/round-01
```

```json
{
  "build_files": ["src", "public", "index.html", "package.json"],
  "build_hash": "命令返回的当前hash",
  "moments": [{
    "moment": "导航上下滚及按钮悬停",
    "source": "live_observation",
    "files": [],
    "observer": "实际观察者或AgentID",
    "observed_at": "实际观察时间",
    "observation": "填写真实操作、看到的中间状态、结果和限制",
    "verifies": ["动效表现", "禁用效果"]
  }]
}
```

此例只是结构，不是可直接提交的通过证据。只列实际存在的开场、导航、1～2个代表性章节和展开交互；不每章固定截帧。source可为video/frames/live_observation；文件路径相对site。录像/实际观察才能判断流畅度；frames只说明构图与状态，不能宣称流畅度。禁用hover须覆盖实际过渡过程，不只比较两个端点。

已有有效录像或真实播放观察可复用，但构建摘要必须一致。静态截图、tween登记、文件夹存在都不等于实际播放。哈希只覆盖声明输入，不能证明未声明的代码无变化；应如实列全运行输入。两个通道给评审实际能消费的材料，缺证据就标未验证。

`round-report.mjs snap <url> <轮次>`默认只截图，不自动跑五项全套；按影响范围调用专项脚本。确有需要才`check <url> <轮次>`或`snap ... --checks`跑全套。继承的检查注明来源、版本与适用范围，不把未运行说成本轮通过。收尾`build rounds`一次。

## 6. 状态、核验、Hook和迁移

台账.lsf/review-ledger.jsonl登记reserved、finished（含returned/failed/timeout/invalid）和用户明确追加的extension；失败占预算。不要改写旧事件，不通过删目录恢复额度。

review_status区分in-progress、passed、closed-unmet、closed-unverified、changed-after-review。到限仍有真实缺陷就closed-unmet；证据缺失/调用失败或无效就closed-unverified。评审后代码、截图或证据变化会使结论过期，不能自动开第3次。需要如实提前收尾时：

```
node <技能>/scripts/workflow-check.mjs close-review --root <原项目> --status closed-unverified --reason <真实缺项>
node <技能>/scripts/workflow-check.mjs check --root <原项目> --url <预览URL>
```

check仍检查真实Gemini候选、独立文案审核、来源、参考动效取证与assets-plan等；评审闭合不让其他缺项通过，整体passed仍可为false。可选Stop Hook看到评审已闭合或预算用尽，不再因同项循环block，只要求如实报告。普通缺项最多连续拦截3次，随后报告未完成，不假称通过。运行不依赖Hook安装，不改全局Hook配置。

旧项目保持历史报告原样，切换用`adopt-review-policy --root ... --reason <本次切换依据>`，只从切换点计新预算，不按旧round-05推断次数。已有新策略不能再迁移归零。用户以后明确要求继续，运行`extend-review --root ... --reason <用户原话>`追加一次修改和一次复核，不自动启用。

真实用户输入等待仍用wait/resume，不能拿等待伪装验收通过或拖延预算收尾。

## 7. 验证边界

Node逻辑测试验证预算、状态、合成、证据变化和Hook行为，不证明模型审美质量或实际提速。原生角色读取与真实浏览器播放须在实际任务核对，不由method_hash代证。只修改技能不发送模型探针、不创建网站，不自动开启全局Hook。


当前视觉评审优先Gemini/Claude，现场测量由独立评审Agent通过Ego Lite完成；均不可用才用继承当前模型的新子Agent。读取[外部视觉评审](外部视觉评审.md)，仍走同一prepare-review/record-review台账；host指宿主协调通道，不代表评分一定来自当前模型。实际评分来源另记在回执，失败/超时共用预算。
