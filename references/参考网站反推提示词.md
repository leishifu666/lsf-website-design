# 模式 F：参考网站反推提示词 / 提示词复刻网站（F-3.1）

面向 `lsf-website-design` 主 Agent 的总控规范。反推子 Agent 系统提示词见 [agents/website-prompt-reverser.md](../agents/website-prompt-reverser.md)；改写子 Agent 系统提示词见 [agents/website-prompt-adapter.md](../agents/website-prompt-adapter.md)。

引用约定：本文件章节记作 `§n`；反推子 Agent 文件章节记作「reverser §n」；改写子 Agent 文件章节记作「adapter §n」；提示词内部章节记作「提示词 §n」（Base Prompt 与 Adapted Prompt 节号相同）。

用户于 2026-10-19 直接授权将模式 F 子 Agent 作为专属角色调用；此委派仅授权参考站取证、提示词生成与定向改写，不代替登录、付费、发布或其他外部授权。只更新本技能时不自动访问当前浏览器页面，当前浏览器随手停留页面（ambient URL）也不得替代用户指定参考站。

| Base Prompt《原站基准制作提示词》 | 阶段 1–3 | 原站 100% 基准，长期复用资产 |

## 1. 触发与分流

### 1.1 触发条件
用户给出参考网站 URL（可附截图、录屏），并提出以下任一诉求：反推提示词、照这个做、提示词复刻网站、换主题或配色重做、先反推提示词再建站。

### 1.2 交付分支

| 用户表述 | 分支 | 终点 |
|---|---|---|
| “只要提示词”“写成提示词”“反推一下”“拆解成 prompt”，且未要求出站 | A：`prompt_only` | 交付提示词与素材方案 |
| “提示词复刻网站”“先反推提示词再做站”“用提示词做出来”“换成我的主题/配色做站” | B：`prompt_to_site` | 交付可运行多级网站 + 双份提示词 |
| 无法判断 | 先问一句：“只要反推提示词，还是要按提示词把站做出来？” | — |

注：普通直接建站未要求走“先反推完整提示词再建站”流程时，仍按 [模式与入口](模式与入口.md) 走模式 A；一旦用户要求“提示词复刻网站 / 先由子 Agent 反推提示词再按提示词制作”或通过 `$lsf-web-prompt` 执行复刻，按本规范模式 F 分支 B 执行。

### 1.3 定制判定

用户提到以下任一项即为「有定制」，在 Base Prompt 通过门禁后统一派发 `website_prompt_adapter` 进入阶段 3.5：

| 字段 | 内容 |
|---|---|
| `new_theme` | 新主题、行业、受众、品牌名（占位或实名） |
| `new_palette` | 新配色（1–5 个色值或描述） |
| `copy_language` | 文案语言切换（如英文站改中文） |
| `custom_requirements` | 文案替换、区块增删合并、功能增减、技术栈指定、其他具体修改 |

这些字段只记录在主 Agent 的定制需求单（§5.2），不传给反推子 Agent，只传给 `website_prompt_adapter`。

### 1.4 页面范围

- 默认 `multi_level_l1_l2`：首页 + 主导航可达的 L1 栏目模板 + 从 L1 进入的 L2 详情/子页模板 + 共享全局壳 + 跨页转场。
- 仅当用户明确说“只要首页”“只要单页”时用 `single_page`。
- 用户点名的页面写入 `pages_hint`。

### 1.5 开工前必须拿到

| 项 | 来源 | 缺失处理 |
|---|---|---|
| `reference_url` | 用户 | 必问一次；Shopify 等平台名、行业名不能唯一确定网站，禁止自行搜索相似站、平台官网、本地旧站或 ambient URL 替代 |
| 交付分支 | 用户表述 | 无法判断时按 §1.2 问 |
| 定制需求 | 用户表述 | 未提即无定制，不追问 |
| 分支 B 的项目目录 | 用户 / 当前工作区 | 必问或新建并告知路径 |

一次最多问两项，其余按默认推进；用户已给可用 URL 时，不要求用户补截图或由主 Agent 预先拆站。

## 2. 阶段 1：构造交接 Prompt

交接 Prompt 不含任何定制字段。字段不得省略；没有的写 `无`。

```text
你是 website_prompt_reverser，严格按 <skill_root>/agents/website-prompt-reverser.md 执行，并先读取 <skill_root>/templates/反推任务输入.md 与 <skill_root>/templates/网站制作提示词.md。只反推原站，不做任何定制。

skill_root: <lsf-website-design 绝对路径>
reference_url: <入口 URL>
page_scope_mode: <multi_level_l1_l2 | single_page>
pages_hint: <用户点名的 URL 列表 或 无>
branch: <prompt_only | prompt_to_site>
sampling_budget: <默认：L1 ≤6 个模板，L2 ≤3 个模板>
attachments: <用户主动提供的截图/录屏绝对路径与时间码起点 或 无>
component_bookmarks: <skill_root>/references/component-bookmarks.json
known_gaps: <登录区/地区限制 或 无>
rework_items: 无

交付：研究记录（≤15 行）+ 原站基准制作提示词（四个反引号代码块，12 节）。
只研究与交付提示词；不得修改网站源码、安装包、生图、提交或递归委派。整站无法访问时，带已取得证据与阻塞原因回报，不要编造。
```

## 3. 阶段 2：派发与等待

- **调用方式**：当前会话可用子 Agent 列表已暴露 `website_prompt_reverser` 时直接按该角色调用；若尚未暴露原生角色，启动一个新的子 Agent，传入上方交接 Prompt 并强制其先完整读取 `agents/website-prompt-reverser.md` 与两份模板后按同一角色执行。不得把 `task_name` 冒充为已加载原生角色；若无任何委派能力则说明限制。
- 一个参考站派一个反推子 Agent；多个参考站且互不依赖时并行派发，各自独立交付。
- 等待期间主 Agent 可做：整理 §5.2 定制需求单（只整理，不派发改写）、确认分支 B 项目目录、读取仓库现有技术栈。不提前写站、不提前生图、不提前改写。
- 反推子 Agent 回报阻塞（反爬、登录、地区）：把阻塞原因与需要的材料转告用户，拿到后重新派发，`attachments` 带上用户材料。

## 4. 阶段 3：Base Prompt 质量门禁

主 Agent 逐项核对。任一项不通过即打回，不自行补写规格。

| 编号 | 核对项 | 通过标准 |
|---|---|---|
| G1 | 输出结构 | 仅两部分；研究记录 ≤15 行；提示词在单个四反引号代码块内 |
| G2 | 12 节完整 | 节号节名与 reverser §9.2 一致，无空节、无“略” |
| G3 | 纯基准 | 不含新主题、新配色、新文案方向 |
| G4 | 页面拓扑 | `multi_level_l1_l2` 时：提示词 §1 拓扑树完整；L1 与 L2 各至少 1 个完整取证模板（站点确无 L2 须写明原因）；边缘页已登记 |
| G5 | 路由与壳 | 提示词 §4.0 关系矩阵、§4.1 SHELL-xx 齐全；Header 反色规则与菜单时间线有数值 |
| G6 | 跨页转场 | 提示词 §6.7 每条 PT 有阶段时序、生命周期清理顺序、返回恢复、打断处理、持久舞台插值（如有） |
| G7 | 证据标签 | 抽查提示词 §3、§6、§9 各 10 个数值/判断，全部带标签且带方法或依据 |
| G8 | 技术栈五层 | ①–⑤ 各有结论 + 标签 + 版本（可得时） |
| G9 | 渲染机制 | 每个 canvas 有核心机制合同；颜色类 uniform、灯光色、背景与雾色对应 TK-C 编号 |
| G10 | 无降级 | 无“背景图位移替代”“fade-up 替代”“CSS 模拟 3D”“直接跳页”类描述；无以性能为由的削减 |
| G11 | 页内时间线 | 每条 TL 有 trigger/start/end/pin/scrub/进度段/反向/快滚/打断 |
| G12 | 状态机 | 每个可交互组件有 default→error 全表、键盘、ARIA、出现页面 |
| G13 | hover 禁令 | 无按钮上浮、无图标位移；原站有的已标 `【原站效果】` 并给 R1–R5 替代参数 |
| G14 | 三端 | 每页每区块有 1440/768/375 规则 |
| G15 | 图片规划 | 每页图片都有 IMG-xx：形态、页面锚点、z 序、运动、三端尺寸、跨页复用 |
| G16 | 生图提示词 | 每条以规定结尾句结尾、句后无字符；工具参数单列；设定集一致 |
| G17 | 定制槽位 | 提示词 §2 定制槽位清单完整；颜色令牌带语义角色与使用位置 |
| G18 | 自包含 | 无“同参考站”“如前所述”“见上文”等；跨节只用编号，区块带页面前缀 |
| G19 | 源码与图标 | 书签来源/许可/状态齐全；唯一开源图标库；无手写 UI 图标 |
| G20 | 文案标点 | 标题、导航、按钮、标签槽位行末无标点（人工逐条核对；建站后由 `check-copy.mjs --style-only` 实测） |
| G21 | 构建可拆 | 提示词 §9 有路由架构、按页面模板的模块划分（分支 B 到文件级）、共享令牌契约、CP0–CP6 |
| G22 | 引用与未知项 | 全部 `§` 引用指向存在且对应的节；提示词 §12 每项有开发默认处理 |

### 4.1 打回模板

```text
rework_items:
- G6：PT-02 缺返回 L1 时的滚动恢复与 ScrollTrigger 重建顺序。按 reverser §4.6 补全。
- G9：M-1 的 uColorA、uColorB 未对应 TK-C 编号。按 reverser §5.5 补全。
其余保持不变。请输出完整两部分整份替换，研究记录第 1 行写修订说明。
```

- 打回发给原反推子 Agent（同一会话继续，保留取证上下文）。
- 最多打回 2 轮。第 2 轮仍有缺口：缺口留在提示词 §12 标 `【未知】`，交付或进入阶段 3.5 时向用户说明哪几项未取得及处理方式。
- 主 Agent 允许直接修改的仅限：错别字、编号不连续、`§` 引用笔误。任何数值、技术栈、机制、路由描述的改动都必须打回。
- 通过后 Base Prompt 锁定，后续阶段不得修改；定制只产出新文件。

## 5. 阶段 3.5：定制改写（统一派发 website_prompt_adapter）

### 5.1 流程

1. 无定制：跳过本阶段，执行版 = Base Prompt。
2. 有定制（§1.3 任一字段）：不分轻重，一律执行下列步骤：
   1. 主 Agent 按 §5.2 整理 `CR-xx` 需求单。
   2. 统一派发 `website_prompt_adapter`（模板见 §5.3；当前会话已暴露该原生角色时直接调用，否则派发新子 Agent 并强制其先完整读取 `agents/website-prompt-adapter.md` 按同一角色执行）。
   3. 子 Agent 回报阻塞（CR 冲突、无法落地、触及降级红线、目标对象不存在）：主 Agent 向用户澄清，更新需求单后重新派发完整输入。
   4. 主 Agent 按 §5.4 核对 A1–A6，不通过打回，最多 2 轮。
   5. 通过后按 §5.5 留档。
3. 主 Agent 不亲自改写提示词；除错别字、编号不连续、`§` 引用笔误外，任何改动都打回给 `website_prompt_adapter`。

### 5.2 定制需求单

格式与类型取值以 adapter §1.1 为准：

| 编号 | 类型 | 用户原话 | 目标对象 | 期望结果 |
|---|---|---|---|---|
| CR-01 | `new_palette` | … | 全局 | 主色 #…、底色 #… |
| CR-02 | `section_remove` | … | PAGE-L1-01/SEC-05 | 删除 |

- 用户原话逐字保留。
- 目标对象写 Base Prompt 中的真实编号；改锁定层对象必须点名编号。
- 用户明确要求以静态内容替换某个 M-x 或 PT-xx 时，期望结果写 `用户确认替换：<内容>`；未经用户确认不得写。
- 需求含糊到无法写出目标对象或期望结果时，先问用户一句，不派发。

### 5.3 派发模板

```text
你是 website_prompt_adapter，严格按 <skill_root>/agents/website-prompt-adapter.md 执行。只在已锁定的基准提示词上定向改写，不打开参考站、不取证。

skill_root: <lsf-website-design 绝对路径>
base_prompt_path: <docs/website-prompt-base.md 绝对路径 或 Base Prompt 文件绝对路径>
custom_requests:
<CR-xx 表，按 adapter §1.1 格式>
branch: <prompt_only | prompt_to_site>
rework_items: 无

交付：改写记录（≤10 行）+ 定制版网站制作提示词（四个反引号代码块，完整 12 节）。
遇到 adapter §1.1 所列阻塞情形，停止改写并回报，不要猜。
```

### 5.4 A1–A6 门禁（主 Agent 复核）

标准与 adapter §7.1 相同。主 Agent 复核方法：

| 编号 | 复核方法 |
|---|---|
| A1 | 抽取 Base 与 Adapted 中 adapter §3 所列锁定层对象，去除颜色值与证据标签后比对；差异只出现在 CR 点名对象与例外条款中 |
| A2 | 核对 Base 每个 TK-C 编号在 Adapted 中有新值；运行 adapter §5.2 扫描脚本，颜色与品牌词均 0 命中 |
| A3 | 抽查每个 M-x 的颜色类 uniform、灯光、背景、雾，以及提示词 §8.1 环境色和 3 条 IMG-xx，与 TK-C 同角色同值 |
| A4 | 用 adapter §4.2.2 公式重算对比度矩阵中最低的 5 格，全部 ≥4.5:1 |
| A5 | 新增区块有三端规格、TL、IMG、验收项；删除区块有衔接；提示词 §4.0、§6.7、§9 已同步 |
| A6 | 抽查：无新增禁用 hover 项；每条生图提示词结尾句原样且句后无字符；无自包含禁用词；标题导航按钮标签槽位行末无标点；`§` 引用准确 |

同时核对证据标签迁移：定制新值均为 `【建议：依据 CR-xx + 推导方法】`，无伪 `【实测】`。

打回模板：

```text
rework_items:
- A3：M-2 的 uFogColor 仍为 #0B0D12，与 TK-C-BG-01 新值不一致。按 adapter §4.4 修正。
- A6：IMG-07 结尾句后带了参数。按 adapter §2.4 修正。
其余保持不变。请输出完整两部分整份替换，改写记录第 1 行写修订说明。
```

- 打回发给原 `website_prompt_adapter`（同一会话继续）。
- 第 2 轮仍不通过：未通过项写入 Adapted Prompt 提示词 §12 并标 `【未知】`，交付时向用户说明。

### 5.5 产物与留档

- 分支 A：交付 Adapted Prompt 与 Base Prompt 两份（Adapted 在前）。
- 分支 B：项目中留档 `docs/website-prompt-base.md`（原站基准版，只读）与 `docs/website-prompt.md`（执行版：有定制为 Adapted，无定制为 Base 的副本）。
- 构建阶段只以 `docs/website-prompt.md` 为施工依据。

## 6. 分支 A：只交付提示词

1. Base 门禁通过（或第 2 轮后缺口已入提示词 §12）；有定制时 `website_prompt_adapter` 产出已通过 A1–A6（§5.4）。
2. 交付：
   - 无定制：Base Prompt 完整代码块。
   - 有定制：Adapted Prompt 完整代码块 + Base Prompt 完整代码块（Adapted 在前）。
   - 素材方案在提示词 §8，不重复粘贴，只说明位置。
   - 一句话说明页面覆盖（L1 / L2 模板数）、未确认项数量与最关键的一项。
3. 研究记录不默认展示；用户要求时再给。
4. 不写代码、不生图。

## 7. 分支 B：按执行版提示词制作网站

### 7.0 执行策略选型

| 条件 | 策略 |
|---|---|
| 页面模板 ≤2，区块合计 ≤8，渲染舞台 ≤1，无持久舞台 | S1：主 Agent 自建；或派 1 个构建子 Agent |

### 7.2 图片资产先行生成与质检（主 Agent 独占，在任何区块编码前完成）

**生成**
- 调用当前会话可用的**原生生图工具**（如 `image-generator` / `generate_image`，若用户指定外部 API 则走该 API），逐项按执行版提示词 §8.2 生成；工具参数从参数行映射到实际接口字段，提示词正文原样使用，不改结尾句。

- 透明底单体：传入原生工具支持的透明底参数（`transparent_background=true` / `output_format=png`）；不支持原生透明输出时按 [氛围图片](氛围图片.md) 做真实去背景与 alpha 校验，严禁把白底、黑底或绘制棋盘格当作透明。完整环境图按不透明生成。
- 落盘 `public/assets/gen/IMG-xx.png`（必要时导出 `IMG-xx@1x.webp`、`IMG-xx@2x.webp`），不引用外部临时缓存路径。

**质检**
- 透明度：运行本技能内置 PNG 逐像素透明检查脚本（传入全部透明底 PNG 路径），并将结果写回 `src/assets/manifest.json`：
  ```powershell
  node <skill_root>/scripts/check-alpha.mjs public/assets/gen/IMG-*.png
  ```
- 如环境具备 Python PIL，可进一步检查四角全透明与半透明边缘白边率（`white_halo_ratio < 0.15`）：
  ```python
  import json
  from PIL import Image
  m = json.load(open("src/assets/manifest.json", encoding="utf-8"))
  for a in m["assets"]:
      im = Image.open(a["png"])
      r = {"id": a["id"]}
      if a["form"] == "transparent":
          r["has_alpha"] = im.mode in ("RGBA", "LA") and im.getchannel("A").getextrema()[0] == 0
          A = im.convert("RGBA"); w, h = A.size
          r["corners_clear"] = all(A.getpixel(p)[3] == 0 for p in [(0,0),(w-1,0),(0,h-1),(w-1,h-1)])
          px = A.load(); halo = edge = 0
          for y in range(0, h, 2):
              for x in range(0, w, 2):
                  al = px[x, y][3]
                  if 0 < al < 255:
                      edge += 1
                      if min(px[x, y][:3]) > 235: halo += 1
          r["white_halo_ratio"] = round(halo / max(edge, 1), 3)
          r["pass"] = r["has_alpha"] and r["corners_clear"] and r["white_halo_ratio"] < 0.15
      else:
          r["pass"] = im.size[0] >= a["min_w"]
      print(json.dumps(r, ensure_ascii=False))
  ```

| 项 | 标准 |
|---|---|
| 真实 alpha | 存在 alpha=0 的像素；四角全透明（棋盘格画进图里视为失败） |
| 边缘 | 半透明边缘无白边；在提示词 §3.1 最深与最浅背景色上叠放目检无白边、无锯齿 |
| 主体完整 | 无裁切、无多余物体、无文字水印 |
| 尺寸 | 原图 ≥ 最大显示尺寸 ×2 |
| 统一画风 | 全部资产按页面拼对照图，核对设定集的光源方位、色温、视角、材质、色调一致 |
| 配色一致 | 有定制时，图片主色调与 TK-C 新配色一致，无原站配色残留 |

- 不通过：同提示词重生成，最多 3 次；仍不通过，只修改正文中与缺陷相关的描述（结尾句不动），在 manifest 记录修改与原因，并同步更新 `docs/website-prompt.md` 对应条目。
- 自检 CP1：manifest 全部 `pass: true` 后才进入编码。

const checks = await page.evaluate(() => ({
