# 自动判断任务与基础版模式

AI先判断用户要的交付物和改动范围，再选择模式。开头用一句“本次进入模式X（名称），因为……”说明；不把模式菜单或“原创/找参考二选一”当作开工许可。用户当前明确意图、专用入口和既有选定方向优先。

| 当前任务 | 模式 | 执行范围 |
|---|---|---|
| 只检查成品文字是否多余、重复或难懂 | H 文案评审 | 只审文字，不默认改写或删模块 |
| 只看视觉问题、评审或评分 | G 视觉评审 | 优先Gemini/Claude评分，独立Agent通过Ego Lite实测、截图和交接；不默认修页面 |
| 明确只要建站提示词、反推提示词 | F 反推提示词 | 取证并交付提示词；不因“复刻”二字误启动建站 |
| 明确先帮找站、看参考候选或让用户选站 | D 寻找参考 | 实际研究至少五站，先交候选；未授权制作不继续建站 |
| 明确原创、探索多方向、不跟随某个站的风格 | C 原创探索 | 五站调研后，用构图方法库和种子做甲/乙/丙三个真实预览 |
| 明确只学参考的方法、设计自己的视觉表达 | B 参考创作 | 迁移适用原则，形成自己的表达 |
| 普通新建网站，或说“参考这个设计做”“按这种风格做”“贴近”“还原”“复刻” | A 风格参考（默认） | 锁定主参考的设计语言与真实表现机制，替换成自己的内容及生成素材 |

“先分析、先给思路”限制本次执行范围：可以对相应模式取证和分析，不自动实现、评分或生图。只修局部Bug等沿用项目局部流程，不扩大成完整制作。

## 默认A的参考从哪里来

- 用户给定URL、截图或录屏：直接作为主参考，不改选其他风格；只有截图时不把推测参数写成实测，无法访问原站也保留已有证据。
- 用户只给主题且已要求制作：AI先实际研究五站，选一个适合主题与资源条件的主参考继续A，默认直接制作一套；用户明确选择三预览时，三份使用同一选定网址。不因没有URL默认转C或停在D等待选站。
- 用户已选主参考：沿用选择。其余调研只辅助理解方法，不混进其他风格，不加入原创方法抽签。
- 用户说“页面没意思、想更有趣/高级”：在当前模式读取[趣味动效与交互选型](趣味动效与交互选型.md)，查真实网站和开源实现；不把这个要求误判成必须换风格或原创。
- 只有缺少会改变核心结果的信息才提问，继续不依赖答案的工作；工具故障与证据缺口如实说明。

## C与D的选择边界

C只在明确原创意图或原创专用入口时使用。三个预览命名甲/乙/丙，避免与模式字母混淆；未授权代选方向时，交付预览后等用户选定再制作一个正式方向。明确“你来选”时AI说明取舍并继续，不再请求选择。

D只在明确要求先找参考/看候选时停留。选定后“按这个风格做”进入A，“只学方法”进入B；已授权AI选站并制作时可自行选主参考进入A。不能把普通建站都变成必须让用户选站的D流程。

## 旧编号兼容

旧记录1B→A、1→B、2A→C、2B→D、4→F；视觉评审→G，文案评审→H。只用于理解历史任务，新任务使用本基础版所列模式。`lsf-web-*`调用名不变，生成入口以命令入口.json为唯一来源。

制作方式按[分流规则](三方向预览与确认.md)单独确定：A普通参考制作默认直接出一套，用户明确要比较时才先三个预览；已表达清楚的不重复询问。确需提供入口选择时，只说明“直接制作1套／先看3个预览再选”。A三份[统一提示词](../templates/风格参考统一提示词.md)、主题与主参考网址完全相同，不给三位构建者分配不同设计方向。子任务明确“完成一个方向预览”时只做一个，不递归派发三版。C原创方向与明确的一套交付范围按用户要求执行。
