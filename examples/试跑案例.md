## 步骤0 判断模式

本次进入**模式B 参考型**，因为用户给了参考站 linear.app，要做的是自己的新网站，不是改 Linear。风险是照抄 Linear 的深色科技感，咖啡品牌照搬会完全错位，所以只迁移原则。

## 步骤1 目标与约束

- 品牌：「慢烘」，杭州一家 3 人小烘焙坊，做精品咖啡豆每月订阅。
- 目标用户：25～40 岁、家里有手冲或意式设备、已经在电商买过精品豆、想要“新鲜、不用每次挑”的人。情境：手机上从小红书/朋友推荐点进来。
- 用户来做什么：判断这家豆子是不是真的新鲜、口味适不适合我、订阅麻不麻烦。
- 核心转化动作：**开始订阅**（选口味偏好 → 选频率 → 付款）。次要动作：单买一包试试、看烘焙日志。
- 调性 3 词：诚实、手作、有节奏。3 个“不要像”：不要像连锁咖啡品牌的广告页、不要像 SaaS 落地页、不要像文艺咖啡馆的摆拍相册。
- 约束：Next.js + Tailwind；内容有：每周烘焙记录（批次号、产地、烘焙日期、风味）、3 个订阅档位、真实产品照少量。
- 出口检查：一个在手机上刷到推荐的手冲爱好者，来确认豆子新不新鲜、合不合口味，我们希望他点“开始订阅”。✅

## 步骤2 拆解 linear.app（2026-10-18）

### 第1层 目标层
| 项 | 是什么 | 为什么 |
|---|---|---|
| 目标用户 | 产品团队、工程团队，标题直说“for teams and agents”〔实测〕 | 用标题直接筛人，不是给所有人看 |
| 解决的问题 | “planning and building products”〔实测〕 | 用一个动词短语说清用途，没有形容词堆砌 |
| 核心转化 | Sign up / Get started〔实测：导航有 Sign up，页尾 “Get started”〕 | 主动作在头尾各出现一次，中间区块用 “Learn more→” 文字链接 |
| 次要动作 | Log in、Open app、Contact sales、Download〔实测〕 | 老用户入口放导航右侧，不和新用户主动作抢 |
| 说服证据 | 真实界面（议题、看板、代码 diff）、客户引言（OpenAI、Ramp、Opendoor）、“40,000 product teams”、更新日志〔实测〕 | 用“产品本身 + 第三方 + 持续更新”三种证据，几乎没有抽象插画 |

### 第2层 信息架构层
- 主导航：Product、Resources、Customers、Pricing、Now、Contact〔实测〕，6 项。
- 区块顺序〔实测〕：
  1. 标题 + 一句副标题 + “New: Loops” 新功能入口 → 说清是什么、告诉你它在变
  2. 一整块真实产品界面（一个议题详情：活动流、属性、AI 处理过程）→ 首屏即产品
  3. 客户 logo + “A new species of product tool” + 三条价值（Purpose-built / Powered by agents / Designed for speed），每条带 “Fig 0.1/0.2/0.3” 编号 → 定位
  4. 按工作流顺序的 4 大区块：Intake → Planning → AI → Build/review/ship，每块 = 标题 + 一句话 + Learn more + 一个真实界面片段 + 子功能列表 → 用“工作流时间顺序”组织功能
  5. Changelog（4 条带日期的更新，最近 2026-10-08）→ 证明持续迭代
  6. 客户引言 + “40,000 product teams” → 社会证明
  7. “Built for the future. Available today.” + 4 个动作 → 收尾
- 组织方式：**按用户工作流的先后顺序**排功能，而不是按功能清单。

| 观察 | 是什么 | 为什么 |
|---|---|---|
| 功能顺序 | Intake→Plan→AI→Build | 读者在脑中跟着“一件事从进来到上线”走一遍，比并列罗列更好记（分块 Chunking，推断） |
| Fig 编号 | 价值点标 Fig 0.1～0.3 | 借“技术文档/论文插图”的隐喻，暗示严谨、工程感〔推断〕 |
| Changelog 放首页 | 带具体日期 | 对工具类产品，“还在快速变好”本身是购买理由 |

- 每个功能区块重复同一结构（标题/一句话/链接/界面），节奏稳定，读者学会一次就能扫读后面所有区块（一致性，C4）。
- 网格、最大宽度、间距阶梯：需跑 `extract-tokens.mjs` 实测，本次未取得。

### 第4层 视觉层〔推断，未实测〕
- 图像全部是产品界面本身，界面内是真实感的数据（议题编号 ENG-2085、人名、时间“2 min ago”）〔实测文本〕→ 用“像真的”的数据替代营销插画。
- 字体、配色、强调色：未实测，不下结论。

### 第5层 交互层〔部分实测〕
- 界面片段里有状态文字：“Working…”“Draft PR awaiting your review”“moved from Todo to In Progress”〔实测文本〕→ 用状态变化讲故事，体现“系统状态可见”（C1）。
- 动效、hover、键盘可达性：未实测。

### 第6层 原则（7 条）
| # | 原则 | 证据 | 为什么有效 | 迁移到「慢烘」 |
|---|---|---|---|---|
| P1 | 首屏放产品本身的真实状态，而不是氛围图 | 首屏即议题详情界面 | 识别优于回忆（C6）；用户直接看到要买的东西 | 首屏放“本周正在烘的这一批”：批次号、产地、烘焙日期、几天后寄出 |
| P2 | 按用户经历的时间顺序组织内容 | Intake→Plan→AI→Build | 分块 + 叙事顺序降低认知负荷（B6 Chunking / Cognitive Load，仅定义） | 按“生豆到货→烘焙→静置→寄出→你冲第一杯”排 |
| P3 | 用带日期的更新证明“活的” | 首页 Changelog | 对需要持续交付的服务，新鲜度就是价值 | 首页放“烘焙日志”：最近 4 批，带日期 |
| P4 | 主动作头尾各一次，中间降级为文字链接 | Sign up / Get started vs Learn more→ | 按钮按层级设计（A7）；减少选择（B2） | “开始订阅”只在首屏和页尾做实心按钮，中间用文字链接 |
| P5 | 用一个统一的编号/记号系统制造品牌感 | Fig 0.1～0.3 | 一致性（C4）+ 与众不同的记号便于记忆（B3） | 用烘焙批次号（如 No.143）贯穿全站 |
| P6 | 证据用“像真的”的具体数据，不用形容词 | ENG-2085、2 min ago、40,000 | 系统与现实匹配（C2），具体比抽象可信〔推断〕 | 写“2026-10-14 烘，静置 5 天，10-19 寄出”，不写“新鲜现烘” |
| P7 | 老用户入口和新用户主动作分开 | 导航右侧 Log in / Open app | 灵活高效（C7），不干扰新用户 | 导航右侧“我的订阅”，不与“开始订阅”同级 |

不迁移清单：深色科技配色、Fig 的工程隐喻本身（迁移的是“编号系统”这个原则，记号改成烘焙批次）、AI/agent 话术、6 项导航（咖啡站内容少，压到 4 项）。

## 步骤5 发散（第4～6版）

### 第4版：「烘焙日志」　发散方向：换隐喻（网站 = 一本正在写的烘焙日志）
- 核心想法：首页就是日志本，最上面一条是“正在烘的这一批”，往下是一条条已寄出的批次。
- 首屏：大号批次号 No.143 + 一行“埃塞俄比亚 古吉 · 10-14 烘 · 静置中，10-19 寄出”+ 一句风味 + 实心按钮“订阅，下一批寄给你”。
- 结构：No.143 当前批次 → 过去 4 批日志（日期、产地、风味、当时的一句烘焙笔记）→ “你会收到什么”（一包豆子的实物照 + 卡片上印的批次信息）→ 3 档订阅 → 页尾按钮
- 视觉：纸张白底、等宽数字字体做批次号和日期、正文无衬线；唯一强调色取烘焙曲线的焦橙色；少量真实照片。
- 关键交互：日志条目点开展开烘焙曲线小图和笔记。
- 刻意避开：C7 全屏情绪摄影+空泛口号（改为数据首屏、具体日期）；C2 三列图标卡片（“新鲜”由日期本身证明）；A10 统一淡入动效；A1 米色+陶土色（底色用纸白、强调色用焦橙，色相与陶土拉开）。
- 前卫手段：subgrid 让每条日志的日期、产地、风味列跨条目对齐，像真的账本（广泛可用）；日志展开用 `@starting-style` 入场（新近可用，不支持时直接显示）。

### 第5版：「从生豆到你的第一杯」　发散方向：换信息组织（按时间轴）
- 核心想法：整页是一条横向/纵向时间轴：生豆到货 → 烘焙 → 静置 5 天 → 寄出 → 第 7～21 天最佳赏味。
- 首屏：一条时间轴，标出“今天”所在位置，例如“今天 10-18：No.143 静置第 4 天”。
- 结构：时间轴 5 个节点，每个节点讲一件事并给证据（到货照片、烘焙曲线、静置说明、物流、冲煮建议）→ 订阅档位按“多久喝完一包”来选 → 页尾按钮
- 视觉：大量留白、细线时间轴、编辑排版式的大号日期数字。
- 关键交互：滚动时“今天”标记沿时间轴移动。
- 刻意避开：C2 三步流程图标（改为真实时间轴）；C8 按功能罗列卖点；C4 定价三栏卡片（改为按饮用速度选）。
- 前卫手段：滚动驱动动画让“今天”标记随滚动移动（`animation-timeline: view()`，有限支持，用 `@supports` 包裹，不支持或 reduced-motion 时静态显示）。

### 第6版：「口味罗盘」　发散方向：换核心交互（首屏就是一个选择器）
- 核心想法：首屏是一个风味选择器：酸度、醇厚度、甜感三个滑杆，拖动后右侧实时出现“下一批最适合你的豆子”和寄出日期。
- 首屏：三个滑杆 + 推荐结果卡 + “就订这个口味”。
- 结构：选择器 → 推荐理由 → 本月所有批次 → 订阅档位 → FAQ
- 视觉：大号风味图、色块表示风味。
- 关键交互：滑杆即时反馈（目标 < 400ms，Doherty 阈值）。
- 刻意避开：C8 商品网格（改为先问偏好再推荐）；C1 双按钮首屏；促销横幅。
- 前卫手段：`@property` 注册颜色变量，风味色块随选择平滑过渡（新近可用）。

## 步骤6 评审 + 循环优化（100 分制，分数线 85）

评审方式：每一轮都由新开的独立评审子 Agent 打分，它只拿到目标卡、评分表、反套路清单和当轮方案卡，看不到上一轮分数和设计者的解释。下面各轮的分数和致命问题都是评审 Agent 给的，设计者只写修改记录。（本试跑在 Hark 内用独立子任务模拟这一分工，没有在 Codex 中实测 `design_reviewer`。）

方案阶段，没有页面可测：axe、reduced-motion 两条硬门槛记“待验”；“独特性”依据是推断（没做竞品普查），按规则最多给 15×80% = 12 分。

| **合计** | **79** | 未达标：总分 < 85，清晰度 9 < 底线 12 |

设计总监 3 个致命问题：
1. 如果目标是让刷到推荐的新用户 10 秒内明白“这是精品豆每月订阅”，那么首屏只有批次号和产地，会让他以为这是博客或单品页。
2. 如果目标是开始订阅，那么价格不在首屏，犹豫的用户要滚三屏才知道多少钱，会提前离开。
3. 如果要证明“新鲜”，那么只写烘焙日期不够，用户关心的是“收到时是第几天”，现在要自己算。

保留的优点：日期作为证据，是全部版本里唯一把“新鲜”变成可核对事实的做法。

| 问题 | 改了什么 | 预期提升 |
|---|---|---|
| 1 | 批次号上方加固定说明行“精品咖啡豆 · 每月新烘 · 寄到家” | 清晰度 |
| 2 | 主按钮下方加“¥89 起 / 月，随时暂停” | 目标达成 |
| 3 | 每条日志自动算出“到你手上是烘焙后第 6～7 天” | 清晰度 |

**第2轮（盲评）**：目标 20、清晰 12、层级 8、独特 12、品牌 10、可用 12、实现 12 = **86**。各维度过底线，硬门槛中可在方案阶段判断的项都通过 → **达标**（axe、reduced-motion 待页面阶段补测）。

1. 转化最直接：首屏就有“订阅，下一批寄给你 · ¥89 起/月”，按钮文案里带寄出日期。

3. 代价：依赖每周更新批次数据，停更一周页面就会“露馅”。控制办法：批次数据做成 CMS 一条记录，过期 10 天自动隐藏“正在烘”模块并显示下一批预告。

## 步骤8 设计说明 + 实现说明（摘要）

### 设计说明
- 原则：P1 首屏是当前批次的真实状态；P2 按“烘→静置→寄出→第一杯”顺序；P3 首页日志带日期；P4 主按钮只在首屏和页尾；P5 批次号贯穿；P6 只写可核对数据；P7 “我的订阅”在导航右侧。
- 页面结构：
  1. 导航（logo / 豆子 / 日志 / 关于 · 右侧“我的订阅”）
  2. 首屏：说明行 → 批次号 No.143 → 产地+日期+状态 → 进度条（烘焙 ● 静置 ● 寄出 ○）→ 风味一句 → 主按钮 + 价格行
  3. 烘焙日志：最近 4 批，每条可展开烘焙笔记
  4. 你会收到什么：一包豆子实物照 + 卡片批次信息
  5. 一个口味问题 → 3 档订阅（按“多久喝完一包”命名）
  6. 页尾：再次主按钮 + 随时暂停说明
- 令牌草案（交给 `lei-frontend-design` 规范细化）：纸白底、近黑正文、单一焦橙强调色；数字用等宽字体；4 倍数间距；状态：按钮 hover/focus/active/disabled/loading，日志展开的 empty（本周无新批次）与 error（数据加载失败）。

### 实现说明（给 AI 开发）
- 技术栈：Next.js + Tailwind；批次数据从 CMS/JSON 读取，字段：batchNo、origin、roastDate、restDays、shipDate、flavor、note、curveImage。
- 开工前先查项目已有组件、动效预设和设计令牌；按钮、展开面板、进度条优先复用或加 variant。
- 组件：`BatchHero`、`RoastProgress`、`RoastLog`/`RoastLogItem`、`WhatYouGet`、`TasteQuestion`、`PlanPicker`、`FinalCta`。
- 验收（页面阶段继续循环，直到补测的硬门槛也通过）：`npm run gate`（axe 无 critical/serious + 375/768/1440 视觉回归）；`npm run lhci`（无障碍 ≥ 0.95、LCP ≤ 2.5s、CLS ≤ 0.1）；首屏 5 秒测试（找 3 个人看 5 秒，能说出“这是咖啡豆订阅”）；`prefers-reduced-motion` 下进度条无动画；批次过期逻辑有单测。
- 未验证：参考站视觉令牌（未实测）；“日志式首屏在咖啡品类少见”是推断，未做竞品普查。

## 这次试跑暴露的规则问题（已回写进 SKILL.md 和评分表）

- 打磨循环如果没有真实对标截图，评审只能凭印象说“超过”，等于自我放水。所以规则改为：没有截图时不得判“超过”，停止条件也就不能满足。

- 发散版容易为了独特牺牲清晰度（第4、6版首轮清晰度都只有 9/15），所以清晰度必须设底线（12），不能被高独特分抵消。
- 没有证据的维度会被自己打高分。加了“推断最多 80%”的封顶后，第4版首轮从按 5 分制换算的 82 分降到 79 分，暴露出它其实不达标。
- 第6版第3、4轮只涨 2 分、1 分，说明在原地打转。“连续 2 轮提升 < 3 分就换策略”和“同一维度 3 轮低于底线就是方向问题”这两条规则，让它及时被淘汰，而不是改到第 10 轮。
- 组合最终版后必须重新盲评，否则组合可能引入新的层级冲突。
