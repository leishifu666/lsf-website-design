## 2. 在流程里怎么串

- 步骤2 拆解：DevTools MCP 截 375/768/1440 → dembrandt 出令牌（`--mobile` 再跑一次）→ DevTools MCP `get_css_styles` 抽查关键元素 → 技术栈判断（webappanalyzer 指纹库或浏览器扩展）
- 步骤5 发散：Refero / Mobbin / Godly 找跨行业参考（只看机制，不抄视觉）
- 页面评审：默认最多两次调用、一批修改；按影响范围取证，工程检查与Lighthouse仅用户要求时运行，不作为美学分数或每轮门槛。
- 步骤8 验收：同上，加 `prefers-reduced-motion` 模拟和 `dembrandt --compare` 检查令牌是否漂移

## 3. Codex 接入配置

格式依据 https://developers.openai.com/codex/mcp ：写在 `~/.codex/config.toml` 或受信项目内 `.codex/config.toml`，每个服务一节 `[mcp_servers.<name>]`。

命令行添加：
```bash
codex mcp add chrome-devtools -- npx chrome-devtools-mcp@latest
codex mcp add playwright npx "@playwright/mcp@latest"   # 可选
codex mcp login figma   # Figma 远程 MCP 走 OAuth 登录，先在 config.toml 加 url（未实测）
codex mcp list
```

完整示例见 `../scripts/codex-config.example.toml`（按官方格式拼装，**未实测**）。

## 5. 本技能脚本用法（兜底方案）

### 5.1 Playwright 截图

安装（需要 Node 18+）：
```bash
cd scripts && npm install && npx playwright install chromium
```
官方 API 要点：
- `page.screenshot({ path })` 截可视区域；
- `page.screenshot({ path, fullPage: true })` 截整页；
- `page.locator('.header').screenshot({ path })` 截单个元素。

本技能用法：`node ../scripts/capture.mjs https://example.com ./out`，会输出 375 / 768 / 1440 三个宽度的首屏图和全页图。拆解时三张全页图并排看，记录“移动端重排了什么”。

### 5.2 实测字体、颜色、间距

两种途径，结果互相印证：
1. 脚本：`node ../scripts/extract-tokens.mjs https://example.com ./out`，输出 `tokens.json`（按出现次数排序的字体、字号、行高、字重、文字色、背景色、margin/padding/gap、圆角）。高频值大概率就是对方的设计令牌。
2. DevTools CSS Overview：打开 DevTools → 右上角 ⋮ → More tools → CSS Overview → Capture overview。看 Colors（含低对比文字列表）和 Font info。点某个颜色可列出使用它的元素。

写拆解报告时，字号写成阶梯（如 14 / 16 / 20 / 28 / 48），间距写成阶梯（如 4 / 8 / 16 / 24 / 48 / 96），并标“实测”。

### 5.3 网格

DevTools → Elements → 找到容器，`grid` 徽章点开即显示网格线；Layout 面板可同时显示多个网格。记录：列数、列间距、最大内容宽度。

### 5.4 技术栈（Wappalyzer）

装浏览器扩展（Chrome / Firefox / Edge / Safari 都有），打开参考站点击图标即可看到框架、CMS、动画库等。用途：判断某个效果靠什么实现，评估自己项目的“可实现性”分。注意：识别结果是推测，写报告时标“Wappalyzer 识别”。

### 5.5 性能与可访问性

Lighthouse：
```bash
npm install -g lighthouse   # 需要 Node 22 LTS 或更高
lighthouse https://example.com --only-categories=performance,accessibility --output html --output-path ./out/lh.html
lighthouse https://example.com --preset=desktop --output json --output-path ./out/lh-desktop.json
```
注意：Lighthouse 默认模拟中端手机 + 慢速 4G，分数会波动，官方建议多跑几次、在一致环境下比较。

axe：`node ../scripts/audit-a11y.mjs https://example.com ./out`，输出 `a11y.json`（只跑 WCAG 2.0/2.1 A 与 AA 标签规则）。自动扫描只能发现部分问题，重要页面要再用 Accessibility Insights 手动查。
