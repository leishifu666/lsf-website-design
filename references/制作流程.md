# 网站制作的阶段流程

用于新建、整页改版和重新生成；分析、局部修复、提示词、评审或技能更新按本次范围执行，不启动完整流程。只读当前阶段的资料，已读且未变化的共享规则不重复加载。

| 阶段 | 完成什么 | 走到这里再读取 |
|---|---|---|
| 登记与研究 | 核对原项目、范围和用户改动；有指定主参考的 A 先侦察该站；其他整页任务按五站研究选参考与核心技术 | [制作约定](制作约定.md)、[五站研究](五站调研与记忆点.md)；A补[主参考取证](参考取证与组件规格.md) |
| 制作方式分流 | 选择一套时由当前对话主Agent直接制作；选择比较时才先三预览；C原创探索按本次范围 | [分流规则](三方向预览与确认.md)、[A统一提示词](../templates/风格参考统一提示词.md) |
| 三预览（按选择执行） | A三位独立构建者使用逐字相同的提示词、主题和主参考，各做一个认真完成的真实片段；C按原创方法探索 | [预览与确认](三方向预览与确认.md)；C补[原创方法](原创构图方法库.md) |
| 预览确认（仅比较路径） | 用户选定后展开一个方向；全不满意按反馈继续；直接制作路径不插入此步骤 | 同上；不新增自动评分轮次 |
| A 的代表样段 | 原站锁定后先在实际页面做一段；操作原站与样段并核对关键差异，样段通过才展开整站 | [样段与阶段命令](A模式证据格式.md) |
| 正式制作 | Gemini文案经独立审核；沿选定方向完成所有区块、素材、状态和动效 | [正式制作与核验](正式制作与核验.md)；具体问题查[模式阅读导航](模式阅读导航.md) |
| 成品审核 | 独立page文案审核，再由视觉Agent实测与独立评分 | [成品文案](topics/copy/04-成品页面.md)、[独立视觉评审](独立评审入口.md) |
| 交付核验 | 同版本截图与实际交互，运行适用检查，如实报告缺项 | [正式制作与核验](正式制作与核验.md#4-最终核验与交付)、[自动化与门槛](自动化与门槛.md) |

A 有参考地址时直接使用[侦察开工命令](原站侦察与回放.md)，它会登记流程并实际访问原站。其他制作在原项目已有网站目录中运行`node <技能>/scripts/workflow-check.mjs begin --root <原项目> --site <网站目录> --design-mode A --reference <参考URL>`。A/B/C按实际模式填写；C或A未锁唯一参考时省略`--reference`，候选证据放现有ref目录，不把某案例假作唯一目标。已有流程先读后续用，不覆盖记录。嵌套网站显式指定site。

A 按 `侦察与回放 → source → prototype → 逐区块实践与对照 → paired` 推进。普通制作直接使用这个样段继续完成全站；若用户选择三预览，把选中的片段沿用为正式实现并核对，避免为检查重做第四个预览。样段之前只整理已有文案与事实，在页面用必要的固定名称排字。
A/C预览不是三套正式网站；B/E不自动追加三版；D只找参考、F只反推、G/H只评审。用户明确要求完整六版或获奖打磨时才按[设计探索与交付](设计探索与交付.md)采用对应方案卡、比较、设计/实现说明和对标产物，不把历史完整探索清单当作普通任务前置条件。

整个流程不依赖Hook，不修改全局配置。用户已经授权的常规实现直接推进；风格选择等真实输入到达前不把等待当同意。正文、素材和交互的实际完成情况分别报告。
